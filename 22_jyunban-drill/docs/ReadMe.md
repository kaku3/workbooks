# 順番のセンス — 仕様・運用メモ

## 1. アプリ概要

「伝わる順番は、反復で身につく。」をコンセプトに、仕事で使う説明や文章の順番を、4文ずつ並べ替えて練習する静的Webアプリです。アカウント登録やサーバー側の保存は使わず、学習記録は利用中のブラウザに保存します。

## 2. 出題カテゴリ

- **説明の順番**: 読み手が理解しやすい説明の構造を考えます。目的、対象・前提、詳細、例外・補足などを並べます。
- **文章の順番**: 出来事や処理のつながりを読み取り、自然な時系列・因果関係に並べます。

カテゴリと問題数は開始前に選びます。問題数は5問が初期選択です。選択内容に合わせて練習パネルの背景・枠と選択ボタンの色が変わり、問題中もパネルの表示は続きます。開始後は5問・10問の切り替えを無効にします。

## 3. セッションの流れ

1. 「説明の順番」または「文章の順番」と、5問または10問を選択します。
2. 開始ボタンには、5問では「さらっと5問に挑戦」、10問では「じっくり10問に挑戦」と表示します。
3. 問題ごとに4文の順番を組み替えます。PCではドラッグ＆ドロップ、タッチ端末では各カードの上下ボタンを使えます。カードにフォーカスしてAlt+↑／↓を押すキーボード操作にも対応します。
4. 回答後は、半透明の全画面背景上に正解の○または不正解の×を短く表示し、自動で次の問題へ進みます。正誤と解説は回答中には表示しません。
5. セッション終了後、正答率、所要時間、平均回答時間を表示します。結果画面には全問の正誤と回答順を表示し、各問の「解説を見る」から正しい順番と解説を確認できます。同じ問題セットでもう一度挑戦できます。

タイマーはセッション全体を計測します。問題ごとの回答時間は、問題表示から回答確定までで計測し、結果の平均回答時間に使います。

## 4. 問題選定とデータ形式

問題データは`src/data/problems.json`にあります。各カテゴリ30問を収録しています。5問モードは難易度1・2・3から基本的に2・2・1問、10問モードは4・4・2問を選びます。難易度内とセッション内の出題順はシャッフルします。問題が不足する場合は、カテゴリ内の未選択問題で補います。

```json
{
  "version": 1,
  "problems": [
    {
      "id": "Q01",
      "category": "文章の順番",
      "title": "プロフィール更新",
      "sentences": [
        { "id": "1-1", "text": "利用者がプロフィールの更新を実行する。" },
        { "id": "1-2", "text": "入力された内容を検証する。" },
        { "id": "1-3", "text": "検証に成功した場合、プロフィール情報を保存する。" },
        { "id": "1-4", "text": "保存が完了したら、更新完了メッセージを表示する。" }
      ],
      "explanation": "操作、検証、保存、結果表示という処理の流れです。",
      "difficulty": 1
    }
  ]
}
```

`sentences`配列の順序を正解として扱います。画面ではそのインデックスをシャッフルし、回答順と正解順を比較して採点します。`difficulty`は1（やさしい）〜3（難しい）です。問題を追加する際はIDを重複させず、4文と解説を設定してください。

## 5. 学習記録

- 保存先はブラウザの`localStorage`、キーは`junban-drill-history-v1`です。
- 1問以上回答した日を`junban-drill-attendance-v1`に保存し、ページ下部の月間カレンダーに表示します。今日の1問・通常ドリルを問わず、正誤にかかわらず回答を送信した日が対象です。
- 挑戦日時、カテゴリ、問題数、正答数、正答率、セッション所要時間、平均回答時間、各問のID・正誤・回答時間を保存します。
- 保存件数は直近100セッションです。個々の問題文や解説、提出した文章順は永続保存しません。回答一覧と解説は終了直後のセッション結果に表示します。
- 記録画面には総挑戦数、回答問題数、直近5セッションの平均正答率と、その前の回答記録との推移矢印、直近10セッションのグラフを表示します。
- 学習カレンダーの回答日を選ぶと、その日の完了セッション、正答率、回答時間、各問の正誤をポップアップで確認できます。
- グラフは日付を横軸、正答率を左軸、平均回答時間を右軸にします。同じ日の複数セッションは、各日の幅の中で時刻順に横へずらして表示します。点にカーソルを合わせると日時と値を確認できます。
- 「記録を消去」からブラウザ内の履歴を削除できます。記録は別端末や別ブラウザとは同期しません。
- 「記録を消去」すると、学習履歴、キャリアポイント、今日の1問の達成状況、学習カレンダーを含む保存データが削除されます。

## 6. ディレクトリ構成

```text
.
├── README.md                    # 概要と使い方
├── docs/ReadMe.md               # 現行仕様・運用メモ
├── docs/incentive-design.md     # 継続インセンティブの設計意図
├── docs/career-mode.md          # キャリア物語の設計意図
├── docs/implementation-design.md # 実装上の詳細設計
└── src/
    ├── index.html               # ページ構造と表示文言
    ├── css/style.css            # デザインとレスポンシブ調整
    ├── js/app.js                # 出題、採点、報酬、キャリア、記録、グラフ
    ├── data/problems.json       # 問題データ
    └── data/career.json         # 報酬設定とキャリア段階
```

## 7. 公開方法

このフォルダには専用のデプロイworkflowやサーバー設定を含みません。公開時は`src/`をWebサイトの公開ルートとして設定してください。GitHub Pagesを使う場合は、ホスティング先リポジトリでPagesの公開元やworkflowを設定します。

ページ内のCSS、JavaScript、問題データは相対パスで読み込むため、リポジトリのサブパスにも配置できます。公開後はトップページから問題データが読み込めることを確認してください。

## 8. 変更する場所

- 文言、ページ構造、カテゴリ：`src/index.html`
- 色、余白、付箋カード、画面幅ごとの表示：`src/css/style.css`
- 出題選定、採点、タイマー、正誤エフェクト、振り返り、履歴グラフ：`src/js/app.js`
- 問題文、正解順、解説、難易度：`src/data/problems.json`
- 報酬ポイント、節目、キャリア段階：`src/data/career.json`

## 9. 現在の対象範囲

2カテゴリ、5問／10問、難易度に応じた出題、時間計測、回答後の正誤エフェクト、終了後の全問振り返りに加え、通常正解のポイント、日付固定の今日の1問、節目ボーナス、キャリアエピソードを提供します。平均回答時間は正解した問題のみで計算します。ローカル履歴、日付軸の成績グラフ、正答率の推移矢印、回答日の詳細を開ける月間カレンダーも利用できます。

ポイント移行、今日の1問の回答条件、節目、キャリア段階の閾値など、確定した実装ルールは[インセンティブ・キャリア機能 詳細設計](implementation-design.md)を参照してください。元の設計意図は[incentive-design.md](incentive-design.md)と[career-mode.md](career-mode.md)にあります。

アカウント、ランキング、オンライン集計、端末間同期はありません。
