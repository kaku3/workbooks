# インセンティブ・キャリア機能 詳細設計

`incentive-design.md` と `career-mode.md` を、現行の静的アプリへ実装するための決定事項とデータ設計です。ポイントは継続の小さな手応えとして扱い、現実の能力・職位の評価には使いません。

## 1. 画面配置

ホーム画面を次の順にします。

1. 今日の1問（通常練習を一度以上完了した利用者に表示）
2. 今日のドリル（既存の5問・10問練習）
3. キャリア（ポイント、肩書き、エピソード、次段階への進捗）
4. 積み重ねの記録

初回は今日の1問を隠し、現在の通常ドリルから始められるようにします。今日の1問は通常の並べ替え・採点・結果画面を共有し、別ルールを追加しません。今日の1問を回答した後は、正誤にかかわらず当日のカードを無効にします。正解の場合のみ5ptを与え、通常ドリルの2ptは重ねません。

## 2. 報酬計算

- 通常ドリル：正解1問につき2pt。不正解は0pt。
- 今日の1問：当日最初の回答が正解なら5pt。不正解なら0pt。どちらの場合も再回答不可。
- 累計正解数：通常・今日の1問の正解を合算します。
- 節目ボーナス：累計正解数が10/50/100/250/500に初めて到達したとき、それぞれ10/20/30/50/100ptを加算します。
- 回答速度にはポイントを付けません。
- 一回の回答イベントIDと、今日の回答済み日付を保存し、同じイベントの再処理を防ぎます。
- 今回獲得したポイントは結果画面に表示します。キャリア表示はホーム画面でいつでも確認できます。
- 最近の正答率には直近5セッションの平均を表示し、その前の最大5セッションとの比較を↑・↓・→で示します。学習カレンダーの回答日を選ぶと、その日の完了セッションと各問の結果を開きます。

今日の1問の正解も節目の累計正解数には含めますが、通常練習の2ptは加算しません。これは「今日の1問はデイリー報酬のみ」と「累計正解数の節目」を両立させるための扱いです。

## 3. 今日の1問

- 日付キーは端末のローカル日付（`YYYY-MM-DD`）です。
- 問題IDは日付から決定的に選びます。同じ日・同じ問題データなら再読み込み後も同じ問題になります。
- 既存の全問題をプールとして使います。問題プールを追加しても、日付による選択方式は変えません。
- 初回の通常セッション完了後にカードを表示します。過去履歴がある利用者には初回表示からカードを出します。
- 当日の回答済み状態はポイント用データに記録し、正誤を問わずカードを無効化します。
- 日付と回答状態はローカル保存です。端末間同期や時計変更への耐性は保証しません。

## 4. キャリア段階

キャリアの段階は現実の昇進や職種の序列ではなく、仕事の見え方・説明・改善に関する短い物語の節目です。

| 必要ポイント | 表示タイトル | エピソードの方向 |
|---:|---|---|
| 0 | 未アサイン | 学んだことと次に経験したいことを書き出す |
| 20 | 駆け出し | 問い合わせの困りごとや利用環境を整理する |
| 60 | ジュニア | 引き継ぐ相手が次に動ける形で伝える |
| 130 | メンバー | 同じ質問から案内文の改善を考える |
| 400 | サブリーダー | 操作、条件、結果を分けて報告する |
| 1080 | リーダー | テストの先にある利用者の迷いに気づく |
| 2000 | シニア | 手順の目的や条件を作業前に確かめる |
| 4000 | エキスパート | 誰が何に困っているかから話を組み立てる |
| 6000 | 一人称で動ける人 | 目的を確認し、自分から提案する |
| 8000 | プレイングマネジャー | 実務を進めながら、チームが判断しやすい情報を整える |

段階の文章は固定のストーリーサンプルです。表示タイトルはドリル内の物語上の呼び名で、現実の職位や能力を評価するものではありません。特にプレイングマネジャーは一人称で動ける人より優れた働き方という意味ではありません。最後の段階以降は肩書きを追加せず、累積ポイントと到達済みの物語を表示します。

## 5. 保存と既存データ

- 既存履歴キー`junban-drill-history-v1`は変更しません。
- ポイント、累計正解数、節目取得、日別回答済み状態、既処理イベントは`junban-drill-career-v1`に分けて保存します。
- 回答を送信した日付は`junban-drill-attendance-v1`に分けて保存し、日付ごとに一度だけカレンダーへ記録します。
- ポイント値、節目ボーナス、キャリア段階の文面と閾値は`src/data/career.json`で管理します。
- 初回起動時、旧履歴（保存上限100セッション）の回答詳細から正解数を集計し、通常練習の2ptと到達済み節目ボーナスを一度だけ移行します。旧履歴は維持します。
- 旧履歴より前の記録がすでに保存上限で失われている場合、その期間の正解数は復元できないため移行対象外です。
- 「記録を消去」はセッション履歴、キャリアポイント、今日の1問の達成状態、学習カレンダーを含む保存データを削除します。確認文は「全ての記録・ポイントを消去します。よろしいですか？」です。
- 保存データが不正・利用不能でも、通常の出題と採点は継続します。

## 6. 回答時間

- セッション結果と履歴の平均回答時間は正解した問題だけで再計算します。
- 正解が0問なら`null`として保存し、画面では`—`を表示します。
- 既存履歴は`answers`にある正誤別時間から正解分のみ再計算します。これにより旧平均値の定義を変更しても、旧履歴のグラフは新定義に揃います。
- グラフでは正解がないセッションの平均時間ポイントを描きません。

## 7. 結果画面

既存の全問レビューに、今回獲得したポイントを追加表示します。ポイント内訳は「正解ポイント」「今日の1問」「節目ボーナス」を分けず合計だけ表示します。キャリアを競争指標にしないため、ランキング、連続日数、失効・減点は導入しません。
