# 設計の階層ドリル

## 1. コンセプト

設計書を書くときに、情報をどの階層に置けばよいかを判断する力を鍛えるドリル。

要求、要件、外部仕様、詳細設計。それぞれの違いを説明できるだけでなく、実際の文章を読んだときに「これはどの階層の話なのか」を自然に見分けられることを目指す。

設計書の章立てが不自然だったり、どこまで書けばよいか分からなくなったりする問題は、文章力だけが原因とは限らない。設計の階層や、各情報の置き場所を理解できていない可能性がある。

AIを使えば文章や設計書のたたき台は作れる。しかし、情報の粒度や配置が適切かを判断できなければ、出力されたものをレビューすることも難しい。

このドリルでは、難しい設計書を最初から書くのではなく、短い文章を分類する練習から始める。

## 2. 学習目標

- 要求・要件・外部仕様・詳細設計の違いを理解する
- 文章が扱っている情報の粒度を判断する
- それぞれの階層に適した情報の置き場所を判断する
- 設計書の章立てや記述内容の違和感に気づくための基礎を身につける
- AIが作成した設計書をレビューするための足がかりを得る

## 3. 基本の出題形式

文章カードを読み、適切な階層のボックスに分類する。

分類先は次の4つ。

1. **要求** — 誰が何を実現したいのか、どのような課題を解決したいのか
2. **要件** — 要求を満たすために、システムが満たすべき条件や機能は何か
3. **外部仕様** — 利用者や外部システムから見て、どのように振る舞うのか
4. **詳細設計** — 仕様を実現するために、内部をどのような構造や処理で実装するのか

これは本ドリルで採用する基本的な整理基準であり、すべての組織・開発手法に共通する唯一の定義と主張するものではない。実際の問題では、分類の根拠が分かるように説明を用意する。

## 4. UI・操作方針

- 文章カードを4つの分類先へドラッグ＆ドロップする
- スマートフォンでも操作できるようにする
- ドラッグ操作が難しい環境では、カードを選択して配置先をタップする操作も検討する
- 判定後は正誤だけで終わらせず、分類の考え方や判断のポイントを提示する
- 繰り返し練習できるようにし、正解数や進捗を表示する
- 操作や演出はシンプルにし、分類を考えること自体に集中できるようにする

## 5. 問題データ

問題文と正解、解説は画面の処理から分離して管理する。

想定するデータ項目：

- 問題ID
- 問題文
- 正解の階層
- 解説・分類の根拠
- 必要に応じてヒントや補足

問題を追加する際に、画面のJavaScriptを毎回変更しなくて済む構成を目指す。

## 6. 実装方針

- HTML、CSS、JavaScriptを基本とする
- 問題データはJSONなどに分離する
- 外部ライブラリやバックエンドは、必要性が明確になるまで導入しない
- まずは少数の問題で操作と学習体験を成立させ、その後に問題数や機能を増やす
- 見た目の豪華さより、分類のしやすさ、判定の分かりやすさ、繰り返し使えることを優先する

## 7. ディレクトリ構成

- `docs/` — ブラウザーで動作するWebアプリケーション
- `src/` — 問題データや開発用ファイル

既存ファイルがある場合は、まず内容を確認してから変更する。既存の構成や命名規則がある場合は、理由なく作り直さない。

## 8. ローカルでの試し方

Visual Studio Code（VS Code）の拡張機能 **Live Server** を利用する。

1. VS Codeで、このプロジェクトのフォルダー `23-design-layer-drill` を開く。
2. 拡張機能の画面で `Live Server` を検索し、インストールする。
3. エクスプローラーから `docs/index.html` を開く。
4. エディター上で右クリックし、**Open with Live Server** を選択する。
5. ブラウザーで表示された画面を操作して確認する。
6. ファイルを修正して保存し、ブラウザーで表示を確認する。通常はLive Serverが自動で再読み込みする。

`index.html` がまだ存在しない場合は、まず `docs/` 内に作成する。

## 9. Codexへの作業指針

作業を始める前に、リポジトリ内のファイルと既存実装を確認する。

最初から大規模な構成にせず、次の順で進める。

1. 出題と4分類の基本操作を実装する
2. 正誤判定と解説表示を実装する
3. 問題データを画面処理から分離する
4. スマートフォンでの操作性を確認する
5. 問題数や履歴などの追加機能を検討する

分類が一意に決まりにくい文章を出題する場合は、曖昧さを放置せず、問題文・分類基準・解説を見直す。

このドリルの目的は、単に4種類の用語を暗記することではない。設計書を読んだときに、情報の粒度や置き場所に違和感を持てるようになることである。
