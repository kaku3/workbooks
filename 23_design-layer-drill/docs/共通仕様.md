# ドリル共通仕様

この文書は、`22_jyunban-drill`の画面・継続機能を参考に、`23_design-layer-drill`で採用するドリル共通の体験を定める。問題の学習目的や回答操作は各ドリル固有とし、回答後の流れ、結果、学習記録、継続の仕組み、フッターを共通化する。

## 1. 基本方針

- 1回の挑戦は複数問で構成し、開始から結果までをひとつのセッションとして扱う。
- 回答操作は各ドリルの学習内容に合わせる。正誤の伝え方、結果の振り返り、記録の扱いは共通にする。
- 競争や速さをあおらず、短い反復と自分の振り返りを支える。
- アカウント登録なしで使え、学習記録は利用中のブラウザー内に保存する。

## 2. 画面遷移

標準的な遷移は「開始前 → 問題 → 回答直後の正誤演出 → 次の問題 → 結果」とする。

1. 開始前に、挑戦内容と問題数を選ぶ。選択を確定して開始した後は、セッションが終わるまで変更できない。
2. 問題画面では進捗と現在の問題を示す。回答を確定するまでは正解や解説を表示しない。
3. 回答確定時に採点し、全画面の半透明背景と大きな「○／×」で正誤を短く伝える。正解・不正解で背景色を変え、内容が分かるラベルも併記する。
4. 正誤演出の後、自動で次の問題へ進む。最終問題の後は結果画面へ遷移する。演出中の二重回答や重複採点は受け付けない。
5. 動きを減らす設定が有効な環境では、演出を簡略化して正誤を判別できる状態を保つ。

スキップ操作は「スキップ」と表示し、未回答として進捗に含める。回答済みと同じく二重処理を防ぎ、結果では未回答と分かるようにする。ヒントは「ヒント」と書いた小さなバッジで示す。

## 3. 結果画面

セッション終了後は、開始前や問題画面へ戻すのではなく結果画面を表示する。

- 正解数／出題数、正答率、セッション所要時間を表示する。
- 問題ごとの回答結果を一覧にし、正誤が分かるようにする。
- 各問の解説や正解根拠は、利用者が選んで開ける形にする。結果を一度に読み切る負担を避ける。
- 同じ問題セットへの再挑戦と、開始画面へ戻って新しい挑戦を選ぶ操作を用意する。
- 継続機能を実装するドリルでは、今回獲得したポイントなどの変化を結果画面で知らせる。
- 今日の1問など一度限りの挑戦では、再挑戦ボタンを隠し、通常ドリルへ戻る操作を示す。

問題形式により「回答順」や「正しい置き場所」などのレビュー項目は異なる。各問題の結果には、利用者が何を選んだかと、正解およびその理由を対応づけて表示する。

## 4. 継続のための仕組み

継続機能は、正解の積み重ねや日々の短い挑戦を見える形にする。失敗による減点、連続日数の失効、ランキングは設けない。

### 4.1 ポイントと節目

ポイント値、節目とボーナス、キャリア段階は`src/data/career.json`で管理する。現在は次のルールを採用している。別ドリルに導入する場合は、問題数や学習単位に合わせて報酬値を設定し、画面表示と保存処理を一致させる。

- 通常ドリルは正解1問ごとに2pt。不正解は0pt。
- 今日の1問は当日最初の回答が正解なら5pt。不正解でも当日分は回答済みとなり、再挑戦できない。通常正解分の2ptは重ねない。
- 通常・今日の1問の正解を累計し、累計正解数10／50／100／250／500問の初回到達時に、それぞれ10／20／30／50／100ptを加算する。
- 回答速度ではポイントを付けない。今回の獲得ポイントを結果画面に表示する。

ポイントや肩書きは学習を続けるための目印であり、現実の能力・職位を評価するものではない。

### 4.2 今日の1問

- 初回利用者は通常ドリルから始められるよう、通常ドリルを先に案内する。
- 通常ドリルを一度以上完了した利用者には、ホーム画面で今日の1問を案内する。
- 問題は端末のローカル日付を基準に選び、同じ日には再読み込み後も同じ問題を出す。
- 回答後は正誤にかかわらず当日のカードを無効化し、翌日に再び挑戦可能にする。
- 通常ドリルと同じ問題画面・採点・結果の流れを使い、専用の操作ルールを増やさない。

### 4.3 キャリア表示

ポイントに応じた段階や短いエピソードを表示する場合、ホーム画面で現在の段階、ポイント、次の段階までの進捗を確認できるようにする。段階は物語上の節目として扱い、他の利用者との比較や現実の職位の序列に結びつけない。

### 4.4 学習記録

- 挑戦日時、挑戦種別、問題数、正解数、正答率、所要時間を保存する。必要に応じて各問のID・正誤・回答時間も保存する。
- 保存先はブラウザーの`localStorage`とし、別端末・別ブラウザーとは同期しない。
- 問題文や解説、利用者が提出した回答内容は、履歴画面で必要がなければ永続保存しない。直後の結果画面では振り返りに必要な情報を表示する。
- 履歴は件数上限を設け、古い記録から整理する。保存データが使えない場合も、出題と採点を継続できるようにする。
- 学習カレンダーで挑戦した日を示し、月ごとの挑戦日数・回数を確認できるようにする。記録のある日を選ぶと、その日の挑戦回数と正解数を表示する。
- 最近の正答率を折れ線グラフで表示する。直近10回を時系列で並べ、各点から日付と正答率を確認できるようにする。
- 履歴の消去操作を設ける場合は、消去対象（履歴、ポイント、日別達成状況など）を確認文で明示する。

## 5. フッター

ページ末尾に共通フッターを置き、ブランド表記、共有導線、関連ページへの導線をまとめる。

- ブランド表記には`WORKBOOKS`と短いメッセージを表示する。
- 「シェア」ラベルとFacebook、X、LINEの共有ボタンを置く。
- 共有先には現在のページURLを渡す。URLのハッシュ（ページ内アンカー）は取り除き、ページタイトルを共有文に使う。
- 外部共有リンクを新しいタブで開く場合は、`rel="noopener noreferrer"`を付ける。
- `WORKBOOKS`の一覧へ戻るリンク（`https://kaku3.github.io/workbooks/`）を配置する。画面幅が狭い場合は縦並びにし、共有ボタンを押しやすく保つ。

## 6. ページメタデータとOGP

- 日本語の`title`とページ内容を端的に説明する`meta description`を設定する。テーマカラーも指定する。
- 公開先URLを`link rel="canonical"`と`og:url`に設定し、URLを一意にする。
- Open Graphには`og:type=website`、日本語ロケール、サイト名、タイトル、説明、共有画像を設定する。
- OGP画像は`src/assets/ogp.png`に置き、1200×630pxのPNGとする。`og:image`と`twitter:image`には公開後に取得できる絶対URLを指定し、画像のMIME type・幅・高さ・代替テキストも記載する。
- Xなどの共有カードには`twitter:card=summary_large_image`とタイトル・説明・画像を設定する。
- OGP画像は小さなプレビューでも内容が分かる構図にし、タイトルや4つの階層を画像内に含める。

## 7. アクセシビリティと操作性

- ボタン・リンク・ドラッグ対象にキーボードフォーカスを表示する。
- タッチ端末でも回答できる代替操作を用意する。ドラッグ操作だけを唯一の回答方法にしない。
- 正誤は色だけに頼らず、記号とテキストでも示す。
- 小さい画面でも進捗、回答操作、結果操作が見切れないようにする。

## 8. 23_design-layer-drillへの適用

23の問題形式は、文章カードを「要求／要件／外部仕様／詳細設計」のいずれかへ分類する1問単位の形式である。開始画面では「4つの箱」の意味と、「出題の文章を4つの箱のいずれかに入れる」という操作説明を問題数ボタンより先に示す。分類先ボタンを押すか、カードを分類先へドラッグして回答する。開始画面には「さらっと5問 →」「じっくり10問 →」の2つのボタンを置き、選択と同時に開始する。回答後に正誤エフェクトを表示して自動で次の問題へ進む。スキップは未回答として記録する。

通常挑戦の完了結果には正解数、正答率、所要時間、獲得ポイントを表示し、全問の回答・正解・理由を最初から一覧で振り返れるようにする。結果画面から同じ問題セットへ再挑戦するか、開始画面へ戻って問題数を選び直せる。ポイント、今日の1問、挑戦回数はブラウザー内に保存し、挑戦日をカレンダー、直近10回の正答率をグラフで確認できる。今日の1問は通常挑戦を完了した後に利用可能となり、正誤にかかわらず当日一度回答すると再挑戦できない。問題画面ではヒントをバッジで表示し、スキップ操作は「スキップ」と表記する。
