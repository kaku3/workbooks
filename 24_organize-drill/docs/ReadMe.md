# 図で整理ドリル

## 現在の実装

- 難易度別50問から選ぶ3問・5問セッション、通常セッション後に解放されるランダムな日替わり1問
- 資料は左のホワイトボードに付箋で段階開示（最初は外部設計1枚＋スコープ外2枚。「（ヒントを見る）」で追加資料を1枚ずつ開き、開くたびに1点減点。付箋はドラッグで配置変更できる）
- `?drill=<問題ID>`で指定した1問を直接開く（例：`src/index.html?drill=zukai-payment-auth`）
- 20_zukai-drillの10テーマを、カード選択と有向接続で解くフロー図問題として再構成
- ポイント・ステージ・学習カレンダー・直近10回の正答率グラフをlocalStorageで記録
- 回答図と正解例の比較、青い正解線・赤い点線、配置の芸術点
- Facebook、X、LINEのシェアリンクとOGPメタデータ

詳しい操作・採点条件は[共通仕様](共通仕様.md)を参照。

## 1. コンセプト

情報を読み取り、要点を見つけ、関係を整理して図に組み立てる力を鍛えるドリル。

図をゼロから自由に描くことだけが、図解の練習ではない。まずは文章や断片的な情報から、何を図に含めるべきか、どの要素が関係しているか、どのように配置すれば伝わるかを判断する練習から始める。

頭では分かっているのに、図にすると伝わらない。情報をたくさん並べたのに、何が重要なのか分からない。こうした問題は、描画技術だけでなく、主題の選び方や情報の整理の仕方にも関係している。

AIは図のたたき台を作れるが、図に含めるべき要素や、伝えるべき関係が適切かを判断するには、人間側にも整理する力が必要になる。

本ドリルでは、情報を見つけて、並べて、つなぐ体験を通じて、図解の前段階にある思考を練習する。

## 2. 学習目標

- 文章や要求から、図に含めるべき情報を見つける
- 図の主題や、最も伝えるべきポイントを判断する
- 情報のまとまりや要素間の関係を整理する
- 要素の配置や接続によって、伝わり方が変わることを理解する
- AIが作成した図をレビューし、改善するための基礎を身につける

## 3. 基本の出題形式

問題文や説明を読み、必要な要素を選び、配置し、関係を組み立てる。

基本的な学習の流れ：

1. 問題文を読む
2. 図に必要な要素を見つける
3. 要素を適切な場所に配置する
4. 必要な要素同士をつなぐ、または順序を整える
5. 完成例や解説を確認し、自分の整理と比較する

最初から複雑な図を描かせず、短いラベルのカードや、少数の配置先を使った課題から始める。

問題の種類に応じて、要素の選択、配置、順序づけ、接続などを組み合わせる。すべての問題で同じ操作を強制する必要はない。

## 4. UI・操作方針

- 初版はPC向けとし、幅850px以下の画面ではPCでの利用を案内する
- 問題開始時は候補カードをすべてキャンバス内へランダムに配置する
- キャンバス右下のゴミ箱に不要なカードを移す。ゴミ箱を開くと中身を確認でき、各カードをキャンバスに戻せる。ゴミ箱アイコンには中の枚数を表示する
- 図に配置したカードは幅を統一し、文章の折り返し行数が最も多いカードの高さに合わせて揃える（すべて1行なら1行分の高さ）
- 問題の作業領域は画面幅を広く使い、キャンバスを配置する
- 配置したカード右上の「×」でゴミ箱へ移し、ゴミ箱内の「戻す」でキャンバスに復元する
- 配置したカードをドラッグして並べ替える。グリッド、他カードの中心線、同じ行・列にあるカードとの等間隔位置に吸着し、矢印キー（Shift併用で細かく移動）でも微調整できる
- 「上下中央」「左右中央」で配置済みカードの中心位置を揃える
- カードを配置し終えた後、通る順にカードをクリックして矢印を連続して追加する。接続先が次の始点になる
- 選択中のカードをもう一度クリックするか、キャンバスの空白をクリックすると線の追加を終了できる
- 接続線をクリックすると線上に「×」が表示され、その線だけを削除できる。「線を消す」ではすべての接続を消せる
- 正解・不正解だけでなく、どの情報を見落としたか、どの関係に注目するとよいかを説明する
- 正解判定は必要なカードの選択と有向接続の一致で行い、カードの配置座標は採点しない。正解例の配置は複数あり得るため、画面には比較用の一例を示す
- 回答後は「解答」と「正解例」を横並びで表示する。2つの図は縦横スクロールが同期し、拡大・縮小も同時に反映する
- 解答時のキャンバス寸法を回答後も保ち、解答図のカード位置や間隔が画面切り替えで変わらないようにする。正解例も同じ寸法で表示する
- 解答図の矢印は、正解パターンに含まれる関係を青い実線、見直しが必要な関係を赤い点線で示す。回答後は始点選択、線の選択、削除ボタン、配置ガイドを解除する
- 知識の正誤とは別に、カードの重なりのなさ、整列、等間隔、問題ごとに定義した意味グループのまとまりを「図の整いポイント（芸術点）」として5点満点で加点表示する
- 配置評価の採点項目やデータ定義は[共通仕様](共通仕様.md)に従う
- 正解確認では解答・正解例のキャンバスをドラッグしてパンできる。縦横スクロールと拡大率は同期する
- 接続の正解は問題データに明示する。別の解釈も正解にしたい場合は許容する接続セットを登録し、未登録の解釈を自動で意味判定することはしない
- 完成例を提示し、自分が組み立てた図と比較できるようにする
- 必要に応じて、完成時に図を整えたり、完成例を重ねて見せたりする演出を検討する
- 操作を複雑にしすぎず、情報を整理する思考に集中できることを優先する

## 5. 図や素材の実装方針

**問題ごとに完成図をSVGとして一から作成し、細かく切り分けて操作させる方式を前提にしない。**

まずは、HTML/CSS/JavaScriptで構成できる要素を使う。

- 要素カード
- 配置先や領域
- 接続線や順序
- ラベルや説明文
- 完成例の表示

問題固有の内容はデータとして管理し、操作の仕組みと分離する。

完成図の画像を使う場合は、完成例や比較用の素材として活用する。画像を利用すること自体が目的ではなく、学習者が情報の選び方や関係の組み立て方を練習できることが重要である。

最初の試作では、複雑な図の画像をパーツに分割するよりも、短いラベルのカードを配置する課題を優先する。

## 6. 問題データ

問題の内容は、画面の処理から分離して管理する。

想定するデータ項目：

- 問題ID
- タイトル
- 問題文
- 学習のポイント
- 配置する要素
- 配置先や領域
- 要素間の関係や接続条件
- ヒント
- 正解条件
- 解説
- 必要に応じて完成例の画像や参照先

問題によって必要な項目は異なるため、すべての項目を必須にする必要はない。

問題を追加するときに画面側のロジックを大きく書き換えなくて済むようにする。

## 7. 学習体験の考え方

このドリルは、正しい図を見せて覚えさせるだけの教材ではない。

情報を読み、必要な要素を選び、関係を組み立ててみることで、学習者自身が「どこで迷うのか」を発見できる体験を目指す。

同じように図がうまく作れない場合でも、原因は一つとは限らない。

- 主題が決められない
- 必要な情報と不要な情報を分けられない
- 情報のまとまりを作れない
- 要素同士の関係を判断できない
- 配置や順序による意味の違いに気づいていない

問題を小さく分けて練習できるようにし、つまずきの発見や、人が学習者を観察するための足がかりにもなる教材を目指す。

## 8. 実装方針

- HTML、CSS、JavaScriptを基本とする
- 問題データはJSONなどに分離する
- 外部ライブラリやバックエンドは、必要性が明確になるまで導入しない
- 50問を難易度別に収録し、指定構成の3問・5問セッションと日替わり1問で繰り返し練習できるようにする
- 初版はPC向けとし、PCのマウスまたはトラックパッド操作に集中する
- 正誤判定や解説は、学習上の狙いと一致するように設計する
- 見た目の豪華さより、操作の分かりやすさと、考えることへの集中を優先する

## 9. ディレクトリ構成

- `docs/` — ブラウザーで動作するWebアプリケーションと公開用ファイル
- `src/` — 問題データや開発用ファイル

既存ファイルがある場合は、まず内容を確認してから変更する。既存の構成や命名規則がある場合は、理由なく作り直さない。

## 10. ローカルでの試し方

Visual Studio Code（VS Code）の拡張機能 **Live Server** を利用する。

1. VS Codeで、このプロジェクトのフォルダー `24_organize-drill` を開く。
2. 拡張機能の画面で `Live Server` を検索し、インストールする。
3. エクスプローラーから `src/index.html` を開く。
4. エディター上で右クリックし、**Open with Live Server** を選択する。
5. ブラウザーで表示された画面を操作して確認する。
6. ファイルを修正して保存し、ブラウザーで表示を確認する。通常はLive Serverが自動で再読み込みする。

## 11. Codexへの作業指針

作業を始める前に、リポジトリ内のファイルと既存実装を確認する。

次の順で段階的に進める。

1. 問題文とカードを表示する
2. 要素の選択・配置など、基本操作を実装する
3. 正解条件と解説を表示する
4. 問題データを画面処理から分離する
5. PC画面でカード配置・接続・完成例との比較を確認する
6. 完成例との比較や演出を検討する
7. ポイント、ステージ、学習カレンダー、正答率グラフで継続状況を振り返る

最初から汎用的すぎる図解エディターを作らない。まずは、決められた課題を通じて情報を整理する学習体験を成立させる。

このドリルの目的は、単に図を描くことではない。何を伝えるべきかを見つけ、情報を整理し、相手に伝わる形へ組み立てる力を育てることである。
