# 注文キャンセルと返金

- 問題ID：`zukai-refund`
- 直接開く：`src/index.html?drill=zukai-refund`
- 難易度：hard
- 出典：`src/data/problems.json`

## 問題文

「注文キャンセルと返金」の見直しにあたり、関係者から集めたメモと設計資料です。今回整理する範囲を考えながら、必要な情報を集めてください。

### 課題

関係する付箋を選び、情報のつながりを矢印で整理してください。

## 段階開示資料

左側のホワイトボードに付箋として表示します。最初は外部設計1枚＋スコープ外2枚。「（ヒントを見る）」を押すたびに追加資料を1枚開示し、開くたびに1点減点します。追加資料は必要な情報とスコープ外の情報が混ざっており、開示順は毎回ランダムです。付箋はドラッグで自由に動かせます。

### 最初に表示する3枚

1. 外部設計｜処理概要（外部設計）：担当者が注文をキャンセルしたあと、返金の可否と決済代行からの結果に応じて対応を進める流れ。
2. 要求メモ（スコープ外）：導入時期は繁忙期を避けたい。
3. 画面仕様メモ（スコープ外）：注文メモの文字数上限は、現行画面の仕様を踏襲する。

### 追加で開示する資料（順不同）

| 資料 | 内容 | 種別 | 根拠になる正解接続 |
|---|---|---|---|
| 要求メモ | 「担当者が注文をキャンセル」を行った後に、「返金対象か判定」へ進む。 | 要件・要求 | 担当者が注文をキャンセル → 返金対象か判定 |
| 外部設計｜分岐の扱い | 「返金対象か判定」の後は、状況によって「決済代行へ返金API」／「返金対象外を担当者へ通知」に分かれる。 | 外部設計 | 返金対象か判定 → 決済代行へ返金API<br>返金対象か判定 → 返金対象外を担当者へ通知 |
| 外部設計｜分岐の扱い | 「決済代行へ返金API」の結果次第で、行き先（「成功時に返金済みへ更新」、「失敗時に再試行キューへ登録」）が決まる。 | 外部設計 | 決済代行へ返金API → 成功時に返金済みへ更新<br>決済代行へ返金API → 失敗時に再試行キューへ登録 |
| 外部設計｜処理順序 | 「失敗時に再試行キューへ登録」が終わったら、「担当者へ失敗を通知」に移る。 | 外部設計 | 失敗時に再試行キューへ登録 → 担当者へ失敗を通知 |
| 帳票メモ | 帳票レイアウトは別紙を参照する。 | スコープ外 | —（図に含めない） |
| 研修メモ | 操作研修の資料は別途用意する。 | スコープ外 | —（図に含めない） |

## ヒント

返金できるかどうかの判断と、APIを呼び出した後の結果に注目しましょう。失敗時の対応も忘れずに。

## 解説

返金対象外なら担当者へ通知し、対象なら返金APIを実行します。API成功時は返金済みに更新し、失敗時は再試行キューへ登録して担当者へ知らせます。
