# クーポン適用

- 問題ID：`coupon-application`
- 直接開く：`src/index.html?drill=coupon-application`
- 難易度：hard
- 出典：`src/data/problems.json`

## 問題文

「クーポン適用」の見直しにあたり、関係者から集めたメモと設計資料です。今回整理する範囲を考えながら、必要な情報を集めてください。

### 課題

関係する付箋を選び、情報のつながりを矢印で整理してください。

## 段階開示資料

左側のホワイトボードに付箋として表示します。最初は外部設計1枚＋スコープ外2枚。「（ヒントを見る）」を押すたびに追加資料を1枚開示し、開くたびに1点減点します。追加資料は必要な情報とスコープ外の情報が混ざっており、開示順は毎回ランダムです。付箋はドラッグで自由に動かせます。

### 最初に表示する3枚

1. 外部設計｜処理概要（外部設計）：利用者がクーポンを使うときに、条件を確認して割引を適用する流れ。条件を満たさない場合の扱いも含む。
2. 利用メモ（スコープ外）：同時利用は最大50人を想定している。
3. 共通デザインメモ（スコープ外）：キャンペーンバナーの色は、季節の配色に合わせて決める。

### 追加で開示する資料（順不同）

| 資料 | 内容 | 種別 | 根拠になる正解接続 |
|---|---|---|---|
| 外部設計｜処理順序 | 「クーポンコードを入力」が終わったら、「有効期限を確認」に移る。 | 外部設計 | クーポンコードを入力 → 有効期限を確認 |
| 外部設計｜分岐の扱い | 「有効期限を確認」の結果次第で、行き先（「対象商品を確認」、「利用できない理由を表示」）が決まる。 | 外部設計 | 有効期限を確認 → 対象商品を確認<br>有効期限を確認 → 利用できない理由を表示 |
| 詳細設計｜内部処理 | 「対象商品を確認」の後は、状況によって「割引を適用」／「利用できない理由を表示」に分かれる。 | 詳細設計 | 対象商品を確認 → 割引を適用<br>対象商品を確認 → 利用できない理由を表示 |
| 帳票メモ | 帳票レイアウトは別紙を参照する。 | スコープ外 | —（図に含めない） |
| 共通デザインメモ | エラー表示の色は共通スタイルに合わせる。 | スコープ外 | —（図に含めない） |

## ヒント

割引には複数の条件がありそうです。確認が一つ終わっただけで適用してよいか、結果による行き先の違いを考えましょう。

## 付箋

| ID | 種別 | ラベル |
|---|---|---|
| `coupon-application-n1` | 必要 | クーポンコードを入力 |
| `coupon-application-n2` | 必要 | 有効期限を確認 |
| `coupon-application-n3` | 必要 | 対象商品を確認 |
| `coupon-application-n4` | 必要 | 割引を適用 |
| `coupon-application-n5` | 必要 | 利用できない理由を表示 |
| `coupon-application-x1` | 余分・参考 | キャンペーンバナーの色 |

## グループ

- **適用条件の確認**：`coupon-application-n1`, `coupon-application-n2`, `coupon-application-n3`
- **判定結果**：`coupon-application-n4`, `coupon-application-n5`

## 正解の接続

- `coupon-application-n1` → `coupon-application-n2`
- `coupon-application-n2` → `coupon-application-n3`
- `coupon-application-n2` → `coupon-application-n5`
- `coupon-application-n3` → `coupon-application-n4`
- `coupon-application-n3` → `coupon-application-n5`

## 解説

この図では、クーポンコードを入力 → 有効期限を確認 → 対象商品を確認 → 割引を適用 → 利用できない理由を表示の関係を整理します。期限と対象商品の両方を満たす場合だけ割引します。「キャンペーンバナーの色」は今回の流れに含めません。
