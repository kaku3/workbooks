# テストから本番公開

- 問題ID：`ci-deploy`
- 直接開く：`src/index.html?drill=ci-deploy`
- 難易度：hard
- 出典：`src/data/problems.json`

## 要求仕様

変更を自動テストで確かめて本番に公開したい。テスト失敗は修正につなぎ、公開後に異常があれば元に戻す。 今回の図の対象：変更を取り込んでテストし、結果に応じて本番へ公開するか、修正へ戻る流れ。公開後の確認も含む。

### 操作

要求仕様と左側のメモを読み、右側のカードで必要な処理と関係を図にしてください。

## 段階開示資料

左側にはヒアリングメモを本文だけの付箋で表示します。最初は3枚で、判断の根拠も含みます。「（他のメモも見る）」で追加メモをランダムに1枚開示し、1点減点します。付箋は移動・ゴミ箱への整理・復元ができます。復元による再減点はありません。以下の種別と正解接続はレビュー用の内部情報です。

### 最初に表示する3枚

1. 自動テストの対象は、今回取り込んだ変更を含むコードとする。（内部種別：要件・要求／根拠：変更を取り込む → 自動テストを実行）
2. 合否は自動テストの実行結果から判定する。（内部種別：要件・要求／根拠：自動テストを実行 → テスト結果を判定）
3. 開発端末の機種名を資産台帳で検索し、交換対象を確認できるようにしたい。（内部種別：スコープ外／根拠：対象外）
