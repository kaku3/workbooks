# バッチ処理の再試行

- 問題ID：`batch-retry`
- 直接開く：`src/index.html?drill=batch-retry`
- 難易度：hard
- 出典：`src/data/problems.json`

## 問題文

「バッチ処理の再試行」の見直しにあたり、関係者から集めたメモと設計資料です。今回整理する範囲を考えながら、必要な情報を集めてください。

### 課題

図に必要な付箋を選び、処理の流れを矢印でつないでください。

## 段階開示資料

左側のホワイトボードに付箋として表示します。最初は外部設計1枚＋スコープ外2枚。「（ヒントを見る）」を押すたびに追加資料を1枚開示し、開くたびに1点減点します。追加資料は必要な情報とスコープ外の情報が混ざっており、開示順は毎回ランダムです。付箋はドラッグで自由に動かせます。

### 最初に表示する3枚

1. 外部設計｜処理概要（外部設計）：定期バッチで外部連携を実行し、失敗したときのやり直しと、最終的な通知までの流れ。
2. 未決事項（スコープ外）：入力項目の桁数・型はテーブル定義に従う。画面項目の詳細は別途確認する。
3. 環境メモ（スコープ外）：バッチ実行サーバーの型番は、インフラ台帳に記載している。

| 詳細設計｜内部処理 | 「外部連携を実行」を受けて、「結果を判定」につなぐ。 | 詳細設計 | 外部連携を実行 → 結果を判定 |

## ヒント

失敗したらすぐ終了するとは限りません。再試行できる間と、上限に達した後の対応を区別しましょう。

## 付箋

| ID | 種別 | ラベル |
|---|---|---|
| `batch-retry-n1` | 必要 | 定期バッチを開始 |
| `batch-retry-n2` | 必要 | 外部連携を実行 |
| `batch-retry-n3` | 必要 | 結果を判定 |
| `batch-retry-n4` | 必要 | 成功データを記録 |
| `batch-retry-n5` | 必要 | 規定回数内なら再試行 |
| `batch-retry-n6` | 必要 | 上限到達時に担当者へ通知 |
| `batch-retry-x1` | 余分・参考 | バッチ実行サーバーの型番 |

## グループ

- **実行と判定**：`batch-retry-n1`, `batch-retry-n2`, `batch-retry-n3`
- **成功と失敗の処理**：`batch-retry-n4`, `batch-retry-n5`, `batch-retry-n6`

## 正解の接続

- `batch-retry-n1` → `batch-retry-n2`
- `batch-retry-n2` → `batch-retry-n3`
- `batch-retry-n3` → `batch-retry-n4`
- `batch-retry-n3` → `batch-retry-n5`
- `batch-retry-n5` → `batch-retry-n2`
- `batch-retry-n5` → `batch-retry-n6`

## 解説

この図では、定期バッチを開始 → 外部連携を実行 → 結果を判定 → 成功データを記録 → 規定回数内なら再試行 → 上限到達時に担当者へ通知の関係を整理します。失敗しても再試行上限に達するまでは繰り返します。「バッチ実行サーバーの型番」は今回の流れに含めません。
