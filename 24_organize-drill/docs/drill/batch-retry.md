# バッチ処理の再試行

- 問題ID：`batch-retry`
- 直接開く：`src/index.html?drill=batch-retry`
- 難易度：hard
- 出典：`src/data/problems.json`

## 要求仕様

定期的な外部連携で成功データを残し、失敗は回数を制限して再試行したい。 今回の図の対象：定期バッチで外部連携を実行し、失敗したときのやり直しと、最終的な通知までの流れ。

### 操作

要求仕様と左側のメモを読み、右側のカードで必要な処理と関係を図にしてください。

## 段階開示資料

左側にはヒアリングメモを本文だけの付箋で表示します。最初は3枚で、判断の根拠も含みます。「（他のメモも見る）」で追加メモをランダムに1枚開示し、1点減点します。付箋は移動・ゴミ箱への整理・復元ができます。復元による再減点はありません。以下の種別と正解接続はレビュー用の内部情報です。

### 最初に表示する3枚

1. 定期バッチの起動で、その回の外部連携を実行する。（内部種別：要件・要求／根拠：定期バッチを開始 → 外部連携を実行）
2. 連携の成否は、外部への処理要求に対する結果から判定する。（内部種別：要件・要求／根拠：外部連携を実行 → 結果を判定）
3. 運用担当者はバッチ実行サーバーの型番を一覧で確認し、保守部品を手配したい。（内部種別：スコープ外／根拠：対象外）

## ヒント

失敗したらすぐ終了するとは限りません。再試行できる間と、上限に達した後の対応を区別しましょう。

## 解説

この図では、定期バッチを開始 → 外部連携を実行 → 結果を判定 → 成功データを記録 → 規定回数内なら再試行 → 上限到達時に担当者へ通知の関係を整理します。失敗しても再試行上限に達するまでは繰り返します。「バッチ実行サーバーの型番」は今回の流れに含めません。
