# API利用上限の超過

- 問題ID：`rate-limit`
- 直接開く：`src/index.html?drill=rate-limit`
- 難易度：normal
- 出典：`src/data/problems.json`

## 問題文

「API利用上限の超過」の見直しにあたり、関係者から集めたメモと設計資料です。今回整理する範囲を考えながら、必要な情報を集めてください。

### 課題

関係する付箋を選び、情報のつながりを矢印で整理してください。

## 段階開示資料

左側のホワイトボードに付箋として表示します。最初は外部設計1枚＋スコープ外2枚。「（ヒントを見る）」を押すたびに追加資料を1枚開示し、開くたびに1点減点します。追加資料は必要な情報とスコープ外の情報が混ざっており、開示順は毎回ランダムです。付箋はドラッグで自由に動かせます。

### 最初に表示する3枚

1. 外部設計｜処理概要（外部設計）：APIへのリクエストを受けて、利用量に応じて処理を続けるか、制限の応答を返すかを決める流れ。
2. 画面仕様メモ（スコープ外）：画面文言は後日確定する。
3. 文書メモ（スコープ外）：API仕様書の表紙は、文書管理のテンプレートに従う。

### 追加で開示する資料（順不同）

| 資料 | 内容 | 種別 | 根拠になる正解接続 |
|---|---|---|---|
| 外部設計｜処理順序 | 「APIリクエストを受信」の次は「利用量を集計」を行う。 | 外部設計 | APIリクエストを受信 → 利用量を集計 |
| 要求メモ | 「利用量を集計」を受けて、「上限内か判定」につなぐ。 | 要件・要求 | 利用量を集計 → 上限内か判定 |
| 詳細設計｜内部処理 | 「上限内か判定」の結果に応じて、「通常処理を実行」、「上限超過の応答を返す」のいずれかへ進む。 | 詳細設計 | 上限内か判定 → 通常処理を実行<br>上限内か判定 → 上限超過の応答を返す |
| 要求メモ | 画面の雰囲気は現行システムに近づけたい。 | スコープ外 | —（図に含めない） |
| 帳票メモ | 帳票レイアウトは別紙を参照する。 | スコープ外 | —（図に含めない） |

## ヒント

リクエストを受け取った後、利用量によって通常処理に進めるかが変わります。判定結果の二つの行き先を探しましょう。

## 付箋

| ID | 種別 | ラベル |
|---|---|---|
| `rate-limit-n1` | 必要 | APIリクエストを受信 |
| `rate-limit-n2` | 必要 | 利用量を集計 |
| `rate-limit-n3` | 必要 | 上限内か判定 |
| `rate-limit-n4` | 必要 | 通常処理を実行 |
| `rate-limit-n5` | 必要 | 上限超過の応答を返す |
| `rate-limit-x1` | 余分・参考 | API仕様書の表紙 |

## グループ

- **利用量の判定**：`rate-limit-n1`, `rate-limit-n2`, `rate-limit-n3`
- **応答分岐**：`rate-limit-n4`, `rate-limit-n5`

## 正解の接続

- `rate-limit-n1` → `rate-limit-n2`
- `rate-limit-n2` → `rate-limit-n3`
- `rate-limit-n3` → `rate-limit-n4`
- `rate-limit-n3` → `rate-limit-n5`

## 正解例の配置

| `rate-limit-n1` | 0.13 | 0.5 |

## 解説

この図では、APIリクエストを受信 → 利用量を集計 → 上限内か判定 → 通常処理を実行 → 上限超過の応答を返すの関係を整理します。上限内と超過で応答を分けます。「API仕様書の表紙」は今回の流れに含めません。
