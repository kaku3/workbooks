# 決済オーソリ

- 問題ID：`zukai-payment-auth`
- 直接開く：`src/index.html?drill=zukai-payment-auth`
- 難易度：hard
- 出典：`src/data/problems.json`

## 問題文

「決済オーソリ」の見直しにあたり、関係者から集めたメモと設計資料です。今回整理する範囲を考えながら、必要な情報を集めてください。

### 課題

購入確定から、決済結果に応じた次の処理までを図に整理してください。

## 段階開示資料

左側のホワイトボードに付箋として表示します。最初は外部設計1枚＋スコープ外2枚。「（ヒントを見る）」を押すたびに追加資料を1枚開示し、開くたびに1点減点します。追加資料は必要な情報とスコープ外の情報が混ざっており、開示順は毎回ランダムです。付箋はドラッグで自由に動かせます。

### 最初に表示する3枚

1. 外部設計｜処理概要（外部設計）：購入を確定する前に内容を確認し、問題がなければ決済へ進む。決済結果を受けて、注文の扱いを決める。
2. 画面仕様メモ（スコープ外）：配送先住所の表示順は、現行画面の並びを踏襲する。
3. 共通デザインメモ（スコープ外）：エラー表示の色は共通スタイルに合わせる。

### 追加で開示する資料（順不同）

| 資料 | 内容 | 種別 | 根拠になる正解接続 |
|---|---|---|---|
| 要件メモ | 購入内容を検証し、不備があれば購入内容の修正を依頼する。問題がなければ決済代行へ承認を要求する。 | 要件・要求 | 購入内容を検証 → 決済代行へ承認要求<br>購入内容を検証 → 購入内容の修正を依頼 |
| 外部設計｜処理順序 | 購入確定を実行した後に、購入内容を検証する。 | 外部設計 | 購入確定を実行 → 購入内容を検証 |
| 外部設計｜決済連携 | 決済代行へ承認要求を行った後、承認結果を判定する。 | 外部設計 | 決済代行へ承認要求 → 承認結果を判定 |
| 外部設計｜結果の扱い | 承認結果に応じて、注文を確定するか、支払い方法の再入力を依頼する。 | 外部設計 | 承認結果を判定 → 注文を確定<br>承認結果を判定 → 支払い方法を再入力 |
| 運用メモ | 操作ログは1年間保存する。今回の処理フロー図では保存方式までは扱わない。 | スコープ外 | —（図に含めない） |
| 未決事項 | 入力項目の桁数・型はテーブル定義に従う。画面項目の詳細は別途確認する。 | スコープ外 | —（図に含めない） |
| 外部設計｜完了後の表示 | 注文を確定した後、注文番号を表示する。 | 外部設計 | 注文を確定 → 注文番号を表示 |

## ヒント

購入内容の確認と、決済代行から返る結果は別の段階です。結果によって次の行き先が変わるところを探しましょう。

## 解説

購入内容の検証で問題が見つかった場合は修正を依頼し、問題がなければ決済代行へ承認を要求します。承認時は注文と注文番号を確定し、非承認時は支払い方法の再入力へ進みます。
