# 顧客データの一括取込

- 問題ID：`data-import`
- 直接開く：`src/index.html?drill=data-import`
- 難易度：normal
- 出典：`src/data/problems.json`

## 問題文

「顧客データの一括取込」の見直しにあたり、関係者から集めたメモと設計資料です。今回整理する範囲を考えながら、必要な情報を集めてください。

### 課題

図に載せる情報を見極め、付箋を矢印でつないでください。

## 段階開示資料

左側のホワイトボードに付箋として表示します。最初は外部設計1枚＋スコープ外2枚。「（ヒントを見る）」を押すたびに追加資料を1枚開示し、開くたびに1点減点します。追加資料は必要な情報とスコープ外の情報が混ざっており、開示順は毎回ランダムです。付箋はドラッグで自由に動かせます。

### 最初に表示する3枚

1. 外部設計｜処理概要（外部設計）：CSVで受け取った顧客データを検証し、問題のないものを登録する流れ。
2. 名簿メモ（スコープ外）：取込担当者の部署名は、組織変更のたびに更新される。
3. 運用メモ（スコープ外）：操作ログは1年間保存する。今回の処理フロー図では保存方式までは扱わない。

### 追加で開示する資料（順不同）

| 資料 | 内容 | 種別 | 根拠になる正解接続 |
|---|---|---|---|
| 詳細設計｜内部処理 | 「CSVを受け付ける」の次は「列構成を検証」を行う。 | 詳細設計 | CSVを受け付ける → 列構成を検証 |
| 外部設計｜処理順序 | 「列構成を検証」を受けて、「各行の必須項目を検証」につなぐ。 | 外部設計 | 列構成を検証 → 各行の必須項目を検証 |
| 要求メモ | 「各行の必須項目を検証」の後は、状況によって「有効行を登録」／「不備行をエラー一覧に出力」に分かれる。 | 要件・要求 | 各行の必須項目を検証 → 有効行を登録<br>各行の必須項目を検証 → 不備行をエラー一覧に出力 |
| 要求メモ | 導入時期は繁忙期を避けたい。 | スコープ外 | —（図に含めない） |
| 利用メモ | 同時利用は最大50人を想定している。 | スコープ外 | —（図に含めない） |

## ヒント

ファイル全体の形式と、各行の内容は別々に確認します。行ごとの結果が分かれるところを見つけましょう。

## 付箋

| ID | 種別 | ラベル |
|---|---|---|
| `data-import-n1` | 必要 | CSVを受け付ける |
| `data-import-n2` | 必要 | 列構成を検証 |
| `data-import-n3` | 必要 | 各行の必須項目を検証 |
| `data-import-n4` | 必要 | 有効行を登録 |
| `data-import-n5` | 必要 | 不備行をエラー一覧に出力 |
| `data-import-x1` | 余分・参考 | 取込担当者の部署名 |

## グループ

- **ファイルと行の検証**：`data-import-n1`, `data-import-n2`, `data-import-n3`
- **取込結果**：`data-import-n4`, `data-import-n5`

## 正解の接続

- `data-import-n1` → `data-import-n2`
- `data-import-n2` → `data-import-n3`
- `data-import-n3` → `data-import-n4`
- `data-import-n3` → `data-import-n5`

## 解説

この図では、CSVを受け付ける → 列構成を検証 → 各行の必須項目を検証 → 有効行を登録 → 不備行をエラー一覧に出力の関係を整理します。ファイル全体の形式確認と行単位の検証を分けます。「取込担当者の部署名」は今回の流れに含めません。
