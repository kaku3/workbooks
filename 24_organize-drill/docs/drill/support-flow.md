# 問い合わせ対応を整理する

- 問題ID：`support-flow`
- 直接開く：`src/index.html?drill=support-flow`
- 難易度：easy
- 出典：`src/data/problems.json`

## 要求仕様

利用者の不具合報告について、状況を把握して対処し、対応結果を本人に伝えたい。 今回の図の対象：利用者から不具合の報告を受けてから、対応結果を伝えるまでの問い合わせ対応を見直す。

### 操作

要求仕様と左側のメモを読み、右側のカードで必要な処理と関係を図にしてください。

## 段階開示資料

左側にはヒアリングメモを本文だけの付箋で表示します。最初は3枚で、判断の根拠も含みます。「（他のメモも見る）」で追加メモをランダムに1枚開示し、1点減点します。付箋は移動・ゴミ箱への整理・復元ができます。復元による再減点はありません。以下の種別と正解接続はレビュー用の内部情報です。

### 最初に表示する3枚

1. 報告だけでは再現できないことがある。担当者は利用者に操作や利用環境を聞き取る。（内部種別：要件・要求／根拠：利用者が不具合を報告する → 担当者が発生条件を確認する）
2. 原因の調査には、聞き取った発生条件と再現状況を使う。（内部種別：要件・要求／根拠：担当者が発生条件を確認する → 原因を切り分ける）
3. サポート責任者は、問い合わせの多い操作を翌月の研修で取り上げたい。（内部種別：スコープ外／根拠：対象外）

## ヒント

利用者への返答だけでなく、その前に状況を確かめる作業にも目を向けてみましょう。

## 付箋

| ID | 種別 | ラベル |
|---|---|---|
| `report-issue` | 必要 | 利用者が不具合を報告する |
| `confirm-context` | 必要 | 担当者が発生条件を確認する |
| `isolate-cause` | 必要 | 原因を切り分ける |
| `apply-fix` | 必要 | 修正または回避策を行う |
| `share-result` | 必要 | 結果を利用者へ共有する |
| `plan-training` | 余分・参考 | 翌月の研修計画を作る |

## グループ

- **問い合わせの受付**：`report-issue`, `confirm-context`
- **原因の調査と対処**：`isolate-cause`, `apply-fix`

## 正解の接続

- `report-issue` → `confirm-context`
- `confirm-context` → `isolate-cause`
- `isolate-cause` → `apply-fix`
- `apply-fix` → `share-result`

## 解説

問い合わせの内容を把握して発生条件を確かめ、原因を切り分けて対処します。対応した結果を利用者へ共有して一連の流れが完了します。研修計画は問い合わせ対応とは別の業務です。
