# 備品購入の承認

- 問題ID：`purchase-approval`
- 直接開く：`src/index.html?drill=purchase-approval`
- 難易度：normal
- 出典：`src/data/problems.json`

## 問題文

「備品購入の承認」の見直しにあたり、関係者から集めたメモと設計資料です。今回整理する範囲を考えながら、必要な情報を集めてください。

### 課題

関係する付箋を選び、情報のつながりを矢印で整理してください。

## 段階開示資料

左側のホワイトボードに付箋として表示します。最初は外部設計1枚＋スコープ外2枚。「（ヒントを見る）」を押すたびに追加資料を1枚開示し、開くたびに1点減点します。追加資料は必要な情報とスコープ外の情報が混ざっており、開示順は毎回ランダムです。付箋はドラッグで自由に動かせます。

### 最初に表示する3枚

1. 外部設計｜処理概要（外部設計）：社員の備品購入の申請を、上長が確認して発注または差し戻しにするまでの流れ。結果は申請者に伝える。
2. 未決事項（スコープ外）：入力項目の桁数・型はテーブル定義に従う。画面項目の詳細は別途確認する。
3. 総務メモ（スコープ外）：備品カタログの表紙は、年度ごとに差し替わる。

### 追加で開示する資料（順不同）

| 資料 | 内容 | 種別 | 根拠になる正解接続 |
|---|---|---|---|
| 要件メモ | 「社員が購入申請」を行った後に、「上長が内容を確認」へ進む。 | 要件・要求 | 社員が購入申請 → 上長が内容を確認 |
| 要求メモ | 「上長が内容を確認」を受けて、「予算内か判定」につなぐ。 | 要件・要求 | 上長が内容を確認 → 予算内か判定 |
| 詳細設計｜内部処理 | 「予算内か判定」の結果次第で、行き先（「備品を発注」、「申請を差し戻す」）が決まる。 | 詳細設計 | 予算内か判定 → 備品を発注<br>予算内か判定 → 申請を差し戻す |
| 外部設計｜処理順序 | 「備品を発注」が終わったら、「申請者へ結果を通知」に移る。 | 外部設計 | 備品を発注 → 申請者へ結果を通知 |
| 外部設計｜処理順序 | 「申請を差し戻す」を受けて、「申請者へ結果を通知」につなぐ。 | 外部設計 | 申請を差し戻す → 申請者へ結果を通知 |
| 設定メモ | APIのタイムアウトは設定ファイルで管理する。 | スコープ外 | —（図に含めない） |
| 非機能メモ | 応答時間は3秒以内を目標とする。性能の検討は別の資料で行う。 | スコープ外 | —（図に含めない） |

## ヒント

判断の結果で処理が分かれますが、どちらの場合も申請者への連絡が必要そうです。最後の通知まで見てみましょう。

## 付箋

| ID | 種別 | ラベル |
|---|---|---|
| `purchase-approval-n1` | 必要 | 社員が購入申請 |
| `purchase-approval-n2` | 必要 | 上長が内容を確認 |
| `purchase-approval-n3` | 必要 | 予算内か判定 |
| `purchase-approval-n4` | 必要 | 備品を発注 |
| `purchase-approval-n5` | 必要 | 申請を差し戻す |
| `purchase-approval-n6` | 必要 | 申請者へ結果を通知 |
| `purchase-approval-x1` | 余分・参考 | 備品カタログの表紙 |

## グループ

- **申請と判断**：`purchase-approval-n1`, `purchase-approval-n2`, `purchase-approval-n3`
- **判断後の処理**：`purchase-approval-n4`, `purchase-approval-n5`, `purchase-approval-n6`

## 正解の接続

- `purchase-approval-n1` → `purchase-approval-n2`
- `purchase-approval-n2` → `purchase-approval-n3`
- `purchase-approval-n3` → `purchase-approval-n4`
- `purchase-approval-n3` → `purchase-approval-n5`

- `purchase-approval-n5` → `purchase-approval-n6`

## 解説

この図では、社員が購入申請 → 上長が内容を確認 → 予算内か判定 → 備品を発注 → 申請を差し戻す → 申請者へ結果を通知の関係を整理します。予算内の場合と超過時の処理を分けます。「備品カタログの表紙」は今回の流れに含めません。
