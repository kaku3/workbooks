# 機能フラグの段階公開

- 問題ID：`feature-flag`
- 直接開く：`src/index.html?drill=feature-flag`
- 難易度：normal
- 出典：`src/data/problems.json`

## 要求仕様

新機能を限定公開して影響を確認し、安全なら対象を広げ、問題があれば停止したい。 今回の図の対象：新機能を一部の利用者へ公開し、様子を見ながら、対象を広げるか止めるかを決める流れ。

### 操作

要求仕様と左側のメモを読み、右側のカードで必要な処理と関係を図にしてください。

## 段階開示資料

左側にはヒアリングメモを本文だけの付箋で表示します。最初は3枚で、判断の根拠も含みます。「（他のメモも見る）」で追加メモをランダムに1枚開示し、1点減点します。付箋は移動・ゴミ箱への整理・復元ができます。復元による再減点はありません。以下の種別と正解接続はレビュー用の内部情報です。

### 最初に表示する3枚

1. 限定利用者が機能を使えるのは、対象機能のフラグが有効なときだけ。（内部種別：要件・要求／根拠：機能フラグを有効化 → 限定利用者へ公開）
2. 監視では、限定公開された利用者の利用状況を集める。（内部種別：要件・要求／根拠：限定利用者へ公開 → 利用状況を監視）
3. フラグ管理画面では有効と無効を色だけに頼らず見分けたい。（内部種別：スコープ外／根拠：対象外）

## ヒント

公開後の状態を見て、次の対応を決めます。問題がない場合と、問題が見つかった場合の行き先を考えましょう。

## グループ

- **限定公開と監視**：`feature-flag-n1`, `feature-flag-n2`, `feature-flag-n3`, `feature-flag-n4`
- **判定後の操作**：`feature-flag-n5`, `feature-flag-n6`

## 解説

この図では、機能フラグを有効化 → 限定利用者へ公開 → 利用状況を監視 → 問題の有無を判定 → 対象範囲を拡大 → 問題時に機能を停止の関係を整理します。監視結果に応じて拡大または停止します。「フラグ管理画面の色」は今回の流れに含めません。
