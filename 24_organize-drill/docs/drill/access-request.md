# システム権限の申請

- 問題ID：`access-request`
- 直接開く：`src/index.html?drill=access-request`
- 難易度：easy
- 出典：`src/data/problems.json`

## 問題文

「システム権限の申請」の見直しにあたり、関係者から集めたメモと設計資料です。今回整理する範囲を考えながら、必要な情報を集めてください。

### 課題

関係する付箋を選び、情報のつながりを矢印で整理してください。

## 段階開示資料

左側のホワイトボードに付箋として表示します。最初は外部設計1枚＋スコープ外2枚。「（ヒントを見る）」を押すたびに追加資料を1枚開示し、開くたびに1点減点します。追加資料は必要な情報とスコープ外の情報が混ざっており、開示順は毎回ランダムです。付箋はドラッグで自由に動かせます。

### 最初に表示する3枚

1. 外部設計｜処理概要（外部設計）：社員が業務システムの権限を申請し、確認を経て付与されるまでの流れ。
2. 画面仕様メモ（スコープ外）：権限画面の配色は、管理画面の共通スタイルに合わせる。
3. 運用メモ（スコープ外）：操作ログは1年間保存する。今回の処理フロー図では保存方式までは扱わない。

### 追加で開示する資料（順不同）

| 資料 | 内容 | 種別 | 根拠になる正解接続 |
|---|---|---|---|
| 外部設計｜処理順序 | 「社員が権限を申請」が終わったら、「上長が必要性を確認」に移る。 | 外部設計 | 社員が権限を申請 → 上長が必要性を確認 |
| 外部設計｜処理順序 | 「上長が必要性を確認」を受けて、「管理者が権限範囲を確認」につなぐ。 | 外部設計 | 上長が必要性を確認 → 管理者が権限範囲を確認 |
| 外部設計｜処理順序 | 「管理者が権限範囲を確認」の次は「権限を付与」を行う。 | 外部設計 | 管理者が権限範囲を確認 → 権限を付与 |
| 詳細設計｜内部処理 | 「権限を付与」が終わったら、「申請者へ結果を通知」に移る。 | 詳細設計 | 権限を付与 → 申請者へ結果を通知 |
| 開発標準メモ | 保存先テーブル名は開発標準に従う。 | スコープ外 | —（図に含めない） |
| 設定メモ | APIのタイムアウトは設定ファイルで管理する。 | スコープ外 | —（図に含めない） |

## ヒント

申請の理由が妥当かという確認と、実際に付与する権限の確認は別の観点です。確認の順番を整理しましょう。

## 付箋

| ID | 種別 | ラベル |
|---|---|---|
| `access-request-n1` | 必要 | 社員が権限を申請 |
| `access-request-n2` | 必要 | 上長が必要性を確認 |
| `access-request-n3` | 必要 | 管理者が権限範囲を確認 |
| `access-request-n4` | 必要 | 権限を付与 |
| `access-request-n5` | 必要 | 申請者へ結果を通知 |
| `access-request-x1` | 余分・参考 | 権限画面の配色 |

## グループ

- **申請と確認**：`access-request-n1`, `access-request-n2`, `access-request-n3`
- **付与と連絡**：`access-request-n4`, `access-request-n5`

## 正解の接続

- `access-request-n1` → `access-request-n2`
- `access-request-n2` → `access-request-n3`
- `access-request-n3` → `access-request-n4`
- `access-request-n4` → `access-request-n5`

## 解説

この図では、社員が権限を申請 → 上長が必要性を確認 → 管理者が権限範囲を確認 → 権限を付与 → 申請者へ結果を通知の関係を整理します。業務上の必要性と技術的な権限範囲を別々に確認します。「権限画面の配色」は今回の流れに含めません。
