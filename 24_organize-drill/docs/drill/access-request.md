# システム権限の申請

- 問題ID：`access-request`
- 直接開く：`src/index.html?drill=access-request`
- 難易度：easy
- 出典：`src/data/problems.json`

## 要求仕様

社員が業務に必要なシステム権限を申請できるようにしたい。業務上の必要性と利用可能な権限を確認したうえで付与し、申請者が結果を把握できること。 今回の図の対象：社員が業務システムの権限を申請し、確認を経て付与されるまでの流れ。

### 操作

要求仕様と左側のメモを読み、右側のカードで必要な処理と関係を図にしてください。

## 段階開示資料

左側にはヒアリングメモを本文だけの付箋で表示します。最初は3枚で、判断の根拠も含みます。「（他のメモも見る）」で追加メモをランダムに1枚開示し、1点減点します。付箋は移動・ゴミ箱への整理・復元ができます。復元による再減点はありません。以下の種別と正解接続はレビュー用の内部情報です。

### 最初に表示する3枚

1. 申請には利用したいシステムと業務上の理由を書いてもらう。理由の妥当性は、その社員の上長が確認する。（内部種別：要件・要求／根拠：社員が権限を申請 → 上長が必要性を確認）
2. 管理者が権限の範囲を確認する対象は、上長が業務上必要と認めた申請とする。（内部種別：要件・要求／根拠：上長が必要性を確認 → 管理者が権限範囲を確認）
3. 権限の一覧では、利用中と停止中を文字と色で見分けたい。（内部種別：スコープ外／根拠：対象外）

## ヒント

申請の理由が妥当かという確認と、実際に付与する権限の確認は別の観点です。確認の順番を整理しましょう。

## グループ

- **申請と確認**：`access-request-n1`, `access-request-n2`, `access-request-n3`
- **付与と連絡**：`access-request-n4`, `access-request-n5`

## 正解の接続

- `access-request-n1` → `access-request-n2`
- `access-request-n2` → `access-request-n3`
- `access-request-n3` → `access-request-n4`

## 解説

この図では、社員が権限を申請 → 上長が必要性を確認 → 管理者が権限範囲を確認 → 権限を付与 → 申請者へ結果を通知の関係を整理します。業務上の必要性と技術的な権限範囲を別々に確認します。「権限画面の配色」は今回の流れに含めません。
