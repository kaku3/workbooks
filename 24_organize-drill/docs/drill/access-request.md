# システム権限の申請

- 問題ID：`access-request`
- 難易度：easy
- 出典：`src/data/problems.json`

## 問題文

「システム権限の申請」に関する資料の断片です。

### 課題

図に載せる情報を見極め、付箋を矢印でつないでください。

## 資料の断片（現行データ）

### 要求仕様

- 導入時期は繁忙期を避ける
- 「社員が権限を申請」の後に「上長が必要性を確認」を行いたい
- 「管理者が権限範囲を確認」を実現したい
- 「管理者が権限範囲を確認」の後に「権限を付与」を行いたい

### 要件

- 「上長が必要性を確認」完了後に「管理者が権限範囲を確認」へ進む
- 機能要件：社員が権限を申請
- 機能要件：権限を付与
- 「権限画面の配色」は担当者間で認識が異なる

### 外部設計

- 利用者から見える動き：上長が必要性を確認

### 詳細設計（現行データ）

- 「権限を付与」完了後に「申請者へ結果を通知」を呼び出す
- 内部処理：申請者へ結果を通知

## ヒント

申請の理由が妥当かという確認と、実際に付与する権限の確認は別の観点です。確認の順番を整理しましょう。

## グループ

- **申請と確認**：`access-request-n1`, `access-request-n2`, `access-request-n3`
- **付与と連絡**：`access-request-n4`, `access-request-n5`

## 正解の接続

## 解説

この図では、社員が権限を申請 → 上長が必要性を確認 → 管理者が権限範囲を確認 → 権限を付与 → 申請者へ結果を通知の関係を整理します。業務上の必要性と技術的な権限範囲を別々に確認します。「権限画面の配色」は今回の流れに含めません。
