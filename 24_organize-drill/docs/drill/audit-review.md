# 操作ログの定期確認

- 問題ID：`audit-review`
- 直接開く：`src/index.html?drill=audit-review`
- 難易度：normal
- 出典：`src/data/problems.json`

## 要求仕様

一定期間の操作を監査し、異常があれば調査して確認結果を残したい。 今回の図の対象：操作ログを定期的に確認し、異常があれば調査を依頼して、結果を記録する流れ。

### 操作

要求仕様と左側のメモを読み、右側のカードで必要な処理と関係を図にしてください。

## 段階開示資料

左側にはヒアリングメモを本文だけの付箋で表示します。最初は3枚で、判断の根拠も含みます。「（他のメモも見る）」で追加メモをランダムに1枚開示し、1点減点します。付箋は移動・ゴミ箱への整理・復元ができます。復元による再減点はありません。以下の種別と正解接続はレビュー用の内部情報です。

### 最初に表示する3枚

1. ログの抽出範囲は、監査の対象として決めた期間とする。（内部種別：要件・要求／根拠：確認対象期間を決める → 操作ログを抽出）
2. 異常操作の確認には、対象期間から抽出したログを使う。（内部種別：要件・要求／根拠：操作ログを抽出 → 異常な操作を確認）
3. ログ画面の列幅を変え、長い操作内容も省略せず読めるようにしたい。（内部種別：スコープ外／根拠：対象外）

## ヒント

確認結果によって追加調査が必要になる場合があります。調査を行う場合と行わない場合の流れを考えましょう。

- **判定後の記録**：`audit-review-n5`, `audit-review-n6`

## 解説

この図では、確認対象期間を決める → 操作ログを抽出 → 異常な操作を確認 → 問題の有無を判定 → 必要時に調査を依頼 → 確認結果を記録の関係を整理します。確認結果によって調査依頼の有無が分かれます。「ログ画面の列幅」は今回の流れに含めません。
