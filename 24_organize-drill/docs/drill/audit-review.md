# 操作ログの定期確認

- 問題ID：`audit-review`
- 直接開く：`src/index.html?drill=audit-review`
- 難易度：normal
- 出典：`src/data/problems.json`

## 問題文

「操作ログの定期確認」の見直しにあたり、関係者から集めたメモと設計資料です。今回整理する範囲を考えながら、必要な情報を集めてください。

### 課題

資料の順番に惑わされず、必要な付箋を選んで図にしてください。

## 段階開示資料

左側のホワイトボードに付箋として表示します。最初は外部設計1枚＋スコープ外2枚。「（ヒントを見る）」を押すたびに追加資料を1枚開示し、開くたびに1点減点します。追加資料は必要な情報とスコープ外の情報が混ざっており、開示順は毎回ランダムです。付箋はドラッグで自由に動かせます。

### 最初に表示する3枚

1. 外部設計｜処理概要（外部設計）：操作ログを定期的に確認し、異常があれば調査を依頼して、結果を記録する流れ。
2. 帳票メモ（スコープ外）：帳票レイアウトは別紙を参照する。
3. 画面仕様メモ（スコープ外）：ログ画面の列幅は、利用者が画面上で調整できる。

### 追加で開示する資料（順不同）

| 資料 | 内容 | 種別 | 根拠になる正解接続 |
|---|---|---|---|
| 要件メモ | 「確認対象期間を決める」の次は「操作ログを抽出」を行う。 | 要件・要求 | 確認対象期間を決める → 操作ログを抽出 |
| 要求メモ | 「操作ログを抽出」を行った後に、「異常な操作を確認」へ進む。 | 要件・要求 | 操作ログを抽出 → 異常な操作を確認 |
| 外部設計｜処理順序 | 「異常な操作を確認」を受けて、「問題の有無を判定」につなぐ。 | 外部設計 | 異常な操作を確認 → 問題の有無を判定 |
| 外部設計｜分岐の扱い | 「問題の有無を判定」の結果に応じて、「必要時に調査を依頼」、「確認結果を記録」のいずれかへ進む。 | 外部設計 | 問題の有無を判定 → 必要時に調査を依頼<br>問題の有無を判定 → 確認結果を記録 |
| 要件メモ | 「必要時に調査を依頼」の次は「確認結果を記録」を行う。 | 要件・要求 | 必要時に調査を依頼 → 確認結果を記録 |
| 設定メモ | APIのタイムアウトは設定ファイルで管理する。 | スコープ外 | —（図に含めない） |
| 研修メモ | 操作研修の資料は別途用意する。 | スコープ外 | —（図に含めない） |

## ヒント

確認結果によって追加調査が必要になる場合があります。調査を行う場合と行わない場合の流れを考えましょう。

## 付箋

| ID | 種別 | ラベル |
|---|---|---|
| `audit-review-n1` | 必要 | 確認対象期間を決める |
| `audit-review-n2` | 必要 | 操作ログを抽出 |
| `audit-review-n3` | 必要 | 異常な操作を確認 |
| `audit-review-n4` | 必要 | 問題の有無を判定 |
| `audit-review-n5` | 必要 | 必要時に調査を依頼 |
| `audit-review-n6` | 必要 | 確認結果を記録 |
| `audit-review-x1` | 余分・参考 | ログ画面の列幅 |

## グループ

- **ログ抽出と確認**：`audit-review-n1`, `audit-review-n2`, `audit-review-n3`, `audit-review-n4`
- **判定後の記録**：`audit-review-n5`, `audit-review-n6`

## 正解の接続

- `audit-review-n1` → `audit-review-n2`
- `audit-review-n2` → `audit-review-n3`
- `audit-review-n3` → `audit-review-n4`
- `audit-review-n4` → `audit-review-n5`
- `audit-review-n4` → `audit-review-n6`
- `audit-review-n5` → `audit-review-n6`

## 解説

この図では、確認対象期間を決める → 操作ログを抽出 → 異常な操作を確認 → 問題の有無を判定 → 必要時に調査を依頼 → 確認結果を記録の関係を整理します。確認結果によって調査依頼の有無が分かれます。「ログ画面の列幅」は今回の流れに含めません。
