# 作業依頼のレビュー

- 問題ID：`task-review`
- 直接開く：`src/index.html?drill=task-review`
- 難易度：normal
- 出典：`src/data/problems.json`

## 要求仕様

作業依頼の情報がそろっているか確認し、担当を割り当てて着手予定を伝えたい。不足があれば依頼者に確認する。 今回の図の対象：作業依頼を受け付け、情報の過不足に応じて、依頼者への確認または担当者への割り当てを行う流れ。

### 操作

要求仕様と左側のメモを読み、右側のカードで必要な処理と関係を図にしてください。

## 段階開示資料

左側にはヒアリングメモを本文だけの付箋で表示します。最初は3枚で、判断の根拠も含みます。「（他のメモも見る）」で追加メモをランダムに1枚開示し、1点減点します。付箋は移動・ゴミ箱への整理・復元ができます。復元による再減点はありません。以下の種別と正解接続はレビュー用の内部情報です。

### 最初に表示する3枚

1. 受け付けた依頼に、目的や期限など着手に必要な情報があるか確認する。（内部種別：要件・要求／根拠：作業依頼を受け付ける → 必要情報を確認）
2. 情報が十分かの判断は、確認した項目の内容に基づいて行う。（内部種別：要件・要求／根拠：必要情報を確認 → 情報が十分か判定）
3. 依頼フォームの背景色は、長時間入力しても目が疲れにくいものにしたい。（内部種別：スコープ外／根拠：対象外）

## ヒント

依頼内容が十分かどうかで、担当者へ回す前に必要な作業が変わります。判断の後を見比べてみましょう。

## 解説

この図では、作業依頼を受け付ける → 必要情報を確認 → 情報が十分か判定 → 不足情報を依頼者へ確認 → 担当者へ割り当て → 着手予定を通知の関係を整理します。不足情報がある依頼は割り当て前に確認します。「依頼フォームの背景色」は今回の流れに含めません。
