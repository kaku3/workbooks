# 作業依頼のレビュー

- 問題ID：`task-review`
- 直接開く：`src/index.html?drill=task-review`
- 難易度：normal
- 出典：`src/data/problems.json`

## 問題文

「作業依頼のレビュー」の見直しにあたり、関係者から集めたメモと設計資料です。今回整理する範囲を考えながら、必要な情報を集めてください。

### 課題

図に載せる情報を見極め、付箋を矢印でつないでください。

## 段階開示資料

左側のホワイトボードに付箋として表示します。最初は外部設計1枚＋スコープ外2枚。「（ヒントを見る）」を押すたびに追加資料を1枚開示し、開くたびに1点減点します。追加資料は必要な情報とスコープ外の情報が混ざっており、開示順は毎回ランダムです。付箋はドラッグで自由に動かせます。

### 最初に表示する3枚

1. 外部設計｜処理概要（外部設計）：作業依頼を受け付け、情報の過不足に応じて、依頼者への確認または担当者への割り当てを行う流れ。
2. 画面仕様メモ（スコープ外）：依頼フォームの背景色は、共通スタイルに合わせる。
3. 未決事項（スコープ外）：入力項目の桁数・型はテーブル定義に従う。画面項目の詳細は別途確認する。

### 追加で開示する資料（順不同）

| 資料 | 内容 | 種別 | 根拠になる正解接続 |
|---|---|---|---|
| 外部設計｜処理順序 | 「作業依頼を受け付ける」を受けて、「必要情報を確認」につなぐ。 | 外部設計 | 作業依頼を受け付ける → 必要情報を確認 |
| 外部設計｜処理順序 | 「必要情報を確認」の次は「情報が十分か判定」を行う。 | 外部設計 | 必要情報を確認 → 情報が十分か判定 |
| 詳細設計｜内部処理 | 「情報が十分か判定」の結果に応じて、「不足情報を依頼者へ確認」、「担当者へ割り当て」のいずれかへ進む。 | 詳細設計 | 情報が十分か判定 → 不足情報を依頼者へ確認<br>情報が十分か判定 → 担当者へ割り当て |
| 外部設計｜処理順序 | 「担当者へ割り当て」を受けて、「着手予定を通知」につなぐ。 | 外部設計 | 担当者へ割り当て → 着手予定を通知 |
| 開発標準メモ | 保存先テーブル名は開発標準に従う。 | スコープ外 | —（図に含めない） |
| 要求メモ | 画面の雰囲気は現行システムに近づけたい。 | スコープ外 | —（図に含めない） |

## ヒント

依頼内容が十分かどうかで、担当者へ回す前に必要な作業が変わります。判断の後を見比べてみましょう。

## 付箋

| ID | 種別 | ラベル |
|---|---|---|
| `task-review-n1` | 必要 | 作業依頼を受け付ける |
| `task-review-n2` | 必要 | 必要情報を確認 |
| `task-review-n3` | 必要 | 情報が十分か判定 |
| `task-review-n4` | 必要 | 不足情報を依頼者へ確認 |
| `task-review-n5` | 必要 | 担当者へ割り当て |
| `task-review-n6` | 必要 | 着手予定を通知 |
| `task-review-x1` | 余分・参考 | 依頼フォームの背景色 |

## グループ

- **依頼受付と確認**：`task-review-n1`, `task-review-n2`, `task-review-n3`
- **確認結果**：`task-review-n4`, `task-review-n5`, `task-review-n6`

## 正解の接続

- `task-review-n1` → `task-review-n2`
- `task-review-n2` → `task-review-n3`
- `task-review-n3` → `task-review-n4`
- `task-review-n3` → `task-review-n5`
- `task-review-n5` → `task-review-n6`

## 解説

この図では、作業依頼を受け付ける → 必要情報を確認 → 情報が十分か判定 → 不足情報を依頼者へ確認 → 担当者へ割り当て → 着手予定を通知の関係を整理します。不足情報がある依頼は割り当て前に確認します。「依頼フォームの背景色」は今回の流れに含めません。
