# 予約キャンセル待ち

- 問題ID：`reservation-cancel`
- 直接開く：`src/index.html?drill=reservation-cancel`
- 難易度：normal
- 出典：`src/data/problems.json`

## 問題文

「予約キャンセル待ち」の見直しにあたり、関係者から集めたメモと設計資料です。今回整理する範囲を考えながら、必要な情報を集めてください。

### 課題

図に載せる情報を見極め、付箋を矢印でつないでください。

## 段階開示資料

左側のホワイトボードに付箋として表示します。最初は外部設計1枚＋スコープ外2枚。「（ヒントを見る）」を押すたびに追加資料を1枚開示し、開くたびに1点減点します。追加資料は必要な情報とスコープ外の情報が混ざっており、開示順は毎回ランダムです。付箋はドラッグで自由に動かせます。

### 最初に表示する3枚

1. 外部設計｜処理概要（外部設計）：満席の予約に対してキャンセル待ちを受け付け、空きが出たときに利用者へ案内する流れ。
2. 広報メモ（スコープ外）：施設の外観写真は、広報が案内ページ用に撮り直している。
3. 帳票メモ（スコープ外）：帳票レイアウトは別紙を参照する。

### 追加で開示する資料（順不同）

| 資料 | 内容 | 種別 | 根拠になる正解接続 |
|---|---|---|---|
| 要求メモ | 「満席を確認」を行った後に、「キャンセル待ちを登録」へ進む。 | 要件・要求 | 満席を確認 → キャンセル待ちを登録 |
| 詳細設計｜内部処理 | 「キャンセル待ちを登録」を行った後に、「予約の取消を受け付ける」へ進む。 | 詳細設計 | キャンセル待ちを登録 → 予約の取消を受け付ける |
| 外部設計｜処理順序 | 「予約の取消を受け付ける」が終わったら、「待ち順の先頭を確認」に移る。 | 外部設計 | 予約の取消を受け付ける → 待ち順の先頭を確認 |
| 要件メモ | 「待ち順の先頭を確認」の次は「空席案内を送信」を行う。 | 要件・要求 | 待ち順の先頭を確認 → 空席案内を送信 |
| 要求メモ | 「空席案内を送信」を受けて、「利用者が予約を確定」につなぐ。 | 要件・要求 | 空席案内を送信 → 利用者が予約を確定 |
| 非機能メモ | 応答時間は3秒以内を目標とする。性能の検討は別の資料で行う。 | スコープ外 | —（図に含めない） |
| 要求メモ | 導入時期は繁忙期を避けたい。 | スコープ外 | —（図に含めない） |

## ヒント

満席の時点で行うことと、後から空きが出た時に行うことを時間の流れでつないでみましょう。

## 付箋

| ID | 種別 | ラベル |
|---|---|---|
| `reservation-cancel-n1` | 必要 | 満席を確認 |
| `reservation-cancel-n2` | 必要 | キャンセル待ちを登録 |

## グループ

- **空席案内**：`reservation-cancel-n3`, `reservation-cancel-n4`, `reservation-cancel-n5`, `reservation-cancel-n6`

## 解説

この図では、満席を確認 → キャンセル待ちを登録 → 予約の取消を受け付ける → 待ち順の先頭を確認 → 空席案内を送信 → 利用者が予約を確定の関係を整理します。満席時の登録と、後日空席が出た後の処理をつなぎます。「施設の外観写真」は今回の流れに含めません。
