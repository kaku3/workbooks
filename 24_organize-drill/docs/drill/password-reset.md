# パスワード再設定

- 問題ID：`password-reset`
- 直接開く：`src/index.html?drill=password-reset`
- 難易度：easy
- 出典：`src/data/problems.json`

## 問題文

「パスワード再設定」の見直しにあたり、関係者から集めたメモと設計資料です。今回整理する範囲を考えながら、必要な情報を集めてください。

### 課題

図に載せる情報を見極め、付箋を矢印でつないでください。

## 段階開示資料

左側のホワイトボードに付箋として表示します。最初は外部設計1枚＋スコープ外2枚。「（ヒントを見る）」を押すたびに追加資料を1枚開示し、開くたびに1点減点します。追加資料は必要な情報とスコープ外の情報が混ざっており、開示順は毎回ランダムです。付箋はドラッグで自由に動かせます。

### 最初に表示する3枚

1. 外部設計｜処理概要（外部設計）：パスワードを忘れた利用者が、本人確認を経て新しいパスワードを登録するまでの流れ。
2. セキュリティメモ（スコープ外）：パスワードの保存ハッシュ方式は、社内のセキュリティ基準に従う。
3. 要求メモ（スコープ外）：導入時期は繁忙期を避けたい。

### 追加で開示する資料（順不同）

| 資料 | 内容 | 種別 | 根拠になる正解接続 |
|---|---|---|---|
| 要件メモ | 「再設定を申請」の次は「登録メールへ確認リンクを送信」を行う。 | 要件・要求 | 再設定を申請 → 登録メールへ確認リンクを送信 |
| 詳細設計｜内部処理 | 「登録メールへ確認リンクを送信」が終わったら、「確認リンクを開く」に移る。 | 詳細設計 | 登録メールへ確認リンクを送信 → 確認リンクを開く |
| 外部設計｜処理順序 | 「確認リンクを開く」が終わったら、「新しいパスワードを登録」に移る。 | 外部設計 | 確認リンクを開く → 新しいパスワードを登録 |
| 詳細設計｜内部処理 | 「新しいパスワードを登録」が終わったら、「完了を通知」に移る。 | 詳細設計 | 新しいパスワードを登録 → 完了を通知 |
| 非機能メモ | 応答時間は3秒以内を目標とする。性能の検討は別の資料で行う。 | スコープ外 | —（図に含めない） |
| 共通デザインメモ | エラー表示の色は共通スタイルに合わせる。 | スコープ外 | —（図に含めない） |

## ヒント

利用者が申請しただけでは、本人だと確認できません。確認が終わる前に進めてよい処理か考えてみましょう。

## 付箋

| ID | 種別 | ラベル |
|---|---|---|
| `password-reset-n1` | 必要 | 再設定を申請 |
| `password-reset-n2` | 必要 | 登録メールへ確認リンクを送信 |
| `password-reset-n3` | 必要 | 確認リンクを開く |
| `password-reset-n4` | 必要 | 新しいパスワードを登録 |
| `password-reset-n5` | 必要 | 完了を通知 |
| `password-reset-x1` | 余分・参考 | パスワードの保存ハッシュ方式 |

## グループ

- **本人確認**：`password-reset-n1`, `password-reset-n2`, `password-reset-n3`
- **再設定完了**：`password-reset-n4`, `password-reset-n5`

## 正解の接続

- `password-reset-n1` → `password-reset-n2`
- `password-reset-n2` → `password-reset-n3`
- `password-reset-n3` → `password-reset-n4`
- `password-reset-n4` → `password-reset-n5`

## 解説

この図では、再設定を申請 → 登録メールへ確認リンクを送信 → 確認リンクを開く → 新しいパスワードを登録 → 完了を通知の関係を整理します。内部の暗号化方式は処理手順と分けます。「パスワードの保存ハッシュ方式」は今回の流れに含めません。
