# パスワード再設定

- 問題ID：`password-reset`
- 直接開く：`src/index.html?drill=password-reset`
- 難易度：easy
- 出典：`src/data/problems.json`

## 要求仕様

パスワードを忘れた利用者が、登録メールを使って安全に再設定できるようにしたい。 今回の図の対象：パスワードを忘れた利用者が、本人確認を経て新しいパスワードを登録するまでの流れ。

### 操作

要求仕様と左側のメモを読み、右側のカードで必要な処理と関係を図にしてください。

## 段階開示資料

左側にはヒアリングメモを本文だけの付箋で表示します。最初は3枚で、判断の根拠も含みます。「（他のメモも見る）」で追加メモをランダムに1枚開示し、1点減点します。付箋は移動・ゴミ箱への整理・復元ができます。復元による再減点はありません。以下の種別と正解接続はレビュー用の内部情報です。

### 最初に表示する3枚

1. 再設定の依頼を受けたアカウントの登録メールに、確認用のリンクを送る。（内部種別：要件・要求／根拠：再設定を申請 → 登録メールへ確認リンクを送信）
2. 利用者は届いたメールのリンクから再設定の手続きを行う。（内部種別：要件・要求／根拠：登録メールへ確認リンクを送信 → 確認リンクを開く）
3. 保存したパスワードから元の文字列を読み出せないよう、ソルト付きのハッシュを使いたい。（内部種別：スコープ外／根拠：対象外）

## ヒント

利用者が申請しただけでは、本人だと確認できません。確認が終わる前に進めてよい処理か考えてみましょう。

## 付箋

| ID | 種別 | ラベル |
|---|---|---|
| `password-reset-n1` | 必要 | 再設定を申請 |
| `password-reset-n2` | 必要 | 登録メールへ確認リンクを送信 |
| `password-reset-n3` | 必要 | 確認リンクを開く |
| `password-reset-n4` | 必要 | 新しいパスワードを登録 |
| `password-reset-n5` | 必要 | 完了を通知 |
| `password-reset-x1` | 余分・参考 | パスワードの保存ハッシュ方式 |

## グループ

- **本人確認**：`password-reset-n1`, `password-reset-n2`, `password-reset-n3`
- **再設定完了**：`password-reset-n4`, `password-reset-n5`

## 正解の接続

- `password-reset-n1` → `password-reset-n2`
- `password-reset-n2` → `password-reset-n3`
- `password-reset-n3` → `password-reset-n4`
- `password-reset-n4` → `password-reset-n5`

## 解説

この図では、再設定を申請 → 登録メールへ確認リンクを送信 → 確認リンクを開く → 新しいパスワードを登録 → 完了を通知の関係を整理します。内部の暗号化方式は処理手順と分けます。「パスワードの保存ハッシュ方式」は今回の流れに含めません。
