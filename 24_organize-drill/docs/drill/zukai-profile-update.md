# プロフィール更新

- 問題ID：`zukai-profile-update`
- 直接開く：`src/index.html?drill=zukai-profile-update`
- 難易度：easy
- 出典：`src/data/problems.json`

## 問題文

「プロフィール更新」の見直しにあたり、関係者から集めたメモと設計資料です。今回整理する範囲を考えながら、必要な情報を集めてください。

### 課題

関係する付箋を選び、情報のつながりを矢印で整理してください。

## 段階開示資料

左側のホワイトボードに付箋として表示します。最初は外部設計1枚＋スコープ外2枚。「（ヒントを見る）」を押すたびに追加資料を1枚開示し、開くたびに1点減点します。追加資料は必要な情報とスコープ外の情報が混ざっており、開示順は毎回ランダムです。付箋はドラッグで自由に動かせます。

### 最初に表示する3枚

1. 外部設計｜処理概要（外部設計）：利用者が表示名を変更して保存を終えるまでの流れ。今回は入力に問題がない場合を扱う。
2. 共通デザインメモ（スコープ外）：保存ボタンの色は、共通スタイルの基本色を使う。
3. 要求メモ（スコープ外）：画面の雰囲気は現行システムに近づけたい。

### 追加で開示する資料（順不同）

| 資料 | 内容 | 種別 | 根拠になる正解接続 |
|---|---|---|---|
| 外部設計｜処理順序 | 「表示名を編集して保存」を受けて、「文字数をチェック」につなぐ。 | 外部設計 | 表示名を編集して保存 → 文字数をチェック |
| 外部設計｜処理順序 | 「文字数をチェック」を受けて、「データを保存」につなぐ。 | 外部設計 | 文字数をチェック → データを保存 |
| 外部設計｜処理順序 | 「データを保存」を行った後に、「完了メッセージを表示」へ進む。 | 外部設計 | データを保存 → 完了メッセージを表示 |
| 未決事項 | 将来の画像変更機能は、次期の検討事項として保留している。 | スコープ外 | —（図に含めない） |
| 運用メモ | 操作ログは1年間保存する。今回の処理フロー図では保存方式までは扱わない。 | スコープ外 | —（図に含めない） |

## ヒント

今回は、表示名を変更して保存する一連の流れが対象です。見た目や将来の機能は、処理そのものと分けて考えましょう。

| ID | 種別 | ラベル |
|---|---|---|
| `zukai-profile-update-n1` | 必要 | 表示名を編集して保存 |

| `zukai-profile-update-n3` | 必要 | データを保存 |

## 解説

この図では、表示名を編集して保存 → 文字数をチェック → データを保存 → 完了メッセージを表示の関係を整理します。将来機能や画面の見た目は今回の処理に含めません。「将来の画像変更機能」「保存ボタンの色」は今回の流れに含めません。
