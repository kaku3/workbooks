# プロフィール更新

- 問題ID：`zukai-profile-update`
- 直接開く：`src/index.html?drill=zukai-profile-update`
- 難易度：easy
- 出典：`src/data/problems.json`

## 要求仕様

利用者が自分の表示名を変更し、保存できたことを画面で確認できるようにしたい。今回は正常に保存できる場合の流れを整理する。 今回の図の対象：利用者が表示名を変更して保存を終えるまでの流れ。今回は入力に問題がない場合を扱う。

### 操作

要求仕様と左側のメモを読み、右側のカードで必要な処理と関係を図にしてください。

## 段階開示資料

左側にはヒアリングメモを本文だけの付箋で表示します。最初は3枚で、判断の根拠も含みます。「（他のメモも見る）」で追加メモをランダムに1枚開示し、1点減点します。付箋は移動・ゴミ箱への整理・復元ができます。復元による再減点はありません。以下の種別と正解接続はレビュー用の内部情報です。

### 最初に表示する3枚

1. 保存操作で送られる表示名は、文字数の確認対象になる。（内部種別：要件・要求／根拠：表示名を編集して保存 → 文字数をチェック）
2. 記録する表示名は、文字数の条件を満たしたものに限る。今回は条件内の入力を扱う。（内部種別：要件・要求／根拠：文字数をチェック → データを保存）
3. 将来は表示名だけでなく、本人のプロフィール画像も変更できるようにしたい。（内部種別：スコープ外／根拠：対象外）

## ヒント

今回は、表示名を変更して保存する一連の流れが対象です。見た目や将来の機能は、処理そのものと分けて考えましょう。

## 解説

この図では、表示名を編集して保存 → 文字数をチェック → データを保存 → 完了メッセージを表示の関係を整理します。将来機能や画面の見た目は今回の処理に含めません。「将来の画像変更機能」「保存ボタンの色」は今回の流れに含めません。
