# 請求書の支払い

- 問題ID：`invoice-payment`
- 直接開く：`src/index.html?drill=invoice-payment`
- 難易度：easy
- 出典：`src/data/problems.json`

## 要求仕様

請求書の内容を照合して承認を得た支払いを行い、支払実績を残したい。 今回の図の対象：届いた請求書を確認し、承認を得て支払い、記録を残すまでの流れ。

### 操作

要求仕様と左側のメモを読み、右側のカードで必要な処理と関係を図にしてください。

## 段階開示資料

左側にはヒアリングメモを本文だけの付箋で表示します。最初は3枚で、判断の根拠も含みます。「（他のメモも見る）」で追加メモをランダムに1枚開示し、1点減点します。付箋は移動・ゴミ箱への整理・復元ができます。復元による再減点はありません。以下の種別と正解接続はレビュー用の内部情報です。

### 最初に表示する3枚

1. 受領した請求書の金額と明細を、発注や納品の内容と照合する。（内部種別：要件・要求／根拠：請求書を受領 → 金額と明細を照合）
2. 承認者には、照合を終えた請求内容を渡す。（内部種別：要件・要求／根拠：金額と明細を照合 → 承認を依頼）
3. 紙の請求書は他の帳票と混ざっても分かるよう、用紙の色をそろえたい。（内部種別：スコープ外／根拠：対象外）

## ヒント

支払いに進む前に、内容の確認が必要です。問題が見つかった場合の戻し先も考えてみましょう。

## グループ

- **受領と照合**：`invoice-payment-n1`, `invoice-payment-n2`
- **承認と支払い**：`invoice-payment-n3`, `invoice-payment-n4`, `invoice-payment-n5`

## 解説

この図では、請求書を受領 → 金額と明細を照合 → 承認を依頼 → 承認後に振込 → 支払記録を保存の関係を整理します。明細に問題がある場合は承認へ回さず差し戻します。「請求書の紙色」は今回の流れに含めません。
