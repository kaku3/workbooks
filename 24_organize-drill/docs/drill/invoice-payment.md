# 請求書の支払い

- 問題ID：`invoice-payment`
- 直接開く：`src/index.html?drill=invoice-payment`
- 難易度：easy
- 出典：`src/data/problems.json`

## 問題文

「請求書の支払い」の見直しにあたり、関係者から集めたメモと設計資料です。今回整理する範囲を考えながら、必要な情報を集めてください。

### 課題

関係する付箋を選び、情報のつながりを矢印で整理してください。

## 段階開示資料

左側のホワイトボードに付箋として表示します。最初は外部設計1枚＋スコープ外2枚。「（ヒントを見る）」を押すたびに追加資料を1枚開示し、開くたびに1点減点します。追加資料は必要な情報とスコープ外の情報が混ざっており、開示順は毎回ランダムです。付箋はドラッグで自由に動かせます。

### 最初に表示する3枚

1. 外部設計｜処理概要（外部設計）：届いた請求書を確認し、承認を得て支払い、記録を残すまでの流れ。
2. 備品メモ（スコープ外）：請求書の紙色は、取引先ごとのフォーマットに任せている。
3. 共通デザインメモ（スコープ外）：エラー表示の色は共通スタイルに合わせる。

### 追加で開示する資料（順不同）

| 資料 | 内容 | 種別 | 根拠になる正解接続 |
|---|---|---|---|
| 詳細設計｜内部処理 | 「請求書を受領」の次は「金額と明細を照合」を行う。 | 詳細設計 | 請求書を受領 → 金額と明細を照合 |
| 外部設計｜処理順序 | 「金額と明細を照合」が終わったら、「承認を依頼」に移る。 | 外部設計 | 金額と明細を照合 → 承認を依頼 |
| 詳細設計｜内部処理 | 「承認を依頼」が終わったら、「承認後に振込」に移る。 | 詳細設計 | 承認を依頼 → 承認後に振込 |
| 詳細設計｜内部処理 | 「承認後に振込」を受けて、「支払記録を保存」につなぐ。 | 詳細設計 | 承認後に振込 → 支払記録を保存 |
| 利用メモ | 同時利用は最大50人を想定している。 | スコープ外 | —（図に含めない） |
| 要求メモ | 導入時期は繁忙期を避けたい。 | スコープ外 | —（図に含めない） |

## ヒント

支払いに進む前に、内容の確認が必要です。問題が見つかった場合の戻し先も考えてみましょう。

## 付箋

| ID | 種別 | ラベル |
|---|---|---|
| `invoice-payment-n1` | 必要 | 請求書を受領 |
| `invoice-payment-n2` | 必要 | 金額と明細を照合 |
| `invoice-payment-n3` | 必要 | 承認を依頼 |
| `invoice-payment-n4` | 必要 | 承認後に振込 |
| `invoice-payment-n5` | 必要 | 支払記録を保存 |
| `invoice-payment-x1` | 余分・参考 | 請求書の紙色 |

## グループ

- **受領と照合**：`invoice-payment-n1`, `invoice-payment-n2`
- **承認と支払い**：`invoice-payment-n3`, `invoice-payment-n4`, `invoice-payment-n5`

## 正解の接続

- `invoice-payment-n1` → `invoice-payment-n2`
- `invoice-payment-n2` → `invoice-payment-n3`
- `invoice-payment-n3` → `invoice-payment-n4`
- `invoice-payment-n4` → `invoice-payment-n5`

## 正解例の配置

| 付箋ID | x | y |
|---|---:|---:|
| `invoice-payment-n1` | 0.13 | 0.5 |
| `invoice-payment-n2` | 0.315 | 0.5 |
| `invoice-payment-n3` | 0.5 | 0.5 |
| `invoice-payment-n4` | 0.685 | 0.5 |
| `invoice-payment-n5` | 0.87 | 0.5 |

## 解説

この図では、請求書を受領 → 金額と明細を照合 → 承認を依頼 → 承認後に振込 → 支払記録を保存の関係を整理します。明細に問題がある場合は承認へ回さず差し戻します。「請求書の紙色」は今回の流れに含めません。
