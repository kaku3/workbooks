# 在庫連携バッチ

- 問題ID：`zukai-stock-sync`
- 直接開く：`src/index.html?drill=zukai-stock-sync`
- 難易度：normal
- 出典：`src/data/problems.json`

## 問題文

「在庫連携バッチ」の見直しにあたり、関係者から集めたメモと設計資料です。今回整理する範囲を考えながら、必要な情報を集めてください。

### 課題

資料の順番に惑わされず、必要な付箋を選んで図にしてください。

## 段階開示資料

左側のホワイトボードに付箋として表示します。最初は外部設計1枚＋スコープ外2枚。「（ヒントを見る）」を押すたびに追加資料を1枚開示し、開くたびに1点減点します。追加資料は必要な情報とスコープ外の情報が混ざっており、開示順は毎回ランダムです。付箋はドラッグで自由に動かせます。

### 最初に表示する3枚

1. 外部設計｜処理概要（外部設計）：毎時の在庫連携で、自社システムと外部倉庫がデータをやり取りし、結果を記録または通知する流れ。
2. 共通デザインメモ（スコープ外）：エラー表示の色は共通スタイルに合わせる。
3. 運用メモ（スコープ外）：実行サーバー名は、運用手順書に記載している。

### 追加で開示する資料（順不同）

| 資料 | 内容 | 種別 | 根拠になる正解接続 |
|---|---|---|---|
| 外部設計｜処理順序 | 「毎時バッチを開始」を受けて、「在庫CSVを送信」につなぐ。 | 外部設計 | 毎時バッチを開始 → 在庫CSVを送信 |
| 要件メモ | 「在庫CSVを送信」が終わったら、「処理結果CSVを受信」に移る。 | 要件・要求 | 在庫CSVを送信 → 処理結果CSVを受信 |
| 要件メモ | 「処理結果CSVを受信」の結果次第で、行き先（「成功時刻を記録」、「失敗行を担当者へ通知」）が決まる。 | 要件・要求 | 処理結果CSVを受信 → 成功時刻を記録<br>処理結果CSVを受信 → 失敗行を担当者へ通知 |
| 連携仕様メモ | CSVの列順の詳細は、別紙のインターフェース定義に従う。 | スコープ外 | —（図に含めない） |
| 運用メモ | 操作ログは1年間保存する。今回の処理フロー図では保存方式までは扱わない。 | スコープ外 | —（図に含めない） |

## ヒント

データを送った後、結果を受け取ります。成功した場合と問題があった場合で、記録や連絡が変わる点に注目しましょう。

## 付箋

| ID | 種別 | ラベル |
|---|---|---|
| `zukai-stock-sync-n1` | 必要 | 毎時バッチを開始 |
| `zukai-stock-sync-n2` | 必要 | 在庫CSVを送信 |
| `zukai-stock-sync-n3` | 必要 | 処理結果CSVを受信 |
| `zukai-stock-sync-n4` | 必要 | 成功時刻を記録 |
| `zukai-stock-sync-n5` | 必要 | 失敗行を担当者へ通知 |
| `zukai-stock-sync-x1` | 余分・参考 | CSVの列順の詳細 |
| `zukai-stock-sync-x2` | 余分・参考 | 実行サーバー名 |

## グループ

- **外部連携**：`zukai-stock-sync-n2`, `zukai-stock-sync-n3`
- **結果処理**：`zukai-stock-sync-n4`, `zukai-stock-sync-n5`

## 正解の接続

- `zukai-stock-sync-n1` → `zukai-stock-sync-n2`
- `zukai-stock-sync-n2` → `zukai-stock-sync-n3`
- `zukai-stock-sync-n3` → `zukai-stock-sync-n4`
- `zukai-stock-sync-n3` → `zukai-stock-sync-n5`

## 解説

この図では、毎時バッチを開始 → 在庫CSVを送信 → 処理結果CSVを受信 → 成功時刻を記録 → 失敗行を担当者へ通知の関係を整理します。CSVの列順などの詳細設定は今回の処理の流れから分けます。「CSVの列順の詳細」「実行サーバー名」は今回の流れに含めません。
