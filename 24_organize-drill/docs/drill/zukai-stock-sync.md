# 在庫連携バッチ

- 問題ID：`zukai-stock-sync`
- 直接開く：`src/index.html?drill=zukai-stock-sync`
- 難易度：normal
- 出典：`src/data/problems.json`

## 要求仕様

毎時、外部倉庫と在庫を連携し、成功の記録または失敗行の連絡を残したい。 今回の図の対象：毎時の在庫連携で、自社システムと外部倉庫がデータをやり取りし、結果を記録または通知する流れ。

### 操作

要求仕様と左側のメモを読み、右側のカードで必要な処理と関係を図にしてください。

## 段階開示資料

左側にはヒアリングメモを本文だけの付箋で表示します。最初は3枚で、判断の根拠も含みます。「（他のメモも見る）」で追加メモをランダムに1枚開示し、1点減点します。付箋は移動・ゴミ箱への整理・復元ができます。復元による再減点はありません。以下の種別と正解接続はレビュー用の内部情報です。

### 最初に表示する3枚

1. 在庫連携の起動時刻は毎時とし、その回の在庫データを倉庫へCSVで渡す。（内部種別：要件・要求／根拠：毎時バッチを開始 → 在庫CSVを送信）
2. 倉庫から返る処理結果CSVは、送った在庫CSVに対する結果として照合する。（内部種別：要件・要求／根拠：在庫CSVを送信 → 処理結果CSVを受信）
3. CSVの列は商品コード、倉庫コード、在庫数の順に統一し、倉庫側で取り込みやすくしたい。（内部種別：スコープ外／根拠：対象外）

## ヒント

データを送った後、結果を受け取ります。成功した場合と問題があった場合で、記録や連絡が変わる点に注目しましょう。

## 解説

この図では、毎時バッチを開始 → 在庫CSVを送信 → 処理結果CSVを受信 → 成功時刻を記録 → 失敗行を担当者へ通知の関係を整理します。CSVの列順などの詳細設定は今回の処理の流れから分けます。「CSVの列順の詳細」「実行サーバー名」は今回の流れに含めません。
