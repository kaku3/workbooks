# 問い合わせのエスカレーション

- 問題ID：`support-escalation`
- 直接開く：`src/index.html?drill=support-escalation`
- 難易度：normal
- 出典：`src/data/problems.json`

## 問題文

「問い合わせのエスカレーション」の見直しにあたり、関係者から集めたメモと設計資料です。今回整理する範囲を考えながら、必要な情報を集めてください。

### 課題

図に必要な付箋を選び、処理の流れを矢印でつないでください。

## 段階開示資料

左側のホワイトボードに付箋として表示します。最初は外部設計1枚＋スコープ外2枚。「（ヒントを見る）」を押すたびに追加資料を1枚開示し、開くたびに1点減点します。追加資料は必要な情報とスコープ外の情報が混ざっており、開示順は毎回ランダムです。付箋はドラッグで自由に動かせます。

### 最初に表示する3枚

1. 外部設計｜処理概要（外部設計）：窓口に届いた問い合わせについて、窓口で解決するか専門部署へ引き継ぐかを判断し、利用者へ回答する流れ。
2. 総務メモ（スコープ外）：担当者の座席配置は、四半期ごとに見直している。
3. 設定メモ（スコープ外）：APIのタイムアウトは設定ファイルで管理する。

## ヒント

窓口で解決できる場合と、専門部署の助けが必要な場合があります。どちらも最終的に利用者へ返答する点に注目しましょう。

## 付箋

| ID | 種別 | ラベル |
|---|---|---|
| `support-escalation-n1` | 必要 | 問い合わせを受け付ける |
| `support-escalation-n2` | 必要 | 窓口で内容を確認 |
| `support-escalation-n3` | 必要 | 窓口で解決可能か判定 |

## グループ

## 解説

この図では、問い合わせを受け付ける → 窓口で内容を確認 → 窓口で解決可能か判定 → 専門部署へ引き継ぐ → 専門部署が回答を作成 → 利用者へ回答するの関係を整理します。窓口で解決できる場合と、専門部署へ引き継ぐ場合を分けます。「担当者の座席配置」は今回の流れに含めません。
