# ネット注文の流れを整理する

- 問題ID：`order-flow`
- 直接開く：`src/index.html?drill=order-flow`
- 難易度：easy
- 出典：`src/data/problems.json`

## 要求仕様

注文者が安心して商品を受け取れるよう、受付から発送連絡までを管理したい。 今回の図の対象：ネット注文を受け付けてから、利用者へ発送を知らせるまでの一連の業務を見直す。注文1件ごとに繰り返される流れが対象。

### 操作

要求仕様と左側のメモを読み、右側のカードで必要な処理と関係を図にしてください。

## 段階開示資料

左側にはヒアリングメモを本文だけの付箋で表示します。最初は3枚で、判断の根拠も含みます。「（他のメモも見る）」で追加メモをランダムに1枚開示し、1点減点します。付箋は移動・ゴミ箱への整理・復元ができます。復元による再減点はありません。以下の種別と正解接続はレビュー用の内部情報です。

### 最初に表示する3枚

1. 注文者から届く品目と数量が、在庫を調べるための情報になる。（内部種別：要件・要求／根拠：利用者が注文内容を送信する → システムが在庫を確認する）
2. 代金を請求できるのは、注文分の在庫を確保できる場合とする。（内部種別：要件・要求／根拠：システムが在庫を確認する → 決済を処理する）
3. 経理は月ごとの売上を商品別に比較し、次月の販売計画に使いたい。（内部種別：スコープ外／根拠：対象外）

## ヒント

まずは注文を受けてから発送するまでを追ってみましょう。今回の流れと関係の薄い付箋も混ざっています。

## 付箋

| ID | 種別 | ラベル |
|---|---|---|
| `submit-order` | 必要 | 利用者が注文内容を送信する |
| `check-stock` | 必要 | システムが在庫を確認する |
| `process-payment` | 必要 | 決済を処理する |
| `request-shipping` | 必要 | 倉庫へ出荷を依頼する |
| `notify-shipped` | 必要 | 利用者へ発送を通知する |
| `monthly-sales` | 余分・参考 | 月次の売上を集計する |

## グループ

- **注文の処理**：`check-stock`, `process-payment`, `request-shipping`

## 正解の接続

- `submit-order` → `check-stock`
- `check-stock` → `process-payment`
- `process-payment` → `request-shipping`
- `request-shipping` → `notify-shipped`

## 正解例の配置

| 付箋ID | x | y |
|---|---:|---:|
| `submit-order` | 0.12 | 0.5 |
| `check-stock` | 0.31 | 0.5 |
| `process-payment` | 0.5 | 0.5 |
| `request-shipping` | 0.69 | 0.5 |
| `notify-shipped` | 0.88 | 0.5 |

## 解説

注文を受け付けた後、在庫を確かめ、決済し、出荷を依頼してから発送を知らせます。月次の売上集計は別の目的の業務なので、この注文処理の図には含めません。
