# ログインの流れ

- 問題ID：`zukai-login`
- 直接開く：`src/index.html?drill=zukai-login`
- 難易度：hard
- 出典：`src/data/problems.json`

## 問題文

「ログインの流れ」の見直しにあたり、関係者から集めたメモと設計資料です。今回整理する範囲を考えながら、必要な情報を集めてください。

### 課題

資料の順番に惑わされず、必要な付箋を選んで図にしてください。

## 段階開示資料

左側のホワイトボードに付箋として表示します。最初は外部設計1枚＋スコープ外2枚。「（ヒントを見る）」を押すたびに追加資料を1枚開示し、開くたびに1点減点します。追加資料は必要な情報とスコープ外の情報が混ざっており、開示順は毎回ランダムです。付箋はドラッグで自由に動かせます。

### 最初に表示する3枚

1. 外部設計｜処理概要（外部設計）：利用者がログインしてホーム画面に進むまでの流れ。アカウントの状態と認証の結果によって、行き先が変わる。
2. 画面仕様メモ（スコープ外）：ログイン画面の背景画像は、季節ごとにデザイナーが差し替える。
3. 利用メモ（スコープ外）：同時利用は最大50人を想定している。

### 追加で開示する資料（順不同）

| 資料 | 内容 | 種別 | 根拠になる正解接続 |
|---|---|---|---|
| 外部設計｜処理順序 | 「認証情報を入力」を受けて、「アカウント状態を確認」につなぐ。 | 外部設計 | 認証情報を入力 → アカウント状態を確認 |
| 外部設計｜分岐の扱い | 「アカウント状態を確認」の結果に応じて、「利用停止を案内」、「システムが認証」のいずれかへ進む。 | 外部設計 | アカウント状態を確認 → 利用停止を案内<br>アカウント状態を確認 → システムが認証 |
| 要件メモ | 「システムが認証」の結果次第で、行き先（「ホーム画面を表示」、「認証エラーを表示」）が決まる。 | 要件・要求 | システムが認証 → ホーム画面を表示<br>システムが認証 → 認証エラーを表示 |
| 設定メモ | APIのタイムアウトは設定ファイルで管理する。 | スコープ外 | —（図に含めない） |
| 未決事項 | 入力項目の桁数・型はテーブル定義に従う。画面項目の詳細は別途確認する。 | スコープ外 | —（図に含めない） |

## ヒント

認証の結果によって、そのまま利用できる場合と、利用できない場合がありそうです。結果が変わる場所を探してみましょう。

## 付箋

| ID | 種別 | ラベル |
|---|---|---|
| `zukai-login-n1` | 必要 | 認証情報を入力 |
| `zukai-login-n2` | 必要 | システムが認証 |
| `zukai-login-n3` | 必要 | ホーム画面を表示 |
| `zukai-login-x1` | 余分・参考 | ログイン画面の背景画像 |
| `zukai-login-n4` | 必要 | アカウント状態を確認 |
| `zukai-login-n5` | 必要 | 利用停止を案内 |
| `zukai-login-n6` | 必要 | 認証エラーを表示 |

## グループ

- **認証の流れ**：`zukai-login-n1`, `zukai-login-n2`, `zukai-login-n3`

## 正解の接続

- `zukai-login-n1` → `zukai-login-n4`
- `zukai-login-n4` → `zukai-login-n5`
- `zukai-login-n4` → `zukai-login-n2`
- `zukai-login-n2` → `zukai-login-n3`
- `zukai-login-n2` → `zukai-login-n6`

## 解説

アカウント状態の確認では、利用停止中なら案内を表示し、利用可能なら認証へ進みます。認証結果も成功時はホーム画面、失敗時はエラー表示に分岐します。
