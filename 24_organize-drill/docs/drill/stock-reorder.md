# 在庫不足の補充

- 問題ID：`stock-reorder`
- 直接開く：`src/index.html?drill=stock-reorder`
- 難易度：easy
- 出典：`src/data/problems.json`

## 問題文

「在庫不足の補充」の見直しにあたり、関係者から集めたメモと設計資料です。今回整理する範囲を考えながら、必要な情報を集めてください。

### 課題

関係する付箋を選び、情報のつながりを矢印で整理してください。

## 段階開示資料

左側のホワイトボードに付箋として表示します。最初は外部設計1枚＋スコープ外2枚。「（ヒントを見る）」を押すたびに追加資料を1枚開示し、開くたびに1点減点します。追加資料は必要な情報とスコープ外の情報が混ざっており、開示順は毎回ランダムです。付箋はドラッグで自由に動かせます。

### 最初に表示する3枚

1. 外部設計｜処理概要（外部設計）：在庫数が基準を下回った商品を補充し、在庫数に反映するまでの流れ。
2. 開発標準メモ（スコープ外）：保存先テーブル名は開発標準に従う。
3. 拠点メモ（スコープ外）：倉庫の所在地は、拠点一覧に記載している。

### 追加で開示する資料（順不同）

| 資料 | 内容 | 種別 | 根拠になる正解接続 |
|---|---|---|---|
| 要求メモ | 「在庫数を確認」を受けて、「補充基準と比較」につなぐ。 | 要件・要求 | 在庫数を確認 → 補充基準と比較 |
| 外部設計｜処理順序 | 「補充基準と比較」を受けて、「仕入先へ発注」につなぐ。 | 外部設計 | 補充基準と比較 → 仕入先へ発注 |
| 外部設計｜処理順序 | 「仕入先へ発注」を受けて、「入荷を確認」につなぐ。 | 外部設計 | 仕入先へ発注 → 入荷を確認 |
| 外部設計｜処理順序 | 「入荷を確認」の次は「在庫数を更新」を行う。 | 外部設計 | 入荷を確認 → 在庫数を更新 |
| 帳票メモ | 帳票レイアウトは別紙を参照する。 | スコープ外 | —（図に含めない） |
| 画面仕様メモ | 画面文言は後日確定する。 | スコープ外 | —（図に含めない） |

## ヒント

在庫を確認した後、すぐに在庫数を書き換えるわけではありません。発注から入荷までの順番を考えましょう。

## 付箋

| ID | 種別 | ラベル |
|---|---|---|
| `stock-reorder-n1` | 必要 | 在庫数を確認 |
| `stock-reorder-n2` | 必要 | 補充基準と比較 |
| `stock-reorder-n3` | 必要 | 仕入先へ発注 |
| `stock-reorder-n4` | 必要 | 入荷を確認 |
| `stock-reorder-n5` | 必要 | 在庫数を更新 |
| `stock-reorder-x1` | 余分・参考 | 倉庫の所在地 |

## グループ

- **補充判断**：`stock-reorder-n1`, `stock-reorder-n2`, `stock-reorder-n3`
- **入荷反映**：`stock-reorder-n4`, `stock-reorder-n5`

## 正解の接続

- `stock-reorder-n1` → `stock-reorder-n2`
- `stock-reorder-n2` → `stock-reorder-n3`
- `stock-reorder-n3` → `stock-reorder-n4`
- `stock-reorder-n4` → `stock-reorder-n5`

## 解説

この図では、在庫数を確認 → 補充基準と比較 → 仕入先へ発注 → 入荷を確認 → 在庫数を更新の関係を整理します。在庫確認から発注、入荷後の反映を順に整理します。「倉庫の所在地」は今回の流れに含めません。
