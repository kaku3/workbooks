# 在庫不足の補充

- 問題ID：`stock-reorder`
- 難易度：easy
- 出典：`src/data/problems.json`

## 問題文

「在庫不足の補充」の打ち合わせ後に残った資料です。

### 課題

資料の順番に惑わされず、必要な付箋を選んで図にしてください。

## 資料の断片（現行データ）

### 要求仕様

- 「入荷を確認」を実現したい
- 「在庫数を確認」の後に「補充基準と比較」を行いたい

### 要件

- 機能要件：補充基準と比較

### 外部設計

- 帳票レイアウトは別紙参照
- 「仕入先へ発注」の次に「入荷を確認」を行う
- 利用者から見える動き：在庫数を更新
- 参考：倉庫の所在地

### 詳細設計（現行データ）

- 「入荷を確認」完了後に「在庫数を更新」を呼び出す
- 内部処理：在庫数を確認
- 内部処理：仕入先へ発注
- 「補充基準と比較」完了後に「仕入先へ発注」を呼び出す

## ヒント

在庫を確認した後、すぐに在庫数を書き換えるわけではありません。発注から入荷までの順番を考えましょう。

## 付箋

| ID | 種別 | ラベル |
|---|---|---|
| `stock-reorder-n1` | 必要 | 在庫数を確認 |
| `stock-reorder-n2` | 必要 | 補充基準と比較 |
| `stock-reorder-n3` | 必要 | 仕入先へ発注 |
| `stock-reorder-n4` | 必要 | 入荷を確認 |
| `stock-reorder-n5` | 必要 | 在庫数を更新 |
| `stock-reorder-x1` | 余分・参考 | 倉庫の所在地 |

## グループ

- **補充判断**：`stock-reorder-n1`, `stock-reorder-n2`, `stock-reorder-n3`
- **入荷反映**：`stock-reorder-n4`, `stock-reorder-n5`

## 正解の接続

- `stock-reorder-n1` → `stock-reorder-n2`
- `stock-reorder-n2` → `stock-reorder-n3`
- `stock-reorder-n3` → `stock-reorder-n4`
- `stock-reorder-n4` → `stock-reorder-n5`

## 解説

この図では、在庫数を確認 → 補充基準と比較 → 仕入先へ発注 → 入荷を確認 → 在庫数を更新の関係を整理します。在庫確認から発注、入荷後の反映を順に整理します。「倉庫の所在地」は今回の流れに含めません。
