# ファイルアップロードと検証

- 問題ID：`zukai-upload`
- 直接開く：`src/index.html?drill=zukai-upload`
- 難易度：hard
- 出典：`src/data/problems.json`

## 要求仕様

10MB以内のPDFを受け付けて一覧で使えるようにしたい。条件に合わないファイルは保存せず、エラーを伝える。 今回の図の対象：利用者がPDFをアップロードし、条件を満たすものだけを保存して一覧に反映する流れ。条件を満たさない場合の扱いも含む。

### 操作

要求仕様と左側のメモを読み、右側のカードで必要な処理と関係を図にしてください。

## 段階開示資料

左側にはヒアリングメモを本文だけの付箋で表示します。最初は3枚で、判断の根拠も含みます。「（他のメモも見る）」で追加メモをランダムに1枚開示し、1点減点します。付箋は移動・ゴミ箱への整理・復元ができます。復元による再減点はありません。以下の種別と正解接続はレビュー用の内部情報です。

### 最初に表示する3枚

1. 受け取ったファイルは容量の検査対象になる。（内部種別：要件・要求／根拠：PDFをアップロード → サイズ上限10MBを確認）
2. 10MBを超えるものはエラーとし、拡張子の検査には回さない。容量内ならPDF形式かを調べる。（内部種別：要件・要求／根拠：サイズ上限10MBを確認 → 拡張子がPDFか確認、サイズ上限10MBを確認 → エラーを表示）
3. 運用担当者は、ファイル保存領域の残容量が少なくなったことを監視画面で把握したい。（内部種別：スコープ外／根拠：対象外）

## 解説

この図では、PDFをアップロード → サイズ上限10MBを確認 → 拡張子がPDFか確認 → ファイルを保存 → 一覧に反映 → エラーを表示の関係を整理します。サイズ・形式のどちらかが不適合ならエラーへ進みます。「サーバーのディスク容量監視」は今回の流れに含めません。
