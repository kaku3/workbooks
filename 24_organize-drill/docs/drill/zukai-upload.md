# ファイルアップロードと検証

- 問題ID：`zukai-upload`
- 直接開く：`src/index.html?drill=zukai-upload`
- 難易度：hard
- 出典：`src/data/problems.json`

## 問題文

「ファイルアップロードと検証」の見直しにあたり、関係者から集めたメモと設計資料です。今回整理する範囲を考えながら、必要な情報を集めてください。

### 課題

関係する付箋を選び、情報のつながりを矢印で整理してください。

## 段階開示資料

左側のホワイトボードに付箋として表示します。最初は外部設計1枚＋スコープ外2枚。「（ヒントを見る）」を押すたびに追加資料を1枚開示し、開くたびに1点減点します。追加資料は必要な情報とスコープ外の情報が混ざっており、開示順は毎回ランダムです。付箋はドラッグで自由に動かせます。

### 最初に表示する3枚

1. 外部設計｜処理概要（外部設計）：利用者がPDFをアップロードし、条件を満たすものだけを保存して一覧に反映する流れ。条件を満たさない場合の扱いも含む。
2. 運用メモ（スコープ外）：サーバーのディスク容量監視は、運用チームが別の仕組みで行っている。
3. 帳票メモ（スコープ外）：帳票レイアウトは別紙を参照する。

### 追加で開示する資料（順不同）

| 資料 | 内容 | 種別 | 根拠になる正解接続 |
|---|---|---|---|
| 要求メモ | 「PDFをアップロード」を行った後に、「サイズ上限10MBを確認」へ進む。 | 要件・要求 | PDFをアップロード → サイズ上限10MBを確認 |
| 詳細設計｜内部処理 | 「サイズ上限10MBを確認」の後は、状況によって「拡張子がPDFか確認」／「エラーを表示」に分かれる。 | 詳細設計 | サイズ上限10MBを確認 → 拡張子がPDFか確認<br>サイズ上限10MBを確認 → エラーを表示 |
| 外部設計｜分岐の扱い | 「拡張子がPDFか確認」の結果次第で、行き先（「ファイルを保存」、「エラーを表示」）が決まる。 | 外部設計 | 拡張子がPDFか確認 → ファイルを保存<br>拡張子がPDFか確認 → エラーを表示 |
| 外部設計｜処理順序 | 「ファイルを保存」を行った後に、「一覧に反映」へ進む。 | 外部設計 | ファイルを保存 → 一覧に反映 |
| 要求メモ | 画面の雰囲気は現行システムに近づけたい。 | スコープ外 | —（図に含めない） |
| 利用メモ | 同時利用は最大50人を想定している。 | スコープ外 | —（図に含めない） |

## ヒント

確認項目が複数あります。どれか一つでも条件を満たさない場合、処理はどうなるでしょう？

## 付箋

| ID | 種別 | ラベル |
|---|---|---|
| `zukai-upload-n1` | 必要 | PDFをアップロード |
| `zukai-upload-n2` | 必要 | サイズ上限10MBを確認 |
| `zukai-upload-n3` | 必要 | 拡張子がPDFか確認 |
| `zukai-upload-n4` | 必要 | ファイルを保存 |
| `zukai-upload-n5` | 必要 | 一覧に反映 |
| `zukai-upload-n6` | 必要 | エラーを表示 |
| `zukai-upload-x1` | 余分・参考 | サーバーのディスク容量監視 |

## グループ

- **アップロードと検証**：`zukai-upload-n1`, `zukai-upload-n2`, `zukai-upload-n3`
- **検証後の結果**：`zukai-upload-n4`, `zukai-upload-n5`, `zukai-upload-n6`

## 正解の接続

- `zukai-upload-n1` → `zukai-upload-n2`

## 解説

この図では、PDFをアップロード → サイズ上限10MBを確認 → 拡張子がPDFか確認 → ファイルを保存 → 一覧に反映 → エラーを表示の関係を整理します。サイズ・形式のどちらかが不適合ならエラーへ進みます。「サーバーのディスク容量監視」は今回の流れに含めません。
