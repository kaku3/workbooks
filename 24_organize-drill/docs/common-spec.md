# 図で整理ドリル 共通仕様

この文書は、`23_design-layer-drill/docs/共通仕様.md`の共通体験を参考にしながら、図で整理ドリル固有の操作と採点を定める。問題データ、画面、採点の振る舞いはこの仕様に揃える。

## 1. 学習体験

- 問題開始時に候補カードをキャンバスへランダム配置する。
- カードをドラッグして整理し、不要なカードはキャンバス左下のゴミ箱へ移動する。ゴミ箱からカードと元の位置を復元できる。
- カードを通る順にクリックして有向矢印をつなぐ。接続先が次の始点になる。同じカードを再クリックするかキャンバスの空白をクリックすると、線の追加を終了する。
- 上部は要求仕様、左側はヒアリングメモ、右側は解答の図作成エリアとする。メモは本文だけを表示し、色で必要性を示さない。初期3枚には判断材料も含める。追加メモはランダムに1枚ずつ開示し、1枚につき1点減点する。左側専用のゴミ箱で削除・復元でき、右側の解答と開示済み枚数には影響しない。復元は元の位置を優先し、重なる場合は空き位置に置く。再挑戦で初期化し、解答確定後は整理操作を止める。
- `index.html?drill=<問題ID>`（例：`?drill=zukai-payment-auth`）で指定した1問を直接開始する。存在しないIDのときは通常の開始画面に案内を表示する。
- 回答後は「解答」と「正解例」を並べる。両方のキャンバス寸法、拡大率、スクロール位置を揃える。
- 解答の正しい矢印は青い実線、正解パターンにない矢印は赤い点線で示す。凡例とテキストでも意味を説明する。
- 回答後は始点・線の選択、削除用アイコン、配置ガイドを解除する。
- 開始画面に「さらっと3問」「じっくり5問」の開始ボタンを置き、選択後すぐ出題を始める。3問は「初級・中級・上級」、5問は「初級・中級・初級・中級・上級」の順で、各難易度の問題群から重複なしで選ぶ。
- 通常セッションを一度完了すると、全問題からランダムに選ぶ「今日の1問」が解放される。日付ごとに同じ問題を出し、1日1回まで挑戦できる。
- 各問題は`easy`（初級）、`normal`（中級）、`hard`（上級）の難易度を持つ。初級はほぼ時系列どおりに情報を提示し、中級は議事メモの順序を入れ替えて補足や背景ノイズを混ぜ、上級は複数の条件判断・例外・背景情報を交錯させる。上級問題には異なる条件判断による分岐点を2か所以上設定する。どの難易度でも必要カードと正解接続がpromptだけから一意に読み取れること。hintは起点・分岐・合流に注目できるようpromptより整理して記述する。
- キャリア表示は`23_design-layer-drill`と同じ形式とし、累計ポイントを`career.json`のステージ基準と比較してランクを決める。通常問題の正解は基礎点10pt、今日の1問の正解は基礎点20pt。さらに、正誤に関係なく各問の芸術点1点につきキャリアポイントを1pt加算し、配置を整えることにもランクアップ上の価値を持たせる。芸術点は正解数や基礎点には混ぜず、独立した内訳として扱う。正解累計の節目では追加ボーナスを付与する。
- 結果画面は正解数、正答率、所要時間、今回実際に加算されたポイント合計と内訳（基礎点・芸術点・節目ボーナス）を表示し、各問題の解説と芸術点を振り返れる。今日の1問を完了した日は再挑戦ボタンを無効化する。
- 学習履歴はブラウザーのlocalStorageに保存し、挑戦カレンダーと直近10回の正答率グラフを表示する。記録が1回だけでもグラフに点を表示する。カレンダーの挑戦日を選ぶと、回数・正解数・基礎点・芸術点・節目ボーナス・合計ポイントを確認できる。問題データと継続設定はそれぞれ`src/data/problems.json`、`src/data/career.json`で管理する。
- フッターにFacebook、X、LINEのシェアリンクと問題集トップへのリンクを置く。ページタイトル、説明、OGPメタデータを設定する。

## 2. 採点の考え方

採点は「内容の正誤」と「図の整いポイント」の二本立てにする。配置の好みで内容の正解を不正解にしたり、内容の誤りを見た目の加点で相殺したりしない。

### 2.1 内容の正誤

- `kind: required`のカードをすべて使い、`kind: extra`のカードを含めず、データに定義された有向接続セットのいずれかと一致した場合に正解とする。
- 許容する別解は`connectionAlternatives`に列挙する。自動で文章の意味を推測して別解を認定しない。
- カードの座標、整列、間隔、意味グループの配置は内容の正誤に含めない。

### 2.2 図の整いポイント（芸術点）

内容の正誤とは別に集計する。配置カードがN枚（2枚以上）の場合、最大は `1 + 2 × (N−1)` 点。5枚なら重なりなし1点＋整列4点＋等間隔4点で9点となる。0〜1枚は0点。何も操作していない解答は0点とする。回答確定時の配置を評価し、内容の正解数からは減点しない。

| 評価項目 | 点 | 判定 |
| --- | ---: | --- |
| 重なりがない | 1 | 配置済みカードが2枚以上あり、カード同士が重なっていない |
| 中心が整列 | 1組1点、最大N−1 | 同じ行・列で中心が12px以内に揃う隣接カードを数える |
| 等間隔 | 1間隔1点、最大N−1 | 同じ行・列で隣り合う間隔同士の平均からのずれが12%以内なら、その間隔を数える。2枚だけの場合はカード寸法＋28pxとの差が14px以内 |
| 追加資料の開示 | −1／枚 | 「（他のメモも見る）」で追加資料を開くたびに1点減点する。下限は0点 |

重なるカードの組は整列・等間隔の加点に使わない。横と縦の両方で整列していても、同じまとまりの中で循環する組を重複加点しない。各項目は独立して、つながったN枚なら最大N−1点になるよう数える。意味のまとまりは採点対象にしない。


### 2.3 表示

- 回答直後に「図の整いポイント（芸術点） 得点 / 最大点」と、整列・等間隔の加点数を表示する。
- 結果画面では各問の得点と最大点、セッション合計を表示する。最大点は各問の配置カード数から求めて合算する。
- 正解数と整いポイントは別の欄に表示し、正答率に整いポイントを混ぜない。

## 3. 問題データ

問題固有の内容と採点根拠は`src/data/problems.json`で管理する。

- `prompt`: `requirements`（要求仕様）・`intro`（互換用）・`task`（操作説明）・`documents`（初期3枚と追加メモ）。原稿は `documents-source.json` に手書きで管理する。全接続の根拠を初期・追加の両方の `covers` で検証し、対象外候補は `itemIds` で追跡する。詳細は `src/data/README.md`。
- `items`: カード候補と`required`／`extra`の区分
- `connections`: 標準の正解となる有向接続セット
- `connectionAlternatives`: 任意の許容接続セット
- `groups`: 任意の意味グループ。各要素は`id`、`label`、`itemIds`を持つ
- `layout`: 正解例の座標。採点には使用しない
- `source`: 問題の出典・再構成元を示す任意の記録。20_zukai-drill由来の題材は`20_zukai-drill`とする。
- `difficulty`: 必須。`easy`、`normal`、`hard`のいずれか。

`groups`は図で近くに置くと伝わりやすいカードの集合を問題ごとに明示する。問題文や解説と整合しないグループを加点目的だけで設定しない。

```json
{
  "groups": [
    { "id": "parallel-checks", "label": "並行する確認", "itemIds": ["manager-approve", "check-receipt"] }
  ]
}
```

## 4. 変更時のルール

- 採点条件や閾値を変更した場合、この仕様書と結果画面の説明も同時に更新する。
- 配置採点は学習上の正誤から独立させ、採点理由を利用者が読める言葉で表示する。
- 配置点の自動判定は幾何情報と問題データだけを使う。曖昧な意味解釈を自動採点の正解条件にしない。
- 問題データに意味グループを足す場合、グループ名とカードのまとまりが学習上妥当かを確認する。
