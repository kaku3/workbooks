# data/

全50問の要求仕様、ヒアリングメモ、解答カード、正解の接続、完成例を管理します。

## 原稿と生成

`documents-source.json`（version 2）を要求仕様とメモの原稿として編集します。本文は問題ごとに手書きし、正解接続から自動生成しません。`problems.json` の prompt だけを直接直すと再生成で戻るため、原稿を変更してください。

```
node data/build-problems.mjs      # カード・正解などを再構築する必要がある場合のみ
node data/build-documents.mjs     # 原稿を problems.json に組み込む
node data/build-documents.mjs --check  # 原稿との一致・根拠の網羅を確認する
node data/build-review-docs.mjs   # ../docs/drill/*.md を更新する
```

上記は src/ から実行します。build-problems の実行後は必ず build-documents を実行します。レビュー資料の「レビュー・見直しメモ」は保持されます。

## prompt と原稿

- `requirements`：上部に表示する要求仕様。利用者、目的、期待する振る舞い、今回の図の範囲を示します。
- `intro`：互換用。生成時に requirements と同じ内容を設定します。
- `task`：共通の操作説明です。要求仕様の表示には使いません。
- `documents.initial`：最初に見せる3枚。判断の根拠も含めて選びます。
- `documents.additional`：ランダムに1枚ずつ開示するメモ。開くごとに1点減点します。

各メモは `text`（本文）、`kind`（内部種別）、`covers`（根拠となる接続）、任意の `itemIds` と `id` を持ちます。IDは省略時に問題IDと通し番号から付与します。付箋は本文だけを表示し、色はメモごとにランダムに割り当てます。内部種別や必要性を色で伝えません。

`covers` は `始点ID->終点ID` の配列です。初期・追加を合わせて、標準解と許容する別解の全接続に根拠があることを検証します。同じ接続を複数のメモで補っても構いません。`kind: scope` は対象外の要求であり、対応する extra カードを `itemIds` に指定します。必要カードの語が本文に含まれること自体は禁止しません。

接続のメタデータだけでは文章の意味は検証できません。レビュー資料で、条件・担当・結果から解答を導けるか確認してください。特に分岐、並行、やり直しの違いを曖昧にしないようにします。

左側のメモは移動・削除・復元できます。ゴミ箱は右側の解答カードから独立し、採点や開示枚数に影響しません。復元で再減点しません。再挑戦では初期化し、解答確定後は整理操作を停止します。

## 問題データ

- `id`・`title`：問題IDとタイトル
- `difficulty`：easy / normal / hard
- `prompt`・`hint`：要求仕様、メモ、考える手がかり
- `items`：カード候補。kind は required（必要）または extra（今回の図の対象外）
- `connections`：標準解の有向接続 `[始点ID, 終点ID]`
- `connectionAlternatives`：任意。許容する別の接続セット
- `groups`：意味上ひとまとまりとして扱うカード群
- `layout`：完成例の配置座標。内容の正誤には使用しません
- `explanation`：要素選択と接続の説明

内容の正誤はカード選択と有向接続で判定します。データにない別解を自動で意味判定しません。`career.json` はポイント報酬とステージの設定です。
