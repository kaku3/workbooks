# Src To Docs Writeback Checklist

このファイルは「変更しやすいチェック別冊」。
チェック観点の追加・削除・並び替えはこのファイルのみ編集する。

## 0. 前提

- 対象は実装事実の反映であり、提案や理想仕様の追記ではない。
- 参照順は `data.js` -> `check.html` -> `index.html` -> `types.html` -> `history.html` -> `style.css`。

## 1. 画面・導線

- [ ] 実在ページ一覧が `docs/ReadMe.md` に反映されている
- [ ] ナビゲーション導線（相互リンク）が記載されている
- [ ] 画面ごとの主目的が実装どおりに記載されている

## 2. 設問・データ定義

- [ ] 設問数が実装と一致している
- [ ] 各設問文が最新の実装文言と一致している
- [ ] タイプ定義（ID、名称、グループ）の整合が取れている
- [ ] 重み行列（スコア配列）の前提が記載されている

## 3. 採点・判定ロジック

- [ ] `calcScores` 相当の計算式が仕様に記載されている
- [ ] 判定閾値（良好/概ね問題なし/要観察/介入推奨）が実装と一致している
- [ ] 正規化ルール（負値の扱い、最大値基準）が一致している
- [ ] 最低回答数など、結果表示条件が一致している

## 4. 結果表示

- [ ] Zスコア表示の仕様が実装どおりに記載されている
- [ ] レーダーチャートの対象軸・説明が一致している
- [ ] 上位タイプ表示ロジックが説明されている
- [ ] 共有URL仕様（クエリ形式）が記載されている

## 5. 永続化・履歴

- [ ] ローカル保存キーが仕様に記載されている
- [ ] 保存件数上限や保持形式が実装と一致している
- [ ] 履歴画面の編集/削除/再表示導線が記載されている

## 6. 文書品質

- [ ] 仕様内に「未実装機能」が紛れ込んでいない
- [ ] 仕様内に「実装済み機能の記載漏れ」がない
- [ ] 断定文には根拠となる実装箇所がある
- [ ] 同じ情報の重複記載が最小化されている

## 7. 変更差分サマリ

- [ ] 何を更新したか（章単位）を最後に明記した
- [ ] 既知の未反映事項があれば明示した
