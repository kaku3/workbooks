# 第3章 レビュー項目

> **状態：再設計をゲームへ反映済み。** 問題・会話の編集正本は docs/problems と docs/scenarios。調査の構造と背景は本分冊を参照する。

各経路固有の確認点は [20_フロー.md](20_フロー.md) の4-1〜4-6。ここでは経路横断のレビューを扱う。

## 1. 経路を横断する検証

| 図を見て確かめる問い | 確認の基準 |
|---|---|
| 依頼だけを受けた人が、最初のチケットを自分で思い付けるか | 担当・実物・画面・コード・資料・先輩という入口に限定している |
| 次の調査を選ぶ理由は、直前の観測から説明できるか | 止まったのに登録がある／通知が来た／再送で増えた、という観測を起点にしている |
| 経路ごとの情報の確度を正しく扱えるか | 同じ事実は同等に扱う一方、単件の確認・新しい検証用コードの結果・完成版の設計上の推測は区別して報告できる |
| 準備状況が変わった再調査に、新しい意味があるか | 初回の結果を無効にせず、新たな記録や疑問があれば追加確認できる。新情報のない反復とは分ける |
| 途中で進め方を変えても調査を続けられるか | 得た証拠は保持され、別の入口に入り直したことを理由に既知の調査を強制しない |
| 真壁の答えが採点用の正解になっていないか | 経験案と確認先に留め、今回の事実・合意・価格を自動付与しない |
| 詳細設計を終えなくても、適切に切り上げられるか | 大きな作業と業務上の違いが分かれば、両案の概算と前提・未確認点を示して佐伯に持ち帰ってもらう。未消化の詳細設計・試験チケットは残してよい |
| A案以外にも仕事上の価値があるか | B案のやり直し削減、ライブラリ選定、規模検討、対象外の裏付けをそれぞれ意味のある成果にしている |
| 早めの報告や寄り道を含む進行が成立するか | 全チケット消化を要求せず、通常経路と任意調査の所要時間を確認する。途中報告による期限延長も同じ条件で使える |

各経路に固有の確認点は20_フロー.mdの4-1〜4-6に記載した。これらと上の横断項目を、実行結果・証拠・会話・採点条件と照らして確認する。構造を先に設計した後、問題・会話・判定へ具体化した。

## 2. 資料の状態と用語の確認

- 現行ゲームに使う原稿と、ドロップした旧設計を混同していないか。
- 既存の単件処理、P1の新しい検証用コード、完成版の未実装機能を区別しているか。
- 1日／10日は概算であり、確定工数・確約・一般相場として書いていないか。
- 最終地点が「佐伯が両案を持ち帰る」になっているか。採用結果の受領を要求していないか。
- 旧資料のリンクから入っても、ドロップ状態と現行の参照先が分かるか。
