# 第3章 台詞原稿の参照先

新しいフローに合わせた会話を制作し、[会話本文の正本](../scenarios/03_bulk-import.md)へ反映済み。本文を二重管理しない。原稿の改行は\n、強調は**強調**で記載する。

[リライト方針](rewrite.md)に沿って、66シーンとチャット13件を見直した。最終報告は佐伯の質問を挟み、CSVの準備、やり直し、概算差の理由を順に説明する。成功リアクションは、最終的に佐伯が両案を持ち帰る返答に合わせる。会話のシーン版は更新し、章の内容版2:2、ID、調査条件、時間、報告判定は維持する。

## 場面の対応

| 状況 | シーンID（03.を付ける） | 会話で扱う範囲 |
|---|---|---|
| 依頼 | intro / request | 佐伯の伝聞、折原の10万円、主人公のCSVという仮説から始め、当日18時の回答期限を伝える |
| 業務と現物 | business / workbook / mapping | 仕事を聞く／ファイルだけを見る／入力と対応付ける、を区別 |
| 準備と運用 | csv-preparation / csv-preparation-first / operations | 準備を実際に試す。まだ存在しない取込画面の使用実績にはしない |
| 今ある単件機能 | screen / source / spec / related / notification / retry | 現行の事実と、新規一括化の検討材料 |
| 新しい検証コード | prototype / related-prototype / notification-prototype / retry-prototype | この試作で起きた停止・確定・送信・再送。完成版の動作ではない |
| 記録の追加照合 | notification-followup | 以前の正常単件の確認を無効にせず、試作の記録を重ねる |
| 処理案と概算 | plan-a / plan-b / plan-both / estimate-a / estimate-b / estimate-both | 新設する機能の粗い作業量。1日・10日は所定CSVを前提にした概算 |
| 概算に根拠不足 | estimate-missing-structure / estimate-missing-notification / estimate-missing-retry | 分かっている事実を忘れず、残る疑問だけを示す |
| 真壁への相談 | makabe-* | 予定と今回の話題で分岐。マクロは経験案、今回の道具や合意ではない |
| 途中報告 | progress-* | その時点の進捗と留保。価格や採用を決めない |
| 一案の報告 | report-only-a / report-only-b | Aは真壁が止め、Bは佐伯が費用に難色。残る仕事に戻る理由を残す |
| 比較の報告 | report-operation / report-3 / clear | 業務が抜けた比較を問い直し、揃えば佐伯が持ち帰る |
| 寄り道と切り上げ | libraries / distributed / tables / macro-check / detail / recheck / no-progress | 調査成果と対象外の根拠。同じ対象の空回りと区別 |

台詞は観測した現物と、その時点の人物の知識から作る。佐伯に現場・ソースの全情報を最初から語らせない。真壁は教育用の模範解答を読み上げず、経験や関心から反応する。最後も採用を代行せず、概算と未確認点を付けて持ち帰りを頼む。

`plan-both` と `estimate-both` は旧保存の会話・履歴を表示するために残している。新しい進行で両案を一度に取得する経路は廃止し、`plan-a`／`plan-b` と `estimate-a`／`estimate-b` を一案ずつ使う。
