# 第3章 実装の対応と確認

分冊のフローを問題・会話原稿へ反映済み。設計の根拠はbackground・10・20、会話本文はdocs/scenarios/03_bulk-import.mdを正本とする。

## 1. 調査IDの対応

| 設計 | 実装ID（bi.を付ける） | 時間・扱い |
|---|---|---|
| I0〜I5 | request / business / workbook / screen / source / spec | 5 / 25 / 20 / 20 / 45 / 20分。仕様書後のソースは30分 |
| M1 | mapping | 業務またはExcelと、画面またはソースの入力を照合。20分 |
| M2 | csv-preparation | 担当に既に作業を聞いていれば25分、初めてなら35分。後者でも件数と実態が分かる |
| M3 | operations | 試作または処理案をもとに担当の仕事を確認。20分 |
| P1 | prototype | 新しく書いた検証用コード。35分。製品の一括機能ではない |
| D1 | related | 30分、ソースを読んでいれば20分。試作あり／なしの会話を分ける |
| D2 | notification / notification-followup | 単件の照合20分、新しく試作した記録の追加照合10分 |
| D3 | retry | 既存単件または試作への再送25分。未実装CSV再投入の実測にしない |
| R1 | plan / plan-more | 初回25分、別案の検討15分。同じ内容の反復は25分で新情報なし |
| R2 | estimate / estimate-update | 初回25分、新しい根拠・追加案を反映15分。足りない根拠を具体的に独白する |
| R3 | summary | 15分。持っていない情報や見積もりは増えない |
| K | ask-makabe | 話題と予定で分岐。忙しい10分、曖昧35分、具体的相談15分、概算の相談10分 |
| 任意 | libraries / distributed / tables / macro-check / detail | 40 / 60 / 45 / 25 / 60分。調査の意味と切り上げ先を残す |

昼休憩60分、途中報告30分、コーヒー5分は維持する。途中報告はどの段階・予定でも初日の延長条件になり、担当の合意や技術証拠を付けない。

## 2. 一案の検討と比較

処理案のチケットをクリックすると、全体を戻す／通った登録を残す、から一案を選ぶ。一度に両案を取得する選択肢は置かない。初期チケットや導入には方式名・概算を出さない。

一案を検討した後はplan-moreで、未検討のもう一案を選べる。概算も一回につき一案だけ。両方の処理案を先に検討した場合も、estimateで最初の一案、estimate-updateで残る一案を取得する。前のチケットを手動で完了に移していても、別案を調べられる。未検討・未見積もりの案は自動付与しない。

ドラッグで作業中に移す場合は従来通りポップアップなしで実行する。話題・検討対象はその時点で選べる最後の項目となる。明示的に選ぶ場合はチケットをクリックする。実行後は作業中に残り、完了への移動は手動。完了のクリックでは実行しない。

## 3. 証拠と報告

CSVの準備と範囲（csv-ready）、停止後の運用（operations）を揃えると業務まとめbusinessを得る。両方とも担当に確認した事実で、価格は増えない。

案を検討したうえで、単件の確定境界・通知を確認すればA案を概算できる。B案はさらに再送の観測が必要。価格カードa / bは提案・未検証とし、詳細設計・試験前の概算だと本文でも明記する。

3枚の報告はa・b・businessで比較を説明する。二案の価格だけなら担当の仕事を問い直し、Aだけなら真壁が開発都合への偏り、Bだけなら佐伯が費用に反応する。失敗報告で証拠や見積もりを自動付与せず、未消化チケットと追加検討を残す。

佐伯が概算の前提と二案を持ち帰れば終了。採用結果・全チケット消化・詳細設計の完了・真壁相談・失敗報告はクリア条件にしない。

## 4. 保存・ビルド・検証

保存キーはreport-drill.bulk-import.v1、内容版は2:2。旧版の状態は強引に移行せず、互換性の案内表示なしで新規開始できる。1・2章は別キー・従来版を維持する。

編集はMarkdown、生成はnode scripts/build-content.mjs。npm testで複数入口・片案からの復帰・自力比較・観測の区別・時間・延長・保存を検証する。node tests/browser.mjsで既存章と第3章、話題の選択、未読、再開、会議の通し操作を確認する。公開用へは検証後のsrcを反映する。
