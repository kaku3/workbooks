# キャラクター設定

『設計ブロックドリル』の[ストーリー原稿](../../../25_desgin-block-drill/docs/story/README.md)をもとに、『調査・報告ドリル』でも引き継ぐ人物像をまとめる。

## 登場人物と所属

自社は架空のSES会社「株式会社コウカンゲン」。主人公・折原・真壁が所属する。佐伯・三田は発注側の人物。

| 人物 | 所属 | 役割 | 設定 |
|---|---|---|---|
| あなた（主人公） | 自社側 | 未経験から現場へ送り込まれたエンジニア | [主人公](01_player.md) |
| 折原 | 自社側 | 営業。案件と追加依頼を持ち込む | [折原](02_orihara.md) |
| 真壁 | 自社側 | 先輩エンジニア。現場の技術対応を担う | [真壁](03_makabe.md) |
| 佐伯 | 発注側 | システムの依頼・問い合わせを伝える担当者 | [佐伯](04_saeki.md) |
| 三田 | 発注側 | 経理・経費精算の業務担当者 | [三田](05_mita.md) |

佐伯と三田の勤務先の社名、同一企業かどうか、正式な役職は原稿では確定していない。年齢・フルネーム・経歴なども、根拠のない設定を追加しない。

## 人物を描くときの共通方針

- 各人物は自分の都合で発言する。折原は案件を取りたい。真壁は自分の仕事を片づけて帰りたい。佐伯は業務を止めずに進めたい。三田は締め日までに正しく精算したい。主人公は無事に一日を終えたい。
- 全員が自分なりに合理的に動いた結果、全体としておかしな状況になる。誰か一人を悪役にして話を終わらせない。
- 会話は依頼の背景や人間関係を描く。教材の正解や調査手順を人物に読み上げさせない。
- 主人公の反応は疑問、心の声、沈黙でもよい。毎回ツッコミで締めない。
- 人物が無茶な依頼をしたことと、その依頼が業務上正しいことは分ける。人物の発言だけで問題の仕様を変更しない。
- 以下の各設定は原稿から読み取れる人物像と、報告ドリルでの会話方針を区別して記載する。

## 既存資料との整合

今回指定された所属を本フォルダの前提とする。[企画書](../00_企画.md)には「営業の佐伯」という記載があるが、自社の営業は折原、佐伯は発注側の担当者として扱う。

報告ドリルのシナリオでは、佐伯が発注側の社内依頼部署への返答を取り次ぐ。第1面は設計図の配布担当、第2面は経理、第3面は登録担当、第4面は締め作業の担当者からの相談として扱う。「顧客担当者」という独立した話者は置かず、佐伯にまとめる。

報告ドリルでも佐伯の話者IDは `client`、折原は `sales` とする。過去の原稿にあった佐伯の `sales` 表記は修正済み。保存キーとシーンIDは維持する。

元シナリオの話者IDは、主人公が `player`、折原が `sales`、真壁が `lead`、佐伯が `client`、三田が `accountant`。報告ドリルへの反映時は、既存データのIDだけで人物の所属を判断せず、人物名との対応を確認する。

## Web会議の背景

各人物の設定に「部屋の特徴（Web会議の背景）」を追記している。これは背景制作のために追加した美術設定であり、元原稿で確定している経歴・役職・所属先を増やすものではない。

| 人物 | 背景の基調 | 主な目印 |
|---|---|---|
| 主人公 | 簡素な開発作業席 | 淡い壁、低いパーティション、少ない備品 |
| 折原 | 明るい営業用打ち合わせスペース | ガラスの間仕切り、パンフレット棚 |
| 真壁 | 資料と道具のある開発作業席 | 技術書の棚、作業灯、ホワイトボード |
| 佐伯 | 整理された共用打ち合わせ室 | 木目、すりガラス、観葉植物 |
| 三田 | 書類を分類した経理・事務スペース | ファイル棚、書類トレー、プリンター |

背景は人物を含まない16:9の室内画像を基本とする。カメラは座った人の目線の高さとし、中央に頭・肩を置く余白を取る。人物の拡大や小窓への切り抜きを考慮し、目印は端に寄せすぎない。読める社名・個人情報・案件の答えは描き込まない。主人公と真壁は同じ現場の雰囲気を保ち、佐伯と三田については同一企業・同じ部屋と断定する意匠を加えない。

ゲーム内では佐伯を左の拡大表示に固定し、主人公と真壁を右の参加者欄に表示する。主人公のカメラがオフのときは背景も表示しない。
