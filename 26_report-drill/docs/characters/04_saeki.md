# 佐伯

## 基本設定

| 項目 | 設定 |
|---|---|
| 表示名 | 担当・佐伯 |
| 元シナリオの話者ID | `client` |
| 所属 | 発注側。自社の営業ではない |
| 立場 | システムの依頼や利用者からの問い合わせを開発側へ伝える担当者 |
| 主な登場案件 | 第1章の注文システム、第3章の社内ポータル |
| 当面の望み | 予定どおり業務を進め、問い合わせや苦情を収めること |

## 原稿から読み取れる人物像

悪意があるわけではなく、システム開発のことをよく知らない。早く商売を始めたい、困っている利用者へ対応したいという目線で動く。決済機能が動けばリリースし、その後にキャンセルや在庫の問題が見つかる。

開発側の内部事情より、業務が動くか、費用がかかるか、いつ直るかが気になる。リファクタリングには「動いているんだから問題ないんじゃないの？」と返し、試験のやり直しと費用を心配する。

セキュリティも技術的な原理より、事故の話題や関係各所の要求をきっかけに対応を求める。問い合わせが止まらないと総点検を求め、契約更新を考え直すことにも言及する。

## 話し方と反応

- 第1章では「早く直してよ！！！」「いま中に直せる？！」と、切迫感をそのまま出す。
- 第3章では「問い合わせが来ているんですけど」「対応お願いしますね」と、丁寧さを含めながら要求する。
- 「大丈夫なんでしょうか？」「安心して運用できるのよね？」と、開発側の確認結果を求める。
- 怒りだけで動かさず、費用への懸念、利用者への返答、周囲への説明といった事情を台詞に含める。

## 他の人物との関係

- 主人公：調査や修正、報告を求める開発側の担当者。経験不足の事情より、依頼への回答を必要としている。
- 折原：受注や契約に関わる自社側の営業。説明の認識違いが、そのまま依頼内容に入り込むことがある。
- 真壁：技術的な説明と対応方針を求める相手。技術の必要性と業務側の費用感がかみ合わないこともある。
- 三田：同じ発注側に属する業務担当者。原稿では両者の直接の会話や上下関係は確定していない。

## 報告ドリルでの会話方針

依頼や報告の窓口として、何ができるのか、何がまだ分からないのか、関係者へどう説明できるのかを求める。専門用語が並んでいても、自分の問いへの回答になっていなければ聞き返す。

佐伯を自社の営業として折原と同じ役回りにしない。依頼を取り次ぐ場面では、発注側の誰から来た要望なのかを明確にする。顧客への約束を扱う場合も、誰の顧客なのかを案件内で定める。

## 部屋の特徴（Web会議の背景）

発注側の共用打ち合わせ室。業務側の窓口として落ち着いて話せる、整理された会議室にする。佐伯専用の個室とは設定しない。

- 壁・家具：淡いベージュの壁、木目の腰壁、すりガラスの間仕切り。奥に会議テーブルの端と椅子が少し見える。
- 小物：端に背の高い観葉植物、低い収納棚、無地の資料ファイル。装飾や備品は少なめ。
- 色・光：暖かい木目と淡いグリーン。ブラインド越しの昼光と均一な室内照明で、顔を見やすくする。
- 構図：左側の拡大表示を前提に、中央の人物の背後は静かな壁面にする。植物とすりガラスを左右の端に置き、顔のアップに切り取っても部屋の特徴が残るようにする。
- 他の人物との描き分け：開発側の機材や技術書は置かず、対外的な説明や相談に使う部屋として整える。高級な社長室のようにはしない。
