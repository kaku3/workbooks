## 編集とビルド

`01_watermark.md` が編集の正本です。JSONは生成物なので直接編集しません。

`26_report-drill` ディレクトリで実行します。追加パッケージは不要です。

```sh
node scripts/build-content.mjs
node scripts/build-content.mjs --check
```

`--check` はファイルを変更せず原稿との一致を確認します。
同じフォルダのJSONと、アプリが読む `src/data/content.mjs` が生成されます。
Markdownの `##` はJSONのトップレベル項目に対応し、各節のJSONコードブロックを取り込みます。
会話は `### 会話ID (version 1)` の下に `- speaker: 台詞` を記述します。
心の声は `- player [thought]: 台詞` です。第2〜4面の草案は取り込みません。

## JSONの形式
UTF-8のJSON。コメントや末尾カンマは使わない。編集上の注記は必要に応じて `authorNotes` に書き、画面へ表示しない。

| 項目 | 内容 |
|---|---|
| `schemaVersion` | データ形式の版。今回1 |
| `caseId` | 問題原稿と一致する案件ID |
| `version` | 内容改訂の版。進行に影響する変更時に増やす |
| `status` | `prototype`。公開済み・実装済みを意味しない |
| `characters` | 登場人物のIDと表示名 |
| `scenes` | 会話IDをキーとする会話の辞書 |
| `scenes[ID].version` | 既読管理用の会話の版 |
| `scenes[ID].lines` | `speaker` と `text` を持つ発言の配列 |
| `kind: thought` | 主人公の心の声。省略時は通常発言 |
| `chat` | 投稿ID、時刻、発言者、本文の配列 |
| `schedules.lead` | 真壁の予定。`from` を含み `to` を含まない |
| `events` | 導入・完了・時間切れ・途中報告・未完了報告・延長・翌日・ゲームオーバーの会話ID。`dream` は旧保存との互換用で、新規進行では再生しない |

会話の本文を変えてもIDは維持する。同じIDの会話を再度読ませたい場合は会話の版を増やす。新しい会話は一意なIDを付け、問題側から参照する。

台詞はプレーンテキスト。HTMLやMarkdownの装飾を前提にしない。登場人物・時刻・並び順を変えたら、問題側の消費時間と予定の判定も見直す。

チャットは同時刻の投稿を許可し、同時刻内は配列順。予定は09:00〜17:00を隙間・重複なく覆う。チャットの投稿で知識・証拠品・フラグを直接増やさず、手がかりの描写に留める。

## 編集の考え方

- 佐伯は発注側の窓口として、業務上の困りごとと社内の依頼部署への返答を気にする。「顧客担当者」は独立した話者にせず、佐伯の台詞にまとめる。真壁は自社の先輩として自分の仕事も進める。
- 会話で正解カードを列挙しない。調査先のヒントは、その人物が自然に知り得る範囲で返す。
- 不十分な報告は、相手の問い返しで表現する。
- 再読・スキップで調査効果を再発生させない。台詞の表示とゲーム上の効果を分ける。
- 第2〜4面を正式化するときは、先に問題原稿の事実を固め、対応するJSONへ移す。
