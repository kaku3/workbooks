# 確認して、回答します。

第1面「ウォーターマークの誤表示」のブラウザ用プロトタイプです。三田が取引先提出用に印刷したPDF資料に、5年前に退職した田中太郎の透かしが入る障害を調べます。
Node.js 22以上を使用します。追加パッケージは不要です。

```sh
cd 26_report-drill
npm run build
npm start
```

ブラウザで **http://127.0.0.1:3026** を開いてください。停止はターミナルで `Ctrl+C`。
`src/index.html` はES Modulesを使用するため、HTTPサーバー経由で開きます。

## 遊び方

1. 「はじめる」で依頼を受ける。
2. 調査カードをクリック、または「作業中」へドラッグすると、確認ポップアップを挟まず開始する。カード上の所要時間を消費する。フォーカスしたカードは Alt＋左右矢印でも列を移動できる。
3. 効果が得られた調査はイベント終了後に「完了」へ、得られなかった調査は「未着手」へ戻る。ログとデバッガは成功後も未着手に戻り、繰り返し使える。同じ結果の報酬は重複しないが、再実行にも時間を使う。調査結果は「手がかり」と「履歴」で確認する。
4. 「報告する」で3枚を組み合わせ、事象・原因・影響と対応を一つの説明にする。提出ごとに10分を使い、主人公の説明と佐伯の反応が変わる。
5. 説明に必要な要素が成立すれば案件完了。期限内に途中報告していれば、未完了時に真壁が一日だけ延長を取りつける。途中報告がなければゲームオーバー。

会話は「次へ」で全文表示・次の台詞へ進みます。「会話をスキップ」は表示中の会話を飛ばします。
通常の会話・報告パートとも、メッセージウィンドウの高さは画面サイズごとに固定します。文字送りや台詞の長さ、報告成立の表示で枠を伸縮させず、長い文章は本文欄の中で縦スクロールできます。
会話中・調査後・報告後の状態は同じブラウザに自動保存します。イベントが終わると、結果と変化内容をチャットへ追加し、下からスライドして表示します。右下の変化ポップアップは使いません。「動きを減らす」設定ではスライドせず追加します。
タイトルの「つづきから」で再開できます。

履歴タブは設けず、右の「#pj-marunage」に調査・報告の記録と人物の投稿を日付・時刻順に表示します。消費時間はカードの背景に、知識や手がかりの増加はアイコンで表示します。列移動は表示せず、会話はその場で展開できます。古い履歴を読んでいる間は位置と展開状態を保ち、新しい履歴は未読として知らせます。翌日も前日の記録を残します。スマホは「#pj-marunage」から同じ記録を読めます。

知識・手がかりの増加と時間短縮は、対応するイベントの履歴カードに残します。イベント進行中の結果はまだ追加せず、その間に到達した人物の投稿もイベント終了時にまとめて表示します。読み込み直した過去の記録には新着演出を付けません。

報告画面の手がかりは本文3行のコンパクトなカードを横スクロールで選び、選択後もスクロール位置を維持します。長い文言は要点を保って短くし、会議の会話文字は通常20px、低い画面では18px、スマホでは16pxで表示します。

仕様書などの効果で調査の所要時間が短くなると、会話終了後に効果元から対象カードへ光の弾が飛び、着弾して「−25m」などの短縮量と新しい時間を表示します。列の中で隠れた対象は見える位置へ移します。未解放の対象は短縮のみを通知し、解放されたときに演出します。「動きを減らす」設定では、弾やカウントダウンを使わず短縮量を表示します。

調査カンバンに「昼休憩（1h）」「真壁に途中報告（30m）」を用意しています。途中報告は手がかりがそろっていなくても実行でき、期限切れ時の延長条件になります。途中報告なしで期限になると真壁に説教され、ゲームオーバーです。報告画面の途中経過・できません報告ボタンはありません。
12:00をまたぐと、未着手の昼休憩を列の先頭へ移し、未着手列も先頭へスクロールします。その後の時間経過では、ユーザーが選んだスクロール位置を保ちます。

業務時間は9:00〜18:00で、昼休憩1時間を含む実働8時間です。残り時間より長いタスクや報告も開始できますが、終了予定が18:00を超える場合は時計を18:00に進め、結果を取得する前に時間切れイベントへ移ります。途中報告の有無による延長・ゲームオーバーの分岐は同じです。終了がちょうど18:00の報告は成立すれば完了になります。

調査画面では実時間5分でゲーム内1時間が経過し、カード・提出の所要時間も別途消費します。報告パートは手がかりの選択中もイベント扱いとし、会話・会議接続・ダイアログ中と同様に実時間による進行を止めます。報告を提出したときの10分は消費します。時計の「:」はタイマー稼働中だけ明滅します。画面を閉じていた間の時間は加算しません。

延長時は、手がかり・知識・調査状況・報告の進み具合と履歴を保って翌日9:00に再開します。翌日専用の会話だけを再生し、夢や初日の導入は繰り返しません。延長は一日だけで、2日目も未完了ならゲームオーバーです。「はじめからやり直す」は1日目から新しい試行を開始します。

「仕様書を読む」から画面仕様書・外部設計書・詳細設計書が分岐し、対応するソースを読む時間を短縮します。「ソースを解析する」は1hでバックエンド・フロントエンド・共通処理へ分岐します。PDF生成処理はバックエンド調査後にだけ表示します。ログとデバッガは事前の現物確認や経路の絞り込みで結果が変わります。分岐図と報告の対応は[案件設計](docs/problems/01_pdf-incident-design.md)を参照してください。

第1面を障害調査へ改稿したため、以前の機能追加シナリオとは保存を分離しています。既存の保存は上書きせず、新シナリオは初日から開始します。

## 原稿の編集

- `docs/scenarios/01_watermark.md`：人物、会話、投稿、対応予定
- `docs/problems/01_watermark.md`：調査、証拠品、報告条件、数値

Markdownを編集して `npm run build` を実行すると、同じフォルダのJSONと `src/data/content.mjs` が更新されます。
JSONと実行データは生成物です。直接編集せず、原稿へ変更を戻してください。
`src` だけを静的HTTPサーバーで配信できます。公開用ファイルは [`docs/report-drill`](../docs/report-drill/index.html) に配置しています。原稿のビルド後に `src` の内容を同フォルダへコピーすると更新できます。

手がかりは調査・報告で共用する画面下部のデッキに表示し、新しく入手したカードを左端に追加します。右端の小・中・大アイコンで、カードの頭だけ／従来の展開サイズ／タブ内全画面を切り替えます。大表示はカードを折り返して並べ、横スクロールを使いません。ドラッグ、またはカードにフォーカスして Alt＋左右矢印で並べ替えられ、順序は保存します。報告は上部タブから会議に参加して実行し、途中報告は調査カードから実行します。履歴カードは増加アイコンを左下に縦積みし、消費時間を右上の背景に表示します。

手がかり入手時はイベント終了後にカードを画面中央で強調します。デッキの既存カードが右へずれて空きを作った後、新しいカードがサイズを保ったまま左端へ移動して収納されます。入手前の空白は作らず、複数枚は1枚ずつ同じ順序で挿入します。動きを減らす設定では移動を省いてフェード表示に切り替え、演出によるゲーム内の時間消費はありません。

報告は説明要素ごとの成立条件で判定し、説明にならない／調査は伝わる／事象は伝わる／回答として成立の4段階の会話になります。佐伯は技術的な採点をせず、担当者に説明できるかを返答します。成功時は主人公が根拠をつなげて説明します。報告画面は会話ウィンドウと佐伯の立ち絵を土台に、上に選択枠・操作、下に共用の手がかりデッキを配置します。以前の3問形式のセーブは、調査結果を残して新しい報告形式へ移行します。

手がかりは短い見出しと要点だけを表示し、情報源欄は省きます。報告画面は青系の背景に切り替わり、会議接続後はデッキを常時表示します。大きな立ち絵を左側からデッキの上に載せ、半透明の会話欄をデッキ直上に配置します。

報告の選択枠はデッキと同じ寸法のカードを表示します。ドラッグで配置し、選択枠同士で交換、デッキへ戻して解除できます。共有画面の右側に「報告する」「10m」を上下に表示する四角いボタンを置きます。クリックでも選択・解除できます。

不成立の報告は、選択したカードを残して報告画面へ戻ります。期限に達した場合は従来どおり終了・延長の判定に進みます。成立時は佐伯が理解した内容を自分の言葉で返し、「回答が伝わった」の表示から完了画面へ進みます。結果画面の記録表示は省きます。

手がかりのカードと件数は、中央の入手演出から収納された時点で表示します。チャットはチャンネル見出しを1行にし、日次見出しと下部メッセージを省きます。コーヒーは左側のSTATUS欄の下から実行します。

入手演出は拡大・ブラーから等倍へ収束し、カード下に「手がかりを入手」を大きくタイプライター表示します。文字を消してから既存カードの移動を開始し、左端の空きができてから新しいカードを着地させます。

報告画面はWeb会議を模し、左にオフィス背景と顔アップのカメラ映像、右に画面共有枠を配置します。依頼文は「PDF印刷のウォーターマークの件／現象、影響範囲、対策の報告をお願いします。」とし、デッキ直上の会話欄でタイプライター表示します。カード操作で再描画しても表示済みの文字は維持し、全文表示・動きを減らす設定にも従います。

上部の［調査カンバン - Backlog］［報告 - Meets］はブラウザ風のタブです。左の依頼欄は DESCRIPTION と表示し、見出しは省きます。報告タブ中央の「会議に参加する」を押すと、薄いグレー背景の上寄りに濃いグレーで「会議が開始すると 誰かが入室を許可します」を表示し、相手の映像 → 依頼セリフ → 自動画面共有の順に進みます。右下ではマイク、カメラ、共有、リアクション、挙手を操作できます。初期状態はマイクオン・カメラオフで、共有はセリフ後にオンになります。

接続後は手がかりデッキを常時表示し、その上に独立した映像・共有画面・メッセージのウィンドウを並べます。自分のウィンドウは右側に常設し、カメラオフ時は人物アイコンになります。メッセージ欄は会議エリアの横幅全体を使い、1行分高くします。会議操作アイコンは共有画面の下部中央に配置し、共有をオフにしても操作できます。右の参加者欄は背景色や縦線を付けずに表示します。解答ボタンは共有エリア内に配置します。共有の切り替えでは各ウィンドウの位置とサイズをアニメーションし、動きを減らす設定では即時に切り替えます。

入室待ち表示は手がかりデッキより上の会議エリア内に限定し、文言を領域の上から20％付近に表示します。デッキは会議参加前・接続中も常時表示し、会議とは別アプリの見出し・枠として区切ります。中表示の高さは通常234px、低い画面・スマホでは218pxです。報告画面では中表示に固定し、サイズ切替は表示しません。

手がかりデッキのタイトルは「調査.xlsx」で、背景は表計算の方眼紙風です。報告ボタンは右端に実際の消費時間を表示し、カメラオフは1人の人物アイコン、挙手中は小さなラベルで表示します。

右側の自分の映像欄は幅を広げます。共有オフ時は佐伯の映像を会議エリア全体の背面へ置き、他のウィンドウを重ねます。左のSTATUS欄は背景を明るくし、補足文を省きます。

会議アイコンは個別の背景を持ち、操作エリア全体の背景枠は省きます。挙手は自分のカメラ内に表示し、リアクションは会議エリア左下から上へ流れて消えます。

共有エリアは紫の見出しと罫線を持つノート風です。「報告する」は共有エリアの右側に配置します。報告後の会話は会議内のメッセージ欄で継続し、左側の拡大表示は佐伯に固定し、右側に主人公と真壁を常時表示します。「回答が伝わった」のアニメーションは同じ報告につき1回だけです。

## 検証

```sh
npm test
node scripts/build-content.mjs --check
npm run test:browser
```

ブラウザ検証はWindowsのMicrosoft Edgeをheadlessで使用します。
別の配置の場合は `EDGE_PATH` で実行ファイルを指定してください。
スクリーンショットは `tests/artifacts/` に出力します。

第2〜4面、実際のAI通信・チャット連携は未実装です。会話の人物画像は `25_desgin-block-drill/src/assets` の素材を `src/assets` に複製して使用しています。固有の人物画像がない話者はアイコンで表示します。
