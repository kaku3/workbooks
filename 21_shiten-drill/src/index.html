WRITING PRACTICE FOR SPEC DOCS

視点ドリル

新人・若手エンジニア向け。仕様書で迷いがちな「システム目線」と「ユーザー目線」の書き分けを学ぶ20問の演習です。

意外と教えてもらえない「視点・目線」

このドリルは、仕様書を書き始めた人が「何を書けば伝わるのか」を素早く掴むためのものです。

実装者に伝えるべき文と、利用者体験を説明する文が混ざると、レビューで「主語がぶれる」「読み手が迷う」状態になります。

そこで使うのが「システム目線」と「ユーザー目線」の2軸です。

どちらで書くべき文かを切り分けるだけで、仕様の伝達精度は大きく上がります。

目線書き換え問題、分類問題を通じて、実務でそのまま使える書き分けの考え方を身につけましょう。

問題

目線の考え方

  • 主語チェック：「システムは」「処理は」が主語ならシステム目線。「ユーザーは」「画面には」ならユーザー目線。
  • 誰が読むか：実装者・テストが読む機能仕様のコアはシステム目線。UI仕様や受け入れ基準はユーザー目線。
  • 非機能要件：性能・セキュリティなど見えない制約は、無理にユーザー目線へ翻訳しない。
  • 受け入れ条件：「ユーザーが何をしたら何が起きるべきか」から書き、内部処理はシステム目線で紐づける。

学習の進め方

問題一覧または右側のPROGRESSから問題を選んで、モーダルで解答。

モーダル内で「前の問題 / 次の問題」に進みながら、連続して学習してください。
