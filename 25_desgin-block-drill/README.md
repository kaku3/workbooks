# 設計ブロックドリル

組み立てて、動かして、設計のつながりを考えるブラウザ教材。外部ライブラリ・ビルド・バックエンドは不要です。

## 起動

VS Code の Live Server で `src/index.html` を開いてください。JavaScript モジュールを使用するため、ファイルの直接起動ではなくHTTPサーバー経由で開きます。

URLの指定なしではタイトル画面を表示します。「はじめから」で第1章の会話から開始し、「つづきから」で再開できます。はじめから遊び直してもクリア済み記録は消しません。

ストーリーは第1章「注文システム」、第2章「経費精算・承認」、第3章「認証・セッション・権限」の全12ステージです。各章は初級→中級→上級→総合。第1章は配置固定、第2章ではブロックの配置・移動とパレットを解放します。全ケース一括検証の全成功でクリアし、結果演出後に会話と次ステージへの導線を表示します。

タイトルの自由演習は第1章を最初から表示し、第2・3章はそれぞれ自身の章のストーリー総合クリアで表示します。従来の `?drill=ID` 直リンクは開発・自由演習用として維持しています。自由演習ではストーリーの進捗は変わりません。

## 試し方

1. 出題欄で問題を選択し、「全ケースを検証」で初期設計の失敗を確認します。
2. ケースを選んでStep／Playし、ログと状態変化から原因を調べます。
3. 接続・操作カード・処理順序を修正し、もう一度全ケースを検証します。

総合問題の初期設計は7件中1件だけが成功します。従来の通知修正に加え、通常注文の接続とキャンセル後処理の順序にも修正が必要です。

「全ケースを検証」は一覧を縮小し、過去の結果を消して先頭から順に再生します。速度を変更でき、Pause／Playで中断・再開できます。完了後は成功件数とExcellent／Almost!／Try Againを全画面表示します。

`?mode=story&drill=order-basics` はストーリーモード。未解放のステージ指定は解放済みステージへ案内します。編集保存は問題別、ストーリー進捗は別キーです。出題調整方針と作者向け修正例は `docs/drill/`、会話は `docs/story/` にまとめています。

カードの前提条件は編集欄の(?)で確認できます。カードを追加・削除・並べ替えでき、成功・失敗の接続先も選択できます。ブロックの移動・新規配置は第2章から利用できます。パレットのクリック配置も使えます。設計はブラウザに自動保存されます。「Reset」は実行状態、「初期設計に戻す」は設計をリセットします。

キャンバスはアクション名だけの1行ブロックで全体を表示します。実行コントロールはキャンバス左上にフローティング表示し、ブロック選択時の編集欄はキャンバス左側へスライド表示します。編集欄を開いた時だけ幅を確保し、×で閉じるとキャンバスがその分まで広がります。荷物・共有状態はキャンバス下部に配置し、各項目も横並びで表示します。テストをクリックするとページ右端に試験パネルが重なって開き、キャンバス幅を変えずに概要・観点・各項目の期待値と現在値を確認できます。実行途中の○×は仮判定として毎ステップ更新されます。同じケースの再クリックは実行をリセットしません。UI方針は `docs/20_UI.md` に記載しています。

## 実装構成

- `src/data.mjs`：初期グラフ・7テスト・期待値。
- `src/drills.mjs`：問題別の初期欠陥・難易度・使用テスト。
- `src/engine.mjs`：UI非依存の状態遷移・FIFO実行・差分ログ・判定。
- `src/approval.mjs`・`approval-drills.mjs`：承認操作・第2章24ケース。
- `src/story.mjs`・`story-ui.mjs`：進捗・章解放・タイトル・会話。
- `src/story-data.mjs`：会話原稿から生成した16イベント。
- `src/app.mjs`：問題選択、編集、再生、状態表示、問題別の自動保存。
- `tests/drills.mjs`：全問題の初期失敗と修正後の成功を検証。
- `tests/approval.mjs`・`tests/story.mjs`：承認の版・権限・再実行と、ストーリー進行を検証。
- `tests/browser-story.mjs`：タイトルから開始・クリア・次へ、配置・保存・会話既読をブラウザで検証。
- `tests/engine.mjs`：エンジン回帰テスト（`node 25_desgin-block-drill/tests/engine.mjs`）。
- `tests/browser-smoke.mjs`：Windows上のEdgeで画面操作を検証（`node 25_desgin-block-drill/tests/browser-smoke.mjs`）。外部パッケージは不要です。Edgeの場所が異なる場合は `EDGE_PATH` 環境変数で指定できます。

## 初期版の実行規則

- 入力イベントは開始時にすべてキューへ投入し、投入順に1荷物ずつ完了まで処理します。共有在庫はケース内で共有し、ケース間では完全にリセットします。
- 1ステップは1荷物の1操作。操作成功時のみ状態差分を適用します。途中失敗前の変更は自動ロールバックしません。
- 操作失敗時は残りの操作を飛ばし、失敗の接続先へ進みます。`no_op` は通常成功と同じですが、処理済みキャンセルの受付はイベントを正常終了します。
- 「正常終了」と「未接続」は別です。未接続・空の操作列は停止となり、判定で検出されます。最大200ステップで停止します。
- `wait` は現在位置に残り、後続イベントも待ちます。Play は待機で一時停止し、Step／Playで再評価できます。外部からの非同期状態更新は初期版に含めません。
- 出荷指示の作成を出荷確定点とし、以降の取消を拒否します。TC-07は出荷先行の固定順序です。
- 通知は前提条件を自動補完しません。失敗経路を終了へ変更する修正と、通知前に成功確認を追加する修正の両方を判定できます。
- 実行中にカードや接続を編集すると実行・判定結果をリセットします。位置の移動は設計の意味を変えないため実行状態を保持します。

外部メール・実決済・厳密な並列競合は対象外です。

会話を変更したら `node 25_desgin-block-drill/scripts/build-story.mjs` で原稿からデータを再生成します。開発元は `src/` で、今回の実装は既存の動作確認用 `docs/tmp/` にも同期しています。ホスティングへのデプロイは行っていません。
