# 上級：ログインできたら管理者？

状態：実装済み。ID `security-session`／03-03。[共通仕様](03-00_security-rules.md)。

## 出題

管理機能にセッションIDが渡ると、そのまま処理が実行されてしまいます。セッションが今も有効で本人のものか、本人に管理権限があるかを別々に確認してください。ログアウトしたセッションも使えないようにします。

ログインを再設計する問題ではない。有効な認証を済ませたセッションを初期状態として与える。管理受付はログイン受付とは別の入力口。

## 初期配置と処理

| ブロック | 登録処理 | 成功先 | 失敗先 |
|---|---|---|---|
| 管理受付 | 監査を記録 | 管理処理 | 完了 |
| 管理処理 | 管理処理を実行 | 完了 | 完了 |
| ログアウト受付 | 監査を記録 | 完了 | 完了 |

未配置：「セッション確認」（セッションを確認）、「管理権限確認」（管理権限を確認）、「セッション失効」（セッションを失効）、「ログイン照合」（パスワードを確認、追加認証を確認）。最後の候補は本問の入力に対応せず、管理受付で認証入力をやり直す必要がないことを考えるための不要候補。利用可能処理もこれらに限定。

## テスト

特記しない時刻は10、有効期限100。セッションは初期状態で存在し、発行合計は0。管理処理の件数は全入力の合計。不正な管理処理合計0・全入力正常終了は全ケース共通。

| ID | ケース名 | 初期状態・入力順 | 終了時の期待 |
|---|---|---|---|
| SS-01 | 管理機能の利用権限 | A-01/adminの有効なS-A → A-01が管理受付 | 管理処理合計1、S-Aは有効のまま |
| SS-02 | 一般会員の利用権限 | U-01/memberの有効なS-U → U-01が管理受付 | 管理処理合計0、S-Uは有効のまま |
| SS-03 | ログアウト後の利用 | A-01の有効なS-A → ログアウト受付 → 同じS-Aで管理受付 | S-Aは失効、失効合計1、管理処理合計0 |
| SS-04 | セッションの有効期限 | A-01のactiveなS-A、期限10 → 時刻10で管理受付 | 管理処理合計0。期限切れを拒否するだけでactiveの書換えは不要 |
| SS-05 | セッションと本人の一致 | U-02の有効なS-U2 → A-01がS-U2で管理受付 | 管理処理合計0、S-U2の所有者・状態は維持 |

観点には、SS-02は「管理権限確認」、SS-03・04・05は「セッション確認」が対応することを記載する。SS-03のログアウトは「セッション失効」を実行して状態を変える。SS-05は管理権限があっても他人のセッションを使えないことを確認する。

## 作者向け修正例

管理受付 → セッション確認 → 管理権限確認 → 管理処理。確認失敗は終了。ログアウト受付 → セッション失効 → 完了。ログアウトでは所有者一致を失効処理自身が検証するため、期限切れでも本人のセッションは失効可能。

初期設計はSS-01だけ成功、残りは不正実行または失効不足で失敗。一般会員を失効させて強引に通す解は、セッション維持の期待値で検出する。
