# 出題の調整方針

初期設計でほとんどのケースが通ってしまう状態を改め、通常系・失敗系・後処理の間で複数の修正を必要とする出題にする。初期状態や期待値を不自然に変えず、操作カードと接続の欠陥から失敗を発生させる。

## 共通方針

ケース名は「何を確認する試験か」を示す短い観点名にする。不具合の断定や期待結果そのものをケース名にせず、概要に入力状況と期待動作、観点に対応するブロック・操作の役割を記載する。同じケースを複数ステージで使う場合は名前を統一する。

| ケースID | 表示名 |
|---|---|
| TC-01 | 注文時の決済・出荷 |
| TC-02 | 在庫不足時の処理 |
| TC-03 | 後処理失敗時の通知 |
| TC-04 | キャンセル時の後処理 |
| TC-05 | キャンセルの再受付 |
| TC-06 | 複数注文の在庫確保 |
| TC-07 | 出荷後のキャンセル |
| AP-01 / AR-01 | 承認後の経理確認・振込 |
| AP-02 / AR-04 | 上長却下時の処理 |
| AR-02 | 領収書不備時の差戻し |
| AR-03（総合のみ） | 上長差戻し時の処理 |
| AT-01 | 経理受付と振込 |
| AT-02 | 経理受付の再実行 |
| AT-03 | 再申請時の上長判断 |
| AT-04 | 再申請後の承認・振込 |
| AT-05 | 承認版の整合性 |
| AS-01 | 一般社員の承認権限 |
| AS-02 | 申請者本人の承認権限 |

- 必要な業務ルールは出題欄と各ケースの概要・観点に公開する。
- 初期設計を一括検証して、不具合を観察してから修正できる。
- 初級は接続の依存関係、中級は操作順序と失敗経路、上級は複数ケースにまたがる整合性を扱う。
- 正解の接続形状は固定しない。終了状態と副作用で判定する。
- 問題別に設計を保存し、他の問題の編集が混ざらないようにする。旧版の保存データは引き継がず、今回の初期設計から開始する。
- 「設計のヒント」欄は廃止する。原因はテスト結果・荷物の状態・操作ログ・前提条件から追う。

| ID | 難易度 | 内容 | テスト |
|---|---|---|---|
| `order-system` | 総合（既存を改訂） | 接続・後処理順序・誤通知 | TC-01〜07 |
| `order-basics` | 初級（追加） | 決済を飛ばす注文フロー | TC-01・02 |
| `cancel-consistency` | 中級（追加） | 後処理と完了通知 | TC-03〜05 |
| `shared-stock` | 上級（追加） | 共有在庫と出荷の確定点 | TC-01〜07 |

`src/index.html?drill=order-basics` のようにIDを指定する。指定なしは総合問題。不明なIDは案内を出して総合問題へフォールバックする。出題欄の問題選択からも切替可能。

各ファイルの修正例は問題作者向け。画面に正解として自動表示しない。

## 実装・レビュー時の確認

- 第1章の4問は初級→中級→上級→総合のまま。ドラッグなしでもカード・接続の編集で全問修正可能。
- 第2章の初級はケース2件・候補1個へ戻し、新規配置を一度に覚えさせすぎない。
- 各出題の初期設計・修正例を実行テストにし、初期の不合格と修正後の全合格を確認済み。第2章は初級0/2、中級1/4、上級0/5、総合3/13が初期の成功数。修正後は全24ケースが成功する。
- ブロック全体の成功／失敗分岐だけで解けるようにする。カードごとの遷移先や自動ロールバックは要求しない。
- パレットを使わず既存ブロックへ同等の操作を置く別解も認める。配置の学習を唯一の正解図への一致判定にしない。
