# 総合：認証・権限の総合点検

状態：実装済み。ID `security-system`／03-04。[共通仕様](03-00_security-rules.md)。

## 出題

ログイン、失敗回数、管理機能、ログアウトが別々に修正され、接続時に確認が抜けています。入力の種類ごとに必要な確認を行い、別入力や別ユーザーの認証結果を使い回さないようにしてください。

## 初期配置

中級の配置を基に、次の欠陥を加える。

- ログイン受付 → パスワード確認 → セッション発行。追加認証確認は配置済みだが未接続。
- パスワード確認の失敗 → 失敗回数記録 → ロック判定。
- セッション発行 → 完了。成功後リセットは未配置。
- 管理受付 → 管理権限確認 → 管理処理。セッション確認は未配置。
- ログアウト受付 → 完了。セッション失効は未配置。

未配置：ロック状態確認、成功後リセット、セッション確認、セッション失効、監査記録。全共通処理を利用可。各開始ブロックに監査処理を1つ持たせるが、監査の追加や配置自体を合格条件にはしない。

## テスト

SL-01〜03、SK-01〜05、SS-01〜05を独立した初期状態で再実行する。ケースの名前・入力・期待値は前3問と同一。計13ケースに、次の2ケースを追加して15ケースとする。すべて全入力終了時の期待値で、全入力正常終了が共通条件。

| ID | ケース名 | 初期状態・入力順 | 終了時の期待 |
|---|---|---|---|
| SX-01 | 別ユーザーの認証結果 | U-01/memberとA-01/admin、未ロック、セッションなし → U-01が両照合一致でS-Uへログイン → A-01がパスワード一致・追加認証不一致でS-Aへログイン → A-01がS-Aで管理受付 | 発行合計1、不正発行0、S-Uのみ存在。U-01の失敗0、A-01の失敗1。管理処理合計0、不正実行0 |
| SX-02 | 再ログイン時のセッション | A-01/admin、失敗2、セッションなし → 両照合一致でS-OLDへログイン → S-OLDでログアウト → 両照合一致で同じS-OLDへの発行を要求 → S-OLDで管理受付 | 正しい発行合計1、不正発行0、失効合計1。3入力目はID衝突で終了し、S-OLDを再有効化しない。失敗回数0・未ロック維持。管理処理合計0、不正実行0 |

SX-01は照合済みフラグをユーザーやセッションの全体変数に保持して使い回す実装を検出する。SX-02は発行失敗を照合失敗として加算したり、既存の失効セッションを再利用してしまう実装を検出する。

## 作者向け修正例

ログインの経路は中級、管理受付・ログアウトの経路は上級と同じ。追加認証の失敗も失敗回数記録へ接続する。管理権限だけでセッションを代替せず、毎回セッション確認を行う。セッション発行の失敗先は終了し、失敗回数記録に合流しない。

## 実装時の追加検証

- SK-05・SX-01は入力ごとの状態履歴でも判定し、最終回数の帳尻合わせを検出する。
- 発行・管理処理が一度でも不正に発生したら不合格。後からセッションを消して救済しない。
- SX-02のID衝突はゲーム内ルール。新しいIDで正常にログインできる機能が壊れていないことは、初級・中級ケースで併せて確認する。
- 矩形移動・ブロックの戻し・結果保持・全件検証・項目フィルタ・ログカードの入力番号を第3章の状態でも確認する。
