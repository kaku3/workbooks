# 中級：後処理と完了通知

ID：`cancel-consistency`

ストーリー：第1章01-02。開始・クリア会話は [第1章原稿](../story/01_order.md)。配置は固定（ドラッグなし）、カードと接続の編集は可。初期設計・テストは既存実装を維持する。

## 狙い・初期の欠陥

キャンセル系4ブロックに絞る。後処理がキャンセル確定→引当解除→返金の順になっており、失敗経路も完了通知へ流れる。受付は「キャンセル要求を記録」を使い、成功済みの要求も要求中へ上書きする。初期状態は3ケースすべて失敗する。

## 修正例と確認

引当解除→返金→キャンセル確定の順にし、キャンセル失敗から通知へ進まないよう接続を直すか、通知前の成功確認を追加する。これだけでは二重要求の2回目に引当解除が失敗し、取消状態が失敗へ変わるため、TC-05は通らない。

受付の「キャンセル要求を記録」を、処理済みなら変更なしで終了する「キャンセル要求」へ置き換える。TC-03・04だけでなくTC-05も通ることを確認する。操作一覧の前提条件で両者の違いを公開し、エンジンが二重要求を無条件に救済しない構成にする。
