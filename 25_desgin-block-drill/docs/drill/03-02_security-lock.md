# 中級：止まらないログイン試行

状態：実装済み。ID `security-lock`／03-02。[共通仕様](03-00_security-rules.md)。

## 出題

ログインに失敗しても回数が記録されず、何度でも試せてしまいます。連続失敗3回でロックし、ロック後はログインできないようにしてください。正しくログインできたときだけ、連続失敗回数を0へ戻します。

3回目の失敗も、その入力の処理中にロックまで行う。4回目が来てからロックする設計は不可。追加認証の不一致も失敗1回と数える。

## 初期配置と処理

初級の正しい照合経路から開始する。

| ブロック | 登録処理 | 成功先 | 失敗先 |
|---|---|---|---|
| ログイン受付 | 監査を記録 | パスワード確認 | 完了 |
| パスワード確認 | パスワードを確認 | 追加認証確認 | 完了 |
| 追加認証確認 | 追加認証を確認 | セッション発行 | 完了 |
| セッション発行 | セッションを発行 | 完了 | 完了 |
| 失敗回数記録 | 失敗回数を記録 | 完了 | 完了 |
| ロック判定 | 失敗回数を確認、アカウントをロック | 完了 | 完了 |

失敗回数記録とロック判定は配置済みだが接続されていない。未配置は「ロック状態確認」（ロック状態を確認）、「成功後リセット」（失敗回数をリセット）。利用可能処理は上記の処理。監査追加を含む別解は許容する。

## テスト

ユーザーU-01。時刻は全入力10、発行期限100。発行先IDは入力ごとに異なる未使用ID。特記しない場合、照合はパスワード・追加認証とも一致。全ケースで不正発行合計0・全入力正常終了を期待する。

| ID | ケース名 | 初期状態・入力順 | 終了時の期待 |
|---|---|---|---|
| SK-01 | ログイン失敗の記録 | 失敗0・未ロック → パスワード不一致1回 | 失敗1・未ロック、発行合計0 |
| SK-02 | 失敗回数とロック | 失敗2・未ロック → 追加認証不一致1回 | 失敗3・ロック済み、発行合計0 |
| SK-03 | ロック後のログイン | 失敗3・ロック済み → 両方一致1回 | 失敗3・ロック維持、発行合計0 |
| SK-04 | ログイン成功時の回数 | 失敗2・未ロック → 両方一致1回 | 失敗0・未ロック、有効発行合計1 |
| SK-05 | 複数入力の失敗回数 | 失敗0 → パスワード不一致 → 追加認証不一致 → 両方不一致 → 両方一致 | 失敗3・ロック済み、発行合計0 |

SK-05は4入力の合計。3入力目で両照合が不一致でも失敗加算は1回、4入力目はロックのため加算も発行も0。最終状態だけでなく、入力ごとの失敗回数とロック発生時点を確認する。

## 作者向け修正例

- ログイン受付 → ロック状態確認 → パスワード確認 → 追加認証確認 → セッション発行 → 成功後リセット。
- ロック状態確認の失敗は終了。パスワード確認・追加認証確認の失敗は失敗回数記録 → ロック判定。
- ロック判定は3未満なら最初の処理で失敗して終了、3以上ならロックを実行して終了。
- 発行失敗をログイン照合失敗と混同せず、終了する。未ロックでもセッションID衝突などは別原因。

初期設計ではSK-01・02・04・05が失敗する。SK-03は照合処理自身にもロック条件があるため通るが、ログイン受付の直後で止める役割を説明できるようにする。
