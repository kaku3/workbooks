# 設計ブロックドリル — タイトル画面・モード構成仕様案

> Codex 引き継ぎ用。既存のゲームエンジンと問題データを活かし、まずはタイトル画面とモード導線を実装する。ストーリー本文・後続章は段階的に追加する。

## 1. 方針

- **タイトルは当面「設計ブロックドリル」を維持する。** 最終的に身につけたい「設計」を表すシリーズ名として使う。
- **メインコピー：**「つないで、動かして、バグを見つける。」
- タイトル画面では「何をするゲームか」を明確に。株式会社コウカンゲンの茶番はストーリー内に短く挟む。
- 教材・シミュレーション部分は真面目に、物語は軽くしょうもないコメディにする。
- Workbooks 共通のノート／付箋風デザインに合わせる。スマホでも使いやすく。

## 2. タイトル画面の構成

```text
WORKBOOKS / DESIGN GAME

       設計ブロックドリル
  つないで、動かして、バグを見つける。

┌──────────────────────────┐
│ ストーリーモード          │
│ 株式会社コウカンゲンへようこそ。│
│ 今日からあなたもエンジニアです。│
│                          │
│ [ つづきから ]            │
│ [ はじめから ]            │
└──────────────────────────┘

┌──────────────────────────┐
│ ドリルモード              │
│ クリアした案件を自由に練習。│
│                          │
│ 第1章 注文システム        │
│ 第2章 ????? ・4ステージ 🔒│
│ 第3章 ????? ・4ステージ 🔒│
│ 第4章 ????? ・4ステージ 🔒│
└──────────────────────────┘

進捗はこのブラウザ内に保存されます
```

※ 上記の章数・各章4ステージは構成例。実際の問題定義に従って表示する。存在しない章を実装済みのように見せない。

## 3. ストーリーモード

### つづきから
- 保存済みの進捗がある場合、未クリアの次のステージ／イベントから再開。
- 未プレイの場合は「はじめから」を主ボタンにし、「つづきから」は非表示または無効化。
- ステージの途中経過を保存しない場合は、該当ステージの冒頭から再開する仕様でよい。

### はじめから
- 第1章の冒頭イベントから再生。
- **クリア済み記録やドリルモードの解放状態を消さない。** ストーリーの再視聴とデータ初期化を分離する。
- 既存進捗がある場合も、冒頭から遊び直せる。

### ストーリーイベント
- 各章の開始時、各ステージのクリア後、章クリア時などに短い会話を表示する。
- スキップ可能。再プレイ時にも強制的に長い会話を読ませない。
- 問題の目的と次の依頼が自然につながる内容にする。
- 既存の **初級 → 中級 → 上級 → 総合** を維持する。章が変わると難易度は再び初級から上がる。

## 4. ドリルモード

- **第1章は最初から利用可能。** 初級・中級・上級・総合を直接選択できる。
- 第2章以降は未解放なら章名・案件名を `?????` とし、**ステージ数だけ**表示。内容やネタバレは伏せる。
- **章の総合ステージをストーリーモードでクリアすると、その章のドリルモードを解放する。**
- 解放済みの章では、各ステージをストーリーなしで自由に再挑戦できる。
- 未実装の章は、解放条件を満たしても実行できない。実装状況と解放状況を別に管理する。
- ドリルで解いてもストーリー進捗を勝手に進めない。

## 5. 章の進行と操作の段階的解放

| 段階 | 主な操作 | 学習上の焦点 |
|---|---|---|
| 第1章：注文システム | **ドラッグなし**。既に配置されたブロックの接続・条件を修正 | 流れ・分岐・状態の理解 |
| 第2章：承認ワークフロー | 未配置のブロックを選んで追加・配置 | 必要な処理の発見と配置 |
| 第3章：認証・セキュリティ | 不要なブロックも混ざる | 取捨選択・権限・条件 |
| 後続章 | より多くのブロックや複雑な構造を扱う | 全体設計・依存関係・安全性 |

- 章が変わると**問題の難易度は下がるが、既に解放した操作は維持**する。
- 後半ほど未配置のブロックが増える。初期から全操作を見せて圧倒しない。
- ドラッグ操作を導入する章では、操作説明を短く追加する。

## 6. 進捗保存

- ログイン不要。`localStorage` に保存。
- ストーリーの現在位置、章・ステージのクリア状態、ドリルモードの解放状態を区別する。
- 「はじめから」では記録を消さない。
- 将来データ初期化機能を作るなら、別途明示的な確認付き操作にする。
- 既存の進捗データがあれば、互換性を考慮して移行・読み込みする。

## 7. 実装上の注意

1. 既存の問題エンジン、Play／Pause／Step、ログ、テストケース検証を壊さない。
2. タイトル画面はルーティング／画面状態として追加し、ストーリー・ドリルの両方から既存ステージを起動する。
3. 章一覧は可能な限り問題定義のメタデータから生成し、章数・問題数のハードコードを避ける。
4. 進捗と解放判定を一箇所にまとめ、表示と実行可否で食い違わないようにする。
5. まず第1章の導線を完成させ、未実装章はプレースホルダーとして扱う。
6. ストーリーの茶番は短く、教材の説明と混ぜすぎない。

## 8. 今後のタイトル・コピーの扱い

- 正式名：**設計ブロックドリル**（暫定維持）
- コピー：**つないで、動かして、バグを見つける。**
- 世界観：**株式会社コウカンゲン**（架空企業）
- 別案として「ブロックをつないで、システムを直そう。」「動かしてみよう。何かがおかしい。」などもあるが、まずはメイン案で実装する。
- 初学者に「設計」が難しく感じられるかどうかは、実際の利用を見て判断する。

## 9. 完了条件（最低限）

- 初回アクセスでタイトル画面が表示される。
- 「はじめから」で第1章の冒頭から開始できる。
- 進捗があると「つづきから」が機能する。
- ドリルモードから第1章の各ステージを直接開始できる。
- 未解放章の名称は伏せ、ステージ数だけ表示される。
- ストーリー進捗とドリルの再挑戦が干渉しない。
- 画面幅が狭くてもボタン・章カードが崩れない。
