# 設計ブロックドリル — UI設計

## コンセプト

ゲームのUIとWebのUIの中間。キャンバスを盤面、テストをミッションとして扱い、処理が進む様子と試験結果の変化を同時に観察できるようにする。操作ボタン・編集フォーム・文章はWebとして読みやすく保つ。

落ち着いた緑の盤面、立体感のある小さなブロック、荷物と成功・失敗の色分けを使う。状態は色に加えて記号と文章でも伝える。

## キャンバス

テストケースとキャンバスの上に「出題とルール」を表示する。注文に対する在庫引当システムを開発している設定、全ケースが正しく動くよう設計を修正する課題、決済・出荷・キャンセル・二重要求のルールをまとめて示す。

- ブロックはアクション名の1行目だけを表示する。操作カード列・分岐先の文章・編集ボタンはブロック内に並べない。
- アクション行をクリックすると、キャンバス内左側へブロック詳細をスライド表示する。選択中のブロック名と強調表示で編集対象を対応づけ、操作カードと成功／失敗の接続先を確認・変更できる。行はドラッグによる位置調整にも使う。
- 初期配置の全8ブロックを一望できるよう、盤面を910×560の論理座標へ整理し、表示幅に合わせて全体を縮小する。スクロールを前提としない。
- 接続線と荷物の移動は維持する。旧レイアウトで保存した設計は、カード・接続を保持して位置だけ初期配置へ移行する。
- ブロック詳細を開いている間だけ、キャンバス左端に290pxの編集領域を確保する。盤面と操作バーはその右に配置し、ブロックを隠さない。×で閉じると予約領域を解放し、キャンバスが左端まで広がる。ブロックの論理座標や接続を保ったまま、表示幅に合わせて盤面を再調整する。
- Play／Pause／Step／Reset・速度・状態表示は、高さを抑えたフローティングバーとして盤面左上に表示する。盤面上部には操作バー用の余白を確保する。

## テストケースと試験内容パネル

- 左のケース一覧は最終判定がOKなら青系、NGなら赤系の背景にする。未実行は中立色を維持する。右の詳細は現在の判定に応じて同系色にし、各試験項目も○は青、×は赤の背景で区別する。実行中は従来どおり仮判定であることを表示する。

- 左のテストケースをクリックすると、そのテストを選択し、ページ全体の右側に試験内容パネルを表示する。キャンバス内のブロック編集とは別のパネルとする。
- 別ケースの選択では実行を初期化する。同じケースの再クリックでは、実行状態を保ってパネルを開く。
- 画面幅によらずページ右端の固定オーバーレイとして表示する。背景の情報へ重ね、開閉してもキャンバスの幅・縮尺を変えない。背面全体を覆う幕は置かず、実行操作は引き続き使用できる。
- 冒頭に「試験概要」「試験の観点」を表示し、その下へ「試験内容リスト」を配置する。各観点は問題データで管理する。
- 各試験項目に期待値・現在値・○／×を表示する。未実行時の記号は「—」。Step、Playの各操作で即時更新する。
- 実行途中の○×は、現在値と最終期待値の比較による仮判定。途中の×が後で○になることを説明文で明示する。ケース全体の最終成否とは区別する。
- パネルを開いたまま実行・一時停止・Step・編集ができる。背景を覆うモーダルにはしない。パネル内だけ独立してスクロールする。
- 「×」またはEscapeで閉じる。テストケースの再クリックで再表示できる。「試験内容を見る」ボタンは設けない。

## 詳細・補助情報

実行ログはキャンバスの下部にチャット欄のようにドッキングする。盤面とは別に約96px（数行）のスクロール領域を確保し、実行ごとに最新ログを表示する。ブロック編集を開いている時は盤面と同じ左余白を取り、操作・移動・ログを一緒に観察できるようにする。

倉庫アイコンをクリックすると、左のブロック編集エリアを荷物・在庫の詳細表示に切り替える。商品別の在庫・引当数、注文別の状態、荷物の実行位置・結果、通知・副作用をそれぞれ別表で表示する。複数商品・複数注文を行で比較でき、横幅が足りない表は横スクロールする。実行ステップごとに更新する。キャンバス下部に状態欄は常設しない。

荷物アイコンをクリックしても同じ詳細を開き、該当注文・荷物の行を強調する。ブロックをクリックするとブロック編集へ戻る。「設計のヒント」欄は設けない。

Play・Stepで実行する際、倉庫の詳細が表示されていなければ左パネルを詳細表示へ切り替えて開く。「実行位置・結果」「通知・副作用」のサブヘッダは .6rem・太字、パディングは .1rem .25rem とする。列ヘッダも文字・余白を小さくして高さを抑える。

荷物の詳細は項目を縦、荷物を横列に配置する1つの表にまとめる。「注文・荷物の状態」を冒頭に置き、「実行位置・結果」「通知・副作用」は全列にまたがるサブヘッダとする。荷物の列見出しと注文行は冒頭だけに置き、下のセクションには繰り返さない。選択中の荷物は列全体を強調する。通知・副作用は種類別件数で示し、同一注文に複数荷物がある場合は注文単位の累計を各列へ表示する（その旨を注記）。商品別在庫の表は商品を行にした別表を維持する。

「設計キャンバス」の見出し行へ操作説明を左詰め、成功／失敗と荷物の凡例を右詰めで集約する。専用の説明行・キャンバス下の凡例行は設けない。左のテストケース欄は外側10px、各ケース8pxのパディングとし、高さを抑える。狭い画面では読みやすさを保つため見出し行を折り返す。

ブロック編集は専用領域内で独立してスクロールし、閉じるボタンで隠せる。試験内容を開いたままブロック編集もできる。

## 操作とアクセシビリティ

### ブロック編集のヘルプと操作追加

- 「ブロックの編集」タイトル横の(?)から、前提条件と失敗時の処理ルールをポップアップ表示する。通常の編集欄には長い説明を置かない。
- `no_op` は画面で「変更なし」と表記する。状態変更が不要だった結果であり、通常は残りのカードを続けて成功経路へ進む。処理済みキャンセルの受付では、その荷物を終了する例外も説明する。
- 追加フォームは操作だけを選択する。右下の［追加］で登録し、操作未選択時は無効とする。薄い緑の「追加モード」とし、操作ごとの編集モードは設けない。
- 編集パネルの上部には、選択中のブロックをキャンバスと同じ外観（枠・背景・影・アクション名）で表示する。ここではドラッグや再選択は行わず、下の「登録済みの操作」一覧と明確に区切る。
- 選択ブロックのプレビューは親の見出し領域を含めて幅を確保し、編集カードの内幅いっぱいに表示する。
- 荷物には注文ごとの現在の引当数バッジを表示する。キャンバス下部には倉庫アイコンと商品Aの在庫数バッジを表示し、各ステップ・Reset・ケース切替で状態に追従する。テスト未選択時は在庫表示を隠す。
- 荷物名の前に小包アイコンを表示し、「数量」「引当」の2バッジを並べる。この「数量」は未引当数（注文数量−現在の引当数量）を意味し、注文総数自体は変更しない。例：引当前は「数量 2／引当 0」、引当後は「数量 0／引当 2」。引当解除後は「数量 2／引当 0」に戻る。数量バッジのツールチップで意味と注文総数を示す。
- 初期状態では追加フォームを折りたたみ、［追加］ボタンのみ表示する。押すと追加フォームと［取消］を表示する。追加の確定・取消でフォームを閉じる。
- ［追加］の下に、ブロック共通の「成功時遷移先」「失敗時遷移先」を常時表示する。それぞれ「現在の遷移先 ［編集］」の形式とする。
- ［編集］の直下に候補を列挙し、ホバー／フォーカスで接続予定の線を表示する。候補をクリックするとその接続を即時確定し、候補を閉じる。操作の追加とは別に保存・実行状態をリセットする。
- 正常終了・未接続は接続先のブロックがないため、プレビュー線を表示しない。
- 未接続による停止と正常終了を区別するため、終了の指定自体は維持する。接続先候補は横2列のボタンで全候補を確認できるようにする（設定を開いている間）。
- 遷移先の選択肢は、未接続を「(未設定)」、正常終了を「(完了)」と表記する。成功先は操作列が最後まで進んだ後、失敗先は途中の操作が失敗した時に使用する。
- 現行エンジンの遷移先はブロック単位。操作ごとに別々の遷移先を持たせる仕様には変更しない。
- 確定操作のアイコンは［削除（ゴミ箱）］［↑］［↓］のみ。操作を変更する場合は削除・追加する。
- 追加フォームを開くと操作候補をすべて列挙する。同じブロックに配置済みの操作はグレー表示・選択不可とし、重複の確定も防ぐ。他のブロックで同じ操作を使うことはできる。
- 「操作」「成功時遷移先」「失敗時遷移先」は小さな太字ラベルとし、選択値とのメリハリを付ける。

### テストケース一覧の拡張

- ［全ケースを検証］でメニューを縮小表示にし、結果をリセットして先頭から順に各ケースをアニメーション実行する。速度設定を共有し、一時停止・再開ができる。ケースの停止・待機はNGとして次へ進む。Resetや別ケース選択、設計の変更は一括実行を中断する。
- 全ケース終了後は全画面の結果演出を表示する。全件成功はExcellent、成功率80%以上はGood、50%以上はNot Good、それ未満はBad。成功件数も示す。確認ボタンは置かず、3秒後に自動で閉じる。Escapeでも閉じられる。動きを減らす設定に対応する。
- 結果演出は3秒後に自動で閉じる。Play開始時および一括検証開始時は右側の試験詳細も開き、各ケースの判定を観察できるようにする。

- 出題欄に難易度付きの問題選択を置く。`?drill=識別ID` による直接表示に対応し、問題切替時はテスト未選択で開始する。左メニューの「各ケースは独立して初期状態から実行します。」という重複説明は削除する。

- 左メニューの高さはキャンバス見出しからキャンバス下部のログ欄までに揃え、ケース一覧だけを縦スクロールさせる。見出し・一覧切替・一括検証ボタンは固定して残す。狭い画面では一覧の最大高さを抑える。
- 「共有状態」は複数の注文で共通して使うデータを指す。画面上の見出しは「荷物の状態・共通の在庫」とし、在庫が全注文で共有されることを説明する。
- 荷物のホバー時は濃い背景と白い文字でコントラストを保つ。クリックすると対象注文を下の状態欄で表示し、荷物の枠・選択ボタン・状態欄の見出しで選択対象を示す。

- 初期表示はリスト拡張モードかつテスト未選択。荷物は表示せず、実行ボタンはケース選択まで無効とする。一括検証は未選択でも利用でき、ケース選択は変更しない。

- 左メニューの「テストケース」右にリストアイコンを配置する。押すと左メニューを広げ、全ケースの試験概要・試験観点をタイトルの下に一覧表示する。
- 縮小アイコンで元の幅とタイトル中心の表示に戻す。選択中のケース・実行状態・結果は保持する。

- アクション行、試験ケース、パネル開閉はキーボードで操作できる。
- 閉じたパネルはフォーカス対象から外す。開いた時は閉じるボタンへ、閉じた時は再表示ボタンへフォーカスを移す。
- 動きを減らす設定ではスライドと荷物移動のトランジションを無効化する。
- 狭い画面では情報欄を縦積みにする。ブロック編集は盤面の下へ配置し、右側ブロックとの重なりを避ける。試験内容はページ右端のパネルとする。
